# 倉庫レイアウト＋経路生成アプリ — 設計ノート
**個人用 / ブラウザ・TypeScript（重い計算はPython併用も可）**
2026-05-31

倉庫レイアウト（棚・壁・検品場・階段・制約エリア）を描き、台車/歩行の**経路ネットワークを自動生成**して最短経路・距離を出す自分用ツールを、公知アルゴリズムと自分のデータからゼロ設計する。

---

## 1. アーキテクチャ（4分割）
**①レイアウト編集 → ②経路グラフ生成 → ③最短路 → ④出力**。③は差し替え可能に。
- フロント：ブラウザ Canvas/WebGL（編集・可視化・**滑らかなpan/zoom**）
- 計算：まずブラウザ内TS。重くなったら **Python サービス（FastAPI＋scipy）** に逃がす。別開発の Warehouse Simulator（Python裏）と同じ流儀＝統合も可能。

## 2. データモデル（既存JSONが出発点）
```
floor { name, bounds{left,top,right,bottom}, view{centerX,centerY,zoom},
        objects[ { type, id, x, y, w, h, name? } ] }
```
単位 mm・軸平行矩形・原点左上・+x右/+y下。既存レイアウトは `exported/*.json` にあり、そのまま読める（LW=699 / Rev2=632 / 変更後=582 オブジェクト）。
**新規に持たせるべきフィールド**：棚の **間口の向き facing(up/down/left/right)**、type別属性（壁=高さ、制約エリア=一方通行方向 等）。保存形式は JSON（言語非依存・差分・人間可読）。

## 3. 経路生成（②③）— 公知アルゴリズムで実装（Java不要）
**道A：レーングラフ方式（推奨）** — 通路=辺、交差点=節点。倉庫の格子構造を素直にモデル化。一方通行・速度・旋回コストが自然で頑健。
**道B：ボロノイ/医中心軸方式** — 障害物のフチをサンプル→ドロネー三角形分割→外心（=ボロノイ頂点＝通路中心）を経由点に→視線が通る点同士を連結。クリアランス最大の経路。古典的だが軸平行入力で退化しやすく robust geometry 必須。

- **pick点**：棚/検品場の各面中央から外側に一定オフセット、**空いてる面のみ**→最寄りの経路網に接続。
- **最短路**：Dijkstra/A\*（直線距離ヒューリスティック）。全点間が要るなら Floyd–Warshall、規模が出れば **Contraction Hierarchies / hub labeling**。
- **スムージング**：Theta\*/funnel で任意角に。
- **複数階**：同名の階段ノードで接続、階段の上下距離はパラメータ（定義 or 入力）。

### ライブラリ（Java不要の裏付け）
| 役割 | Python | ブラウザ JS/TS |
|---|---|---|
| ドロネー/ボロノイ | `scipy.spatial.Delaunay/Voronoi` | `d3-delaunay` |
| 最近傍/空間索引 | `scipy.spatial.cKDTree` | `rbush` |
| 幾何（交差/視線） | `shapely` | `turf.js`/自前 |
| グラフ最短路 | `networkx`/`rustworkx`/`igraph` | `ngraph.path`/`graphlib` |
| 行列・数値 | `numpy` | `gl-matrix` |

→ Python（scipy）は計算幾何が一級。既存 Warehouse Sim と同構成にできる。

## 4. 倉庫ドメインの要点
- **間口（ピック面）と連**：棚はピックする面=間口を持つ。連（棚の並び）は **間口の左右に並べる**。奥行き方向に積むと後ろの棚の間口が塞がりピック不可。→棚に間口の向きを必ず持たせ、**一括生成は「間口を空けて並べる」を既定**に。
- pick点は間口前のアイルから。空き面検出でpick可能面を判定。
- 一方通行/制約エリアは辺に方向属性。
- 座標 mm、軸平行、原点左上/+y下。

## 5. UX要点
- **滑らかな pan/zoom（カメラ補間）は必須**（好評ポイント）。requestAnimationFrame＋easingで自前実装。
- **Undo/Redo は最初から**（コマンド or スナップショット）。
- 操作モード（編集/棚/壁/…）、フロアタブ、オブジェクト情報パネル、**グリッド吸着**、**コピペ/複製**、**全体表示(zoom to fit)**、棚名の一括/連番。
- **棚の一括生成**（間口指定→サイズ・連結数で一発。PowerPointの図形のように）＝目玉機能。

## 6. 推奨スタック（個人・手軽さ重視）
- フロント：**TypeScript + Vite + Canvas2D**（まず）/ 後で WebGL。状態は軽量（zustand 等）。
- 計算：まず TS、重ければ **Python(FastAPI+scipy)** に分離。
- 保存：JSON（ローカルファイル / IndexedDB）。
- カメラ：自前の補間でスルスル。

## 7. ロードマップ
1. **JSONローダ（`exported/*.json`）＋Canvas表示＋スルスルpan/zoom**。
2. 編集（棚/壁の追加・移動・選択・削除・複製・グリッド吸着）＋Undo。
3. **棚一括生成（間口指定）**。
4. 経路v1：レーングラフ＋A\*（クリアランスは最小離隔で代替）。
5. 経路v2：一方通行/複数階/スムージング、規模次第CH。
6. 最適化層（スロッティング/混雑/レイアウト）＝Sim連携。

*出発点＝自分の既存レイアウト(JSON)＋公知アルゴリズム。まずは①のMVP（JSON読込＋スルスル描画）から。*
