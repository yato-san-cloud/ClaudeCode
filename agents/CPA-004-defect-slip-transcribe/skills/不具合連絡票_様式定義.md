# 不具合連絡票 様式定義 — エージェント用ナレッジ

紙の「不具合連絡票」（ネオ・ウィング現場、バインダー綴じ・1枚1件）の読み取り仕様。
転記エージェントはこの語彙を**そのまま**使う。言い換え・新語の発明をしない。

## この文書が扱う依頼の例

- 「この不具合票を転記して」「不具合連絡票をデータ化して」（写真・PDF添付）
- 「この画像をkintoneに貼れる形にして」

## 票の項目と記入方式

| 項目 | 記入方式 | 読み取りの注意 |
|---|---|---|
| いつ | 年・月・日を手書き | 年が2桁・省略のことがある。西暦4桁に正規化し、省略時は【要確認・年】 |
| 何処で | ☑ ネオウイング / ネオロジ | チェックボックス2択 |
| 区分 | 入荷・出荷 のどちらかに丸 | 丸が薄い・両方にかかる場合は【要確認】 |
| 場所 | T-sort・HT検収・9マルチ のいずれかに丸 | |
| 誰が | 氏名を手書き | 「実際に作業した方の氏名」。姓と名の間の空白は詰めてよい |
| 作業名 | 入荷検収・格納・ピック・検品・T-sort入荷・T-sort出荷 のいずれかに丸 | |
| どうした（事象） | チェックボックス（複数可） | 下の12種のみ |
| 発見・破損 | 左側の □発見 □破損 | 事象とは別枠。チェックがあれば記載 |
| 詳細 | 自由手書き | 伝票番号（T+数字6桁、例: T769163）が書かれることが多い。抽出して伝票番号欄にも出す |
| 注文番号 | 手書き（空欄が多い） | |
| ロケーション | 「−」区切りの枠 | 空欄（全部−）なら「なし」 |
| JANコード | 手書き数字13桁 | 1桁ずつ読む。13桁でなければ【要確認・桁数】 |
| 品目名 | 手書き（ローマ字・空欄・「1」だけ等の記入ゆれあり） | 記入のまま転記。空欄は「(記載なし)」 |
| 数量 | 手書き数字 | |
| 本事象の責任 | ロジスティード中部・NW様 のどちらかに丸 | 票の上端と下端の両方に同じ欄がある。丸が付いている方を読む |

## 事象の語彙（この12種のみ。これ以外の語は使わない）

過剰入庫 / 過少入庫 / 入庫漏れ / 格納漏れ /
過剰ピック / 過少ピック / 誤ピック / 棚移動ミス /
特典JAN貼りミス / 作業完了エラー / 破損 / その他（空欄チェック枠に手書きがある場合はその語を転記し【要確認】を付ける）

## 実物の記入例（読み取りの粒度）

- 2026-06-04 / ネオウイング / 出荷 / T-sort / 佐野秀美 / T-sort出荷 / 過剰ピック /
  詳細「T769163 過剰」→ 伝票番号 T769163 / JAN 4580883373959 / 品目名「(記載なし)」
- 品目名がローマ字のことがある（例: Naniwa Danshi ND5）。そのまま転記する

## 転記後の検証（スクリプト側の役割・参考）

- JAN は EAN-13 チェックデジットで検証される。エージェントは検算せず、読み取りに集中する
- 票No の欠番チェックで転記漏れを検知する運用のため、票No があれば必ず転記する
