# ナレッジ配置手順(SharePoint)

所要30分。エージェントの「根拠」になるファイル群をSharePointに置き、鮮度を保つ仕組みを作る。

## 1. サイトとライブラリ(10分)

1. SharePoint→「+サイトの作成」→チームサイト→名前「営業管理」→メンバー: 4名
2. 「ドキュメント」ライブラリ内にフォルダを作成:
   `ナレッジ/00_共通` `ナレッジ/01_フォーマット` `ナレッジ/02_台帳スナップショット` `ナレッジ/03_SOP` `エージェント定義` `出力控え`
3. このフォルダ(07_Copilot検証\ナレッジ\)の中身を対応する場所へアップロード。
   03_SOPへは `03_タスク工場\タスク類型テンプレ.md` もコピーして配置

## 2. 同期(5分)

ライブラリの「同期」ボタン→OneDrive同期を有効化。以後、エクスプローラーの
`(会社名)\営業管理 - ドキュメント\ナレッジ\...` に**ファイルをコピーするだけでSharePoint側が更新**される。

## 3. 台帳スナップショットの自動出力(5分)

```bat
cd /d "C:\Users\sti-p\OneDrive\ドキュメント\Claude\Projects\営業管理\01_生成"
python gen_knowledge.py --out "(同期フォルダ)\ナレッジ\02_台帳スナップショット"
```
- 案件リスト_最新.md と 活動サマリ_最新.md が生成される(kintone稼働後は `--kintone` で活動をAPI取得)
- 週次で回す場合: 定時ジョブ設定手順.md の「営業管理_週次」タスクにこの1行を追加

## 4. エージェントへのナレッジ指定(各エージェント作成時)

エージェントビルダーのナレッジ追加で、SharePointサイト「営業管理」→該当ファイル(またはナレッジフォルダごと)を指定。
各エージェントが参照すべきファイルは `エージェント定義_*.md` の「ナレッジ」欄に記載済み。

## 5. 鮮度の注意

- SharePointへ置いた直後は検索インデックス反映まで時間差がある(数分〜数時間)。エージェントが古い内容を答えたらまず反映待ちを疑う
- 台帳の正本はローカル(00_台帳)のまま。**SharePointは「エージェント用の鏡」**であり、直接編集しない(gen_knowledge.pyの出力で上書きされる)
