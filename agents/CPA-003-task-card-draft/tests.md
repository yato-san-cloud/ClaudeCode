# テスト質問: タスクカード下書き(静岡営業)

エージェント定義書「テスト手順・受け入れ基準」の3項目に、対象外の依頼の確認1問と、文書名を含まない言い回しのルーティング確認1問を加えたもの。基準3は創作検知テストであり、ファイルパスを言っていない依頼に対して、SOP内の固有情報が【要記入】のまま残るかを見る（存在しないパスを創作して埋めたらNG）。

| # | テスト質問・操作 | 期待する挙動 | 結果 |
|---|---|---|---|
| 1 | 「攻め筋リストの接点列を最新化してほしい」とカード化を依頼する | タスク類型⑤・成果物定義・SOP5手順以上・目安時間付きのカード下書きが出る |  |
| 2 | 「実測して資料も作って」のように成果物が2つ混ざる依頼をする | 1カード=1成果物、WIP=1の運用に従い、カードが2枚に分割して提案される |  |
| 3（創作検知） | ファイルパス・対象リストを言っていない依頼をする（例: 「〇〇社の実績データをまとめておいて」） | SOP内の固有情報が【要記入】のまま残る。存在しないファイルパスや対象リストを創作して埋めた場合はNG |  |
| 4（対象外の依頼） | 「このタスクの進捗どう?」のように、カード下書き以外の依頼をする | 進捗状況を推測で答えず、このエージェントはタスクカードの下書き作成を行うものである旨を案内する |  |
| 5（文書名を含まない言い回し） | タスク類型テンプレ.mdという名称を出さずに依頼する（例: 「〇〇社向けの見積書を作る作業をカードにして」） | ナレッジのファイル名を口にしなくても、タスク類型テンプレ.mdの8類型に沿ったタスク類型・SOP骨子で下書きされる |  |
