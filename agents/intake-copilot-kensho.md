## 定義書の分解（1 本 → 4 ファイル）

既存の定義書は 1 本に全部入りのため、パッケージでは次のとおり分解する:

| 定義書のセクション | 行き先 |
|---|---|
| 名前・説明文 | `spec.md` ヘッダ表 ＋ setup-guide の貼り付け表 |
| Instructions 全文 | `instructions.md`（8,000 字チェックを取り込み時に実施） |
| ナレッジ指定 | `spec.md` 構成表（静的/動的の区別を追記） |
| 会話スターター | setup-guide の STEP 1 貼り付け表 |
| 受け入れ基準 | `tests.md` |
| （欠けているもの: 背景 Why・変更履歴） | `spec.md` に新規記入——**取り込み時にヒアリングで補う唯一の項目** |

## 共有ナレッジ（用語集）の扱い

用語集は 3 エージェントが共通参照するため、コピーを 3 か所に置かず
`agents/shared-knowledge/` に 1 本だけ置く。各エージェントの `spec.md` 構成表と
Studio のナレッジ登録には 3 エージェントすべてで同ファイルを指定する。
更新時は 1 回直して 3 エージェントに再配布（動的ナレッジと同じく SharePoint 参照に
しておけば再配布も不要）。

## 動的ナレッジ（鮮度パイプライン）の扱い

`gen_knowledge.py` が台帳（Excel、kintone 稼働後は `--kintone` で API 取得）から
`案件リスト_最新.md`・`活動サマリ_最新.md` を再生成する構成は、
**静的なスキル文書とは別区分（動的ナレッジ）**として扱う。規約は
`.claude/skills/copilot-agent-builder/references/copilot-studio-track.md` の
「動的ナレッジ」節を正とする。要点:

- 生成物はスクリプトの出力であり、手で編集しない。**spec.md の版管理・変更履歴の
  対象外**（変更履歴に載せるのはスクリプト自体の変更のみ）
- 置き場は Dataverse 直アップロードではなく **SharePoint 参照**にする
  （OneDrive 同期フォルダに出力→上書きだけで自動再インデックス。
  直アップロードだと再生成のたび削除→再アップロードの手作業が発生するため）
