START HERE初日に知っておく7つのこと

マニュアルを全部読む前に、これだけ押さえれば事故は防げます。

① ボタンは1回だけ。二度押し禁止

処理が終わるまで他の操作をしない。二度押しすると同じ処理が2回動く恐れがあります。F5（更新）を押すと入力内容が全部消えます。

② 出荷検品中にブラウザの「戻る」は絶対に押さない

押してしまうとステータスが「検品中」のまま残り、再開できなくなります。復旧方法は困ったとき → 「検品が再開できない」を参照。

③ 「戻る」「×」を押しても処理は止まらない

登録処理が始まった後にブラウザを閉じても処理は継続されます（取消にはなりません）。取消・修正は必ず各画面の機能（取消ボタン・実績訂正など）で行います。

④ 画面名とボタン名の読み方

このガイドでは 『画面名』＝画面、【ボタン名】＝ボタンです。メニューは「マスタ／入荷／出荷／在庫／棚卸／日次／運用／ヘルプ」の8つ。荷主・センタの切替はメニュー上部のセンタ名称を押して【切替】（ログインし直し不要）。

⑤ メッセージの色 = 青は正常・赤はエラー・黄は警告

入力エラーは項目単位に表示されます。チェックの種類は「必須・桁数・文字種・日付形式・マスタ未存在」。「マスタに存在しません」系はマスタ登録漏れか削除済みが原因です。

⑥ 挙動は「パラメータマスタ」の設定で変わる

同じWMSでもセンタ・荷主ごとに設定が違います。特に影響が大きいのは: 欠品時の挙動（取消/0引当）、ラベル・荷札・納品明細の自動出力、荷材選択のスキップ、入庫No.管理の有無（HTの画面フロー自体が変わる）。「あの倉庫と動きが違う」と思ったらまず設定を疑い、管理者に確認しましょう。

⑦ 1日の最後は「日次締」。忘れると翌日警告が出る

庫内業務が終わったら日次メニューの『日次締処理』。忘れてもデータは壊れませんが、翌日ログイン時に警告が出るので、締めてから業務を始めます。詳しくは日次締のページへ。

DAILY FLOW倉庫の1日と画面の対応

どの作業がどの画面かをまず地図として覚えます。

入荷の流れ

入荷予定登録→ 入荷予定リスト発行→ 検品・格納→ 入荷実績入力＝在庫計上→ 入庫ラベル発行・貼付

予定の取込は『入荷予定一括取込』（Excel）か『入荷予定入力』（手入力）、EDI自動連携も可。実績を入れた瞬間に在庫が増えます。

出荷の流れ

出荷指示登録→ 出庫指示＝在庫引当→ ピッキングリスト発行→ ピッキング→ 出荷検品・梱包→ 送り状・積込→ 出荷確定＝在庫引落

在庫が動くのは「出庫指示（引当）」と「出荷確定（引落）」の2点。ここを覚えると在庫数の見方に迷いません。

締め

庫内業務終了→ 日次締処理→ ログ一覧で結果確認

RECEIVING入荷

予定 → 検品・格納 → 実績入力（在庫計上）→ ラベル。

入荷予定を登録する（手入力 / Excel取込）
  1. 手入力: 入荷メニュー → 『入荷予定入力』。入荷予定日・仕入先CD・処理区分・在庫区分・商品CD・予定数を入力 → 【登録】。
  2. Excel: 『入荷予定一括取込』 → 【ファイル取込】 → 【登録】。フォーマットはヘルプメニューからダウンロード。
  3. 登録結果は 『伝票別入荷一覧』／『商品別入荷一覧』で確認。
注意 明細0行では登録不可。逆に修正時に明細を0行にして登録すると「予定の削除」になる。修正は未入荷・エラー有のみ、伝票1件だけチェックして【入荷予定修正】。
エラー有の入荷予定を直す
  1. 『伝票別入荷一覧』で対象をチェック → 【エラーチェック】。エラー行はピンク背景＋メッセージ。
  2. 「〇〇マスタに存在しません」→ 該当マスタを登録するか、削除済みなら未削除に戻す。または予定側を修正。
  3. 直したらもう一度【エラーチェック】。ステータスが「未入荷」に戻れば作業再開OK。
入荷実績を入力する（在庫計上）
  1. 一覧で対象をチェック → 【入荷実績入力】 → 『入荷実績入力（予定あり）』。
  2. 実績を入力。ロット管理品・期限日管理品は「ロット」「期限日」が必須。
  3. 複数のロット・期限日・ロケに分かれた場合は【明細分割】。
  4. 【登録】で在庫計上。設定によっては入庫ラベル／商品ラベルが自動で出ます。

予定なし入荷は『入荷実績入力（予定なし）』（ロケーションCD必須）。

注意 入荷の取消は【入荷取消】。ただし入庫後に在庫を移動・調整して入庫時より減っていると取消不可 → 先に在庫を入荷時の状態に戻す。
分納・打切り（予定数に届かないとき）
  1. 『入荷未完了一覧』で対象をチェック。
  2. 画面下部で「分納」（未入荷分を別予定として残す）か「打切り」（未入荷分を取消）を指定 → 【指示】 → 【登録】。
進捗・履歴を見る

『入荷ステータス別進捗』（円グラフ）、『入荷履歴』。ステータスは 未入荷 → 入荷中（一部計上）→ 入荷済。「エラー有」は進捗上は未入荷扱い。

SHIPPING出荷

指示 → 出庫指示（引当）→ ピッキング → 検品 → 確定（引落）。

出荷指示を登録する
  1. 手入力: 『出荷指示入力』。納品先CD・納品予定日・作業日・出荷日・商品CD・出荷指示数 → 【登録】。
  2. Excel: 『出荷指示一括取込』 → 【ファイル取込】 → 【登録】（エラー項目は画面上で修正可）。
  3. 確認・操作の起点は『出庫指示一覧』。修正は『商品別出荷一覧』 → 【指示修正】。
注意 修正・キャンセルができるのは未出荷（またはエラー有）のみ。出庫指示済のものは先に【出庫指示解除】。出荷確定済は日付・配送コース変更も不可。
出庫指示（在庫引当）をかける
  1. 『出庫指示一覧』でステータス「未出荷」で検索 → 対象をチェック（タイトル部で全選択可）。
  2. 【出庫指示】 → ステータスが「出庫指示済」に。取り消すときは【出庫指示解除】で「未出荷」へ戻る。
  3. 緊急補充のメッセージが出たら『在庫移動一覧』で補充ラベル発行 → 補充作業 → 【完了】。
注意 欠品時の動き（伝票ごと取消／引当可能数だけ引当／商品ごと0／納品先ごと0）はパラメータマスタの設定次第。欠品行は一覧に青文字で表示。再引当は「出庫指示解除 → 指示修正 or 在庫を直す → 再度出庫指示」。
ピッキングリストを発行する
  1. 『ピッキングリスト発行』（または『出庫指示一覧』で1件チェック → 【ピッキングリスト】）。
  2. 発行区分（一次／二次／ケース／送り状・荷札）を指定 → 【検索】 → 帳票種別を選びチェック → 【発行】。
方式使いどころ出す帳票
オーダー納品先単位にそのままピックオーダーピッキングリスト＋ケース分
トータル＋摘み取り/種蒔き総数で集品→納品先別に仕分トータル＋摘み取り or 種蒔きリスト
マルチ複数オーダーを台車で同時ピックマルチピッキングリスト＋摘み取り
ケースケース引当分（ある場合は必須出力）ケースピッキングリスト
単行1商品だけの伝票をまとめ処理単行ピッキングリスト（他リストからはピック不可）

最適ピック提案を使う設定なら『ピッキング提案』 → 【検索】 → 行選択 → 【発行】。

出荷検品する（PC＋スキャナ）
  1. 『出荷検品』で担当者CDと箱CD／ピックリストNo.を入力 → 【検索】。
  2. ソースCDまたは商品CDをスキャンしてカウント。青=検品済、ピンク=検品中、白=未検品。数量手入力は明細行ダブルクリック。
  3. 箱が変わるときは【箱登録】で荷材を追加。全商品完了で『荷材選択』が自動表示 → 【登録】で完了。
厳禁 検品中のブラウザ「戻る」。押したら『出庫指示一覧』で【出荷検品解除】（1件チェック）して最初から。荷材選択で【閉じる】を押すと検品完了にならない → 【箱登録】で荷材登録し直す。
送り状・納品明細・積込
  1. 納品明細: 『納品明細発行』。送り状データ: 『送り状データ出力』 → チェック → 【データ出力】（CSV。種別は配送コースの設定に従う）。
  2. 荷札をWMSから直接出す場合は『ピッキングリスト発行』の発行区分「送り状・荷札」（ヤマト/佐川/ゆうパック/汎用に対応）。
  3. 積込: 『積込リスト発行』 → 積込検品。
出荷確定（在庫引落）と解除
  1. 『出荷確定一覧』 → 対象チェック → 【出荷確定】（検品済のみ）。ここで在庫が引き落とされます。
  2. 目視検品のみで確定したいとき: 出庫指示済の行に【強制確定】。
  3. 解除: 表示を「全件表示」にして検索 → チェック → 【出荷確定解除】。
注意 出荷確定済になると以降の出荷業務（修正・変更）は一切不可。確定は最後の関門と心得る。

INVENTORY在庫・補充

照会 → 調整・移動 → 補充。在庫は9つのキー（荷主・センタ・預託・在庫区分・商品・ロケ・入庫ラベルNo.・ロット・期限日）で分かれます。

在庫を調べる

『トータル在庫問合せ』=商品別・全センタ（定点切れ確認も）。『在庫問合せ』=ロケーション別。行を選ぶと【在庫受払問合せ】【在庫調整】【在庫移動】などへ。受払履歴で「誰がいつ何をしたか」を追えます（訂正・取消は赤処理＝マイナス計上で残る）。

在庫調整（数を合わせる）
  1. 『在庫問合せ』で対象行 → 【在庫調整】（新規在庫は『在庫調整（新規）』）。
  2. 調整内容を入力 → 【登録】。ロット・期限日管理品は必須。入庫No.管理ありなら入庫ラベルNo.を指定（未入力だと新規在庫の追加になる）。
在庫移動（ロケ・在庫区分・預託の切替）
  1. 『在庫問合せ』 → 【在庫移動】 → 移動先を入力 → 【登録】。
  2. 複数まとめて動かすなら【在庫一括移動指示】 → 『在庫移動一覧』で搬送ラベル発行 → 作業 → 【完了】。
注意 補充ロケの在庫を全数移動すると補充ロケ定義が消える（移動先がピックロケなら移動先が新しい補充ロケになる）。一部だけ動かすと入庫No.は分割されて新しい番号が付く。
補充（定期・緊急）

定期補充: ロケーションマスタに補充点を設定 → 補充点を切ると『補充指示一覧』に出る → チェック → 【補充指示】 → 『在庫移動一覧』でラベル発行・完了。緊急補充: 出庫指示時にピックロケ在庫が足りないと自動発生 → メッセージが出たら『在庫移動一覧』で処理。

セット組・セット解除

『セット組指示』／『セット解除指示』で指示 → 指示書発行 → 作業 → 完了。構成総数と指示数が合わないと登録できません。親商品は構成品になれない（逆も同じ）。

STOCKTAKE棚卸

データ作成 → リスト発行 → カウント入力 → 差異確認 → 在庫調整。

棚卸の手順
  1. 『棚卸データ作成』。条件なし=一斉棚卸、ロケ・ゾーン・受払日指定=循環棚卸。
  2. 『棚卸作業リスト発行』（HT・SDで数える場合は不要）。
  3. カウント結果を『棚卸入力』へ（リスト外在庫は【行追加】）。HTなら「商品棚卸入力」。
  4. 『棚卸差異リスト発行』で差異確認 → 必要なら再棚卸。
  5. 調整: 1件ずつなら『棚卸入力』→【在庫調整】、まとめてなら『棚卸在庫一括更新』→【在庫一括更新】。
鉄則 棚卸は入出荷作業が終わってから。データ作成後に在庫が動くと差異の原因になります（動いた行は一括更新画面で赤背景）。引当済がある在庫は「引当可能数」だけが棚卸対象 — 現物と合わないときはピッキング済みでないか確認。一度調整した行は再入力できません（在庫調整フラグ=調整済）。

DAY-END日次締

日次締の実行と確認
  1. 庫内業務がすべて終わったことを確認。
  2. 日次メニュー → 『日次締処理』 → システム管理日付（翌稼働日）を確認 → 荷主をチェック → 【締切】。
  3. 結果は運用メニュー → 『ログ一覧』で確認（ダブルクリックで明細）。
注意 荷主ごとにバラバラに実行すると荷主間でシステム管理日付がずれます。稼働日は戻せますが受払が発生した日には戻せない。締め忘れは翌日ログイン時に警告が出るので、締めてから業務開始。日次締で保持期間を過ぎたデータは履歴移動・削除されます。

E-COMMERCEEC受注業務

取込 → 出庫指示 → 納品書・EC送り状 → 以降は通常の出荷と同じ。

EC受注データを取り込む
  1. EC受注メニュー → 『EC受注データ一括取込』 → 取込種別（楽天/Yahoo!/Amazon等）を選択 → 【取込】 → 【登録】。
  2. 登録と同時に出荷指示も自動作成されます。確認は『EC受注データ一覧』。
注意 Yahoo!は注文ファイル＋商品ファイルの2種必須。同じ種類のファイルを連続で取り込むと最後の1つしか有効にならない。
修正・キャンセル・納品書の落とし穴
  • 【指示修正】で直せるのは出荷指示だけ。EC受注データ自体は変わらない → 納品書は変更前の内容（欠品品も含む）で出ます。受注データを直すならキャンセル → 再取込。
  • 【受注キャンセル】は未出荷のみ。受注と出荷指示は双方向連動で一緒に消えます（エラー削除も同様）。
  • EC送り状データ出力は出庫指示済以降のみ表示。送り状種別は配送コースへの関連付けで決まります。
重要 EC受注データは出荷日から一定期間で自動削除され、納品書・EC送り状が出せなくなります。取り置き等で日が空くときは『出庫指示一覧』で出荷日を実際の日に更新しておくこと。
帳票アタッチ（照合）

ピッキングリスト・納品書・EC送り状は出庫作業No.単位で照合。印字位置: ピッキングリスト=右上、納品書=右上、送り状（メール便）=お届け先電話番号欄、送り状（宅配）=ご依頼主氏名末尾の【】内。

HANDYHT（ハンディ）/ SD（スマートデバイス）

HTはキー操作、SDはタッチ操作。入庫No.管理の有無で画面フローが変わる点だけ先に押さえる。

HTの共通キー
キー意味
F3 / ENT確定・次へ
F4完了・切替・選択リスト表示・後回し
F1登録内容の一覧確認・補助機能
F2終了・戻る

電池切れ・電源OFFで中断しても、再ログイン時に「再開画面」からF3で復帰できます（やり直し不要）。数量入力では【・・・】でケース／ボール別の入力補助が使えます。

HT入荷（検品 → 格納）
  1. 入荷管理メニュー → 【1:入荷検品】。ラベル選択（入庫ラベル/汎用ラベル）→ 伝票No.と仮ロケをスキャン → ソースCDスキャン → 数量 → F3。ロット・期限日管理品は続けて入力。
  2. 格納は【2:入庫格納】: 入庫ラベルNo.スキャン → 数量 → 格納ロケスキャン → F3。
  3. 検品と格納を一気にやるなら【4:入荷検品格納】。予定数を超えると『検品数確認』画面が出ます。
HTピッキング・出荷検品
  1. オーダーピッキング: 出庫作業No.入力 → 表示された商品をスキャン → 数量 → F3。F4で後回し。入庫No.管理ありはF4で入庫No.単位ピックに切替。
  2. 出荷検品: 出庫作業No.入力 → スキャンでカウント → 箱が満杯ならF4で箱登録 → 完了はF3。完了前にF3を押すとエラー。
  3. 積込検品: 配送コース指定時に別コースの荷物をスキャンするとエラー（指定なしでも実施可）。
SDの操作と制約

SDはブラウザベース。ピッキングは『ピッキング』で 0:バラ / 1:ケース を選ぶと対象が順次表示され【登録】で次へ。解除は対象行の【ピッキング解除】 — 「ピッキング中」ステータスのものだけ解除可。

注意 ボタン二度押し禁止・ブラウザ更新でメインメニューに戻り入力消失・登録開始後の戻る/閉じるでも処理は継続 — PCと同じ3原則がSDにも当てはまります。

TROUBLE困ったとき（症状から引く）

上の検索ボックスに症状を入れても絞り込めます。

出荷検品が再開できない（「検品中」のまま）

原因: 検品中に【出荷検品中断】を押さずに画面を閉じた／ブラウザの戻るを押した。

  1. 『出庫指示一覧』で対象を1件チェック → 【出荷検品解除】（または【出庫指示解除】）。
  2. 検品解除なら再度『出荷検品』からやり直し。出庫指示解除まで戻した場合は再度【出庫指示】 → 新しい出庫作業No.で検品。
タイムアウトした / 放置後に操作したらダイアログが出た

【OK】 → ログインし直すと中断前の画面に戻ります。ただし画面は表示直後の状態に戻るので、入力途中の内容は消えています。

「他のユーザに変更された可能性があります」（排他エラー）

原因: 自分が画面を見ている間に、他の人が同じデータを処理した。

  1. 【検索】し直して画面を最新化。
  2. 内容を確認 — 他の人の処理で既に完了していることが多い。必要な場合のみ再実行。

入荷実績入力で出た場合は「取引先マスタが削除された」パターンの可能性 → 『伝票別入荷一覧』でエラーチェック →「取引先マスタに存在しません」なら取引先マスタで該当仕入先を未削除に戻す → 再度エラーチェックで「未入荷」に戻れば再開OK。

ログインできない / 全画面が使えない

システム更新等で稼働停止中の可能性。3回程度試して駄目ならシステム管理者へ。ID・パスワード不明も管理者へ。

ログイン時に日次締を促すメッセージが出る

前日の日次締が未実行でシステム管理日付が過去日のまま。日次メニュー → 『日次締処理』を実行してから業務開始。

「不明なエラー」「致命的エラー」が出た

システム内部エラー。操作では復旧できません。発生時刻・操作内容を控えて、サーバログの確認をシステム管理者へ依頼。

欠品になった / 引当がおかしい
  1. 欠品行は一覧で青文字。まず『在庫問合せ』で引当可能数を確認（引当済数に食われていないか）。
  2. 在庫はあるのに引当されない場合: 出荷限界日切れ・期限日逆転防止・引当禁止ロケ・出荷停止フラグを疑う。期限日を指定した出荷指示ならチェック対象外にできる。
  3. 復旧: 【出庫指示解除】 → 指示修正 or 在庫を直す（入荷実績・調整・移動）→ 再度【出庫指示】。未出荷のまま欠品表示だけ消すなら【欠品解除】。
「出荷停止中、または引当不可の商品が含まれています」

出庫指示の後に商品・取引先マスタで出荷停止が設定されたケース。検品・確定が止まります（一覧はインディアンレッド背景）。マスタの出荷停止を確認し、解除するか指示をキャンセル。

マスタが削除できない / 削除したら画面がおかしくなった

在庫がある取引先・商品・ロケーションは削除できません（エラーで保護）。ただし入荷予定・出荷指示だけが残っている場合は削除できてしまい、「該当データが存在しません」「名称が表示されない」等が発生。対処: マスタを未削除に戻す → エラーチェックで解消。

納品書・EC送り状が出せない（EC）

EC受注データが出荷日起算の保持期間を過ぎて自動削除された可能性。こうなると復元不可 — 以後は取り置き時に出荷日を更新する運用で防止。EC送り状は出庫指示済以降でないと一覧に出ない点も確認。

荷札の印字がずれる・用紙送りがおかしい

プリンタドライバの用紙サイズとセンサタイプの設定ミスが定番。荷札・印刷のページの一覧表どおりか確認（ゆうパック・ヤマト系は反射センサ「アイマーク」指定）。

画面が崩れる・ボタンが隠れる

推奨環境からのずれ（解像度1920×1080・拡大率100%・標準フォント）を確認。1ページ表示件数を変えたときは再検索が必要。Excel出力は一覧表示に関係なく検索条件の全件（上限あり）が出る仕様です。

GLOSSARY用語辞書（よく使う順）

上の検索ボックスで絞り込めます。全268語の完全版は原本「用語辞書.xlsx」へ。

入荷 / 入庫 / 出庫 / 出荷
入荷=荷受完了、入庫=所定場所へ格納、出庫=ピッキング、出荷=発送。WMSでは厳密に使い分ける。
荷主
荷物の所有者、または業務を委託した事業者。1つのWMSで複数荷主を管理でき、ログイン後に切替可能。
センタ / 倉庫 / ゾーン / ロケーション
センタ＞倉庫＞ゾーン＞ロケーションの階層。ロケーションは棚1つ1つに割り当てた番号。
ピックロケ / バックロケ
ピックロケ=バラピッキング用の棚。バックロケ=補充用にケース単位で保管する棚。ケース引当はバックロケから、端数バラはピックロケから。
入庫仮ロケ
正規ロケへ格納するまで一時的に在庫を計上するロケーション。
引当可能数 / 引当済数
引当可能数=これから引当できる在庫。引当済数=引当済みでまだ出荷確定していない数（未出荷数）。
出庫指示
在庫の引当とピッキング指示の作成。ここで在庫が「引当済」になる。
出荷確定
出荷業務の最終処理。引当済数から出庫数が引き落とされる。以降の修正は不可。
強制確定
目視検品などでWMS上の検品を通さずに出荷確定すること。確定一覧に「強制確定」と表示される。
WMS入荷伝票No. / WMS出荷伝票No.
予定・指示の登録時にセンタ単位で採番される伝票番号（13桁）。
出庫作業No.
出庫指示時に採番。同一出荷日・納品先・配送コースを名寄せした作業単位で、ピッキング・検品・梱包・荷札アタッチの単位になる。納品指定日・時間帯が違うと別番号。
出庫指示バッチNo.
1回の出庫指示のまとまりに付く番号。
入庫ラベルNo.（入庫No.）
在庫が作られた単位に付く管理番号。番号だけで商品・ロケ・ロット・期限日等を特定できる。先入先出や期限管理の要。
入庫No.管理フラグ / マージ区分
入庫No.で在庫を分けて管理するかの設定。00=マージしない（厳密管理）、01=ピックロケのみ自動マージ、02=自動マージ（実質管理なし）。HTの画面フローもこれで変わる。
汎用ラベル
作業前に事前発行しておくラベル。印字された入庫ラベルNo.を実績入力時に指定して使う。
ロット管理 / 期限日管理
商品マスタのフラグ。管理品は在庫発生時（入荷実績・在庫調整）にロット／期限日の入力が必須になる。
期限日逆転防止
前回出荷した期限日より古い在庫を引当てない仕組み。商品マスタ＋取引先マスタ両方で「管理する」のとき有効。
出荷期限日数 / 出荷限界日
期限日までの残り日数がこの値を切った在庫は引当てない。出荷指示で期限日を指定すればチェック対象外。
在庫区分
同じ商品を状態別（通常/不良品/検査中など）に分けて管理する区分。導入時に任意設定。
預託
在庫はセンタで保管するが所有権が荷主先にある状態。出店者別管理などに使う。
処理区分
在庫に対する処理の種別。01通常入荷/02返品入荷/11通常出荷/12返品出荷、21移動/23調整(-)/24調整(+)/25入庫格納/32定期補充/33緊急補充 など。
赤処理 / 黒処理
受払履歴の訂正方式。訂正・取消は元の処理をマイナス計上（赤）し、新しい処理（黒）を立てる。
オーダーピッキング
納品先（出庫作業No.）単位でピッキングする方式。
トータルピッキング
複数オーダーの総数をまとめてピッキング（一次）し、その後仕分（二次）する方式。
摘み取り / 種蒔き
二次ピッキングの2方式。摘み取り=仮置き場から納品先単位に取る。種蒔き=納品先別に配って仕分ける。
マルチピッキング
複数オーダーを台車のバケットに同時ピッキングする方式。
ケースピッキング
ケース引当分をケース単位でピッキング。ケース引当があるときはケースピッキングリストが必ず出る。
単行ピッキング
1商品だけの伝票をまとめて処理する方式。対象は単行リストからしかピッキングできない。
ピッキング提案
引当データから最適なピッキング方式を自動提案するサービス（要設定）。
定期補充 / 緊急補充
定期=補充点を切ったピックロケへの計画補充。緊急=出庫指示時の在庫不足で自動発生する補充。
補充点 / 最大格納数
ロケーションマスタの設定。補充点を切ると補充対象になり、最大格納数を超えては補充されない。
定点
商品マスタの基準在庫量。全センタ合計で定点を切るとトータル在庫問合せに表示。
配送コース
運送業者・方面・引取時間ごとの出庫作業グループ。取引先マスタ（1:1）か配送コースマスタ（1:n）で設定。
ワンタイム
届先を出荷指示ごとに直接入力できる納品先設定（取引先マスタのワンタイムフラグ）。
顧客出荷指示No.
顧客独自の伝票番号。ピッキングリストと伝票の照合に使う。
アタッチ
ピッキングした商品と荷札・納品書・送り状を出庫作業No.で照合して組み合わせる作業。
梱包計算
容積・重量から箱数を自動計算する機能（パラメータマスタで有無・詰め方を設定）。
セット組 / セット解除
複数の構成品から親商品を作る／親商品を構成品に戻す在庫処理。
循環棚卸 / 一斉棚卸
循環=ロケ・ゾーン・受払日で範囲を絞る棚卸。一斉=条件なしの全件棚卸。
日次締処理
1日の最後の締め。在庫繰越（前日残設定）・保持期間超過データの削除・翌稼働日設定を行う。
システム管理日付
WMS内の「今日」。日次締で進む。受払が発生した日には戻せない。
3期制（10日/15日/20日/末日残）
保管料計算用に月内の区切り日時点の在庫数を自動保持する仕組み。
パラメータマスタ
センタ・荷主単位のWMS動作設定。欠品時挙動・自動出力・引当順序・補充・梱包計算など、ほぼ全ての「挙動の違い」の源泉。
引当ソートキー
引当順序のカスタマイズ設定（ロット/期限日/ゾーン/ロケ/入庫ラベルNo./入庫日等を1〜8位で指定）。未設定時は 取引先引当順序→期限日→ロケ引当順序→入庫ラベルNo.→ロット→ロケCD の順。
EDI
WebAPIによるデータ自動連携。受信=マスタ・入荷予定・出荷指示、送信=入庫実績・出荷実績・在庫。
HT / SD
HT=ハンディターミナル（キー操作）。SD=スマートデバイス（スマホ・タブレットのブラウザ操作）。
ソースCD
CODE39/128/CODABAR/JAN/ITF等のバーコード値の総称。スキャン入力の基本。
シリアルNo.
商品個々の管理番号。同一商品CD＋シリアルNo.の重複登録は不可。登録後の編集は削除→再取込。
出荷停止フラグ
商品単位・納品先単位で出荷を止める設定。出庫指示後に設定すると検品・確定でエラーになる。
引当禁止フラグ
ロケーション単位で引当を止める設定。他ロケに在庫がなければ欠品になる。
