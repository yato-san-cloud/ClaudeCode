# kintone 不具合連絡票アプリ — 構築と運用

全体構想は `docs/不具合票転記_構想.md`。ここはアプリ構築と日々の運用手順。

## 1. アプリを作る（10分・どちらか一方）

### A. スクリプトで作る（推奨）

```bat
set KINTONE_DOMAIN=(会社ドメイン).cybozu.com
set KINTONE_USER=(ログイン名)
set KINTONE_PASS=(パスワード)
python create_app.py --dry-run      :: まず内容確認
python create_app.py                :: 作成+デプロイ。スペース内に作るなら --space ID
```

- アプリ作成 API はパスワード認証が必須（API トークンでは作れない）
- 表示された **appId** を控える
- アプリ作成権限が無い場合はエラーになる → B の手動作成に切り替え

### B. 手動で作る

kintone →「アプリ」→「作成」→ フィールドを `create_app.py` の FIELDS の定義どおり配置
（フィールドコードも同じにする。defects_upload.py がコード名で書き込むため）。

### 作成後の共通設定（2分）

1. アプリ設定 → API トークン → 生成（**レコード閲覧・追加・編集**にチェック）→ 保存
2. 一覧を 2 つ作る: 「未転記(発行済み)」= 状態が発行済み ／ 「全件」= レコード番号降順

## 2. 発行運用（連番の付け方）

**票No = kintone のレコード番号。** 紙に書く前に kintone で発行する。

1. 不具合発生 → 現場 PC/スマホで本アプリ「＋」→ 発生日だけ入れて保存（状態は既定で「発行済み」）
2. 表示された**レコード番号を紙の票の余白に書く**（これが票No）
3. 紙はこれまでどおり記入・バインダー保管

→「発行済みのまま残っているレコード」＝ まだデータ化されていない紙、が常に一覧で見える。

## 3. 転記運用（週次または都度）

1. バインダーを撮影（真上から1枚ずつ）or 複合機で PDF 化
2. M365 Copilot で **[CPA-004] 不具合票転記** に添付 →「転記して」
3. 出力をそのまま `転記出力.txt` に貼って保存
4. ```bat
   set KINTONE_DOMAIN=... & set KINTONE_APP_ID=... & set KINTONE_API_TOKEN=...
   python defects_upload.py 転記出力.txt --dry-run   :: 検証だけ
   python defects_upload.py 転記出力.txt             :: 反映
   ```
5. スクリプトが自動でやること:
   - **機械検証**: JAN チェックデジット(EAN-13) / 選択肢 enum / 日付形式 / 伝票番号 T+6桁 /
     【要確認】残存 → NG 票は送信せず差し戻し一覧に出す（原票と照合して直す）
   - 票No あり → 該当レコードを**更新**し状態を「転記済み」に / 票No なし → 新規作成
   - 最後に**漏れ検知レポート**（発行済みのまま残っている票の一覧）を表示
6. レポートだけ見たいとき: `python defects_upload.py --report`

## 4. 検証済みの動作

`sample_転記出力.txt`（実物写真2票＋検証NGデモ1票）で dry-run 済み:
実物2票は正しいレコード JSON に変換、NG票は「JANチェックデジット不一致」
「伝票番号が T+6桁 でない」で差し戻された。

## 5. 役割分担（なぜこの分け方か）

| 役割 | 担当 | 理由 |
|---|---|---|
| 手書きの読み取り | CPA-004（視覚AI） | 手書き・丸・チェックの解釈は LLM の得意領域 |
| 数字の検算・形式検証 | defects_upload.py | チェックデジット等の算術は LLM に任せず機械で確実に |
| kintone への書込 | defects_upload.py（API トークン） | T1 エージェントは書き込み不可のため |
| 漏れの検知 | kintone の状態フィールド＋レポート | 発行→転記の突合はクエリ1本 |
