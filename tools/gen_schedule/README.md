# gen_schedule — スケジュール3型(WBS/支援者/移管)をデータ1式から自動生成

構想の背景と全体像は `docs/スケジュール管理_構想.md` を参照。
gen_knowledge.py の兄弟スクリプト（正はデータ、見た目は生成）。

## 使い方

```bat
:: 3型連動(プロジェクトフォルダを渡す)
python gen_schedule.py "(OneDrive同期フォルダ)\ローソン立上げ" --out 出力先

:: WBS型のみ(タスク表1枚を渡す)
python gen_schedule.py tasks.csv
```

- `--today 2026-07-17` … テスト用に「今日」を固定
- 再実行のたびに全出力を上書きし、3表まとめて前回との差分を `変更履歴.md` に自動追記

## プロジェクトフォルダの構成（ファイル名で自動発見）

| ファイル | 型 | 必須 |
|---|---|---|
| `tasks.csv` | WBS型（立上げ・レイアウト変更） | ○ |
| `assignments.csv` | リソース型（支援者） | 任意 |
| `lots.csv` + `quota.csv` | 数量型（移管） | 任意（2つセット） |

## 連動のしくみ

- 3表は **関連タスクID** で `tasks.csv` に紐づく
- 実行時に**整合チェック**が走り、矛盾は警告＋`スケジュール_最新.md` 冒頭に出る:
  - 割当・移管計画が関連タスクの期間外
  - 関連タスクID が tasks に存在しない
  - 移管ロットの計画合計 ≠ 総量
- `スケジュール_最新.md` は3型統合のスナップショット（遅延/今週タスク/マイルストーン/
  今週の支援者/割当日数/移管消化率）。SharePoint に置けばエージェントの根拠になる

## 列仕様

### tasks.csv（WBS型）

| 列 | 必須 | 内容 |
|---|---|---|
| ID | ○ | 一意（例: S-01）。履歴の追跡キーなので途中で変えない |
| 大項目/中項目/小項目 | 大のみ○ | WBS 階層。ガントの行グループは大項目単位 |
| 担当正/担当副 | 正のみ○ | 部署または氏名 |
| 開始日/終了日 | ○ | YYYY-MM-DD |
| 状態 | ○ | 未着手 / 着手 / 完了 |
| マイルストーン | | 値が入っていれば ◆ 表示（終了日の週） |
| 先行ID / 進捗メモ / 備考 | | 任意 |

### assignments.csv（リソース型・1行=1人×1日）

| 列 | 必須 | 内容 |
|---|---|---|
| 日付 / 氏名 | ○ | |
| 所属 | | 例: [営業] [中営開] |
| 場所 | | マトリクスのセル色は場所ごとに自動割当 |
| 時間帯 / 作業内容 / 備考 | | |
| 関連タスクID | | tasks.csv の ID。期間整合チェックの対象 |

### lots.csv + quota.csv（数量型）

| ファイル | 列 |
|---|---|
| lots.csv | 移管元 / 荷姿 / 頻度 / 総量 / 関連タスクID / 備考 |
| quota.csv | 移管元 / 荷姿 / 頻度 / 日付 / 計画 / 実績（未実施日は空欄のまま） |

移管の実績は quota.csv の「実績」列に数字を入れるだけ。消化率・遅れ・バーンダウンは自動計算。

## 出力

| ファイル | 用途 |
|---|---|
| `<名前>_ガント.xlsx` | 現行様式の週次ガント（□■☆◆・今日の週に色）。定例会・印刷用 |
| `<名前>_ガント.html` | ブラウザガント。担当フィルタ・今日線・遅延赤枠。Teams 共有用 |
| `支援者_マトリクス.xlsx / .html` | 人×日付の割当表（場所ごとに色・割当日数集計つき） |
| `移管_マトリクス.xlsx` | ロット×日別の計画/実績（実績記入済セルは達成=緑/未達=橙） |
| `移管_バーンダウン.html` | 累積計画 vs 実績の消化曲線 |
| `スケジュール_最新.md` | 3型統合スナップショット（エージェント用ナレッジ） |
| `変更履歴.md` | 3表の差分を日付つきで自動追記 |
| `.snapshot.json` | 差分検出用の内部ファイル（消すと次回が「初回登録」になる） |

## サンプル

- `sample/ローソン立上げPJ/` … 3表そろったプロジェクト＋出力一式（`out/`）。
  整合チェックのデモとして**わざと 2 箇所エラー**が入れてある（S-13 期間外の割当・計画合計の10PL不足）
- `sample/ローソン立上げPJ_移管期間中/` … 移管3日目まで実績を記入した状態
  （--today 2026-11-19 で生成）。バーンダウンと「遅れ 202 PL」検出のデモ

## 運用ルール

1. 人が編集するのは3表だけ。出力ファイルは直接編集しない（次回実行で消える）
2. 週次（定例会前）に1回実行。移管期間中は日次（実績記入→実行）。定時ジョブ化は「営業管理_週次」タスクに1行
3. ID は永久欠番方式。行の削除より状態・備考で残す方が履歴が読める
4. 整合チェックの警告が出たまま定例会に出さない（警告は md の冒頭にも載る）
