# セッション引継ぎSkill

「文脈ゼロから読める単一ファイル」を生成する。HANDOFF_to_CLCode / SQL_AI_HANDOFF で実証済みの型を標準化。

## 2つのモード

1. **HANDOFF(引継ぎ書)**: セッションの全文脈を次セッションへ。ファイル名 `HANDOFF_テーマ_vN.md`
2. **申し送り(依頼/回答/通知)**: 特定の依頼・回答のみ。ファイル名 `依頼_内容_to_宛先_from_発信元_YYMMDD.md`(回答_/通知_も同形)

## 必須構成(HANDOFFモード)

```markdown
# HANDOFF_テーマ_vN
- 作成: YYYY-MM-DD ／ 発信元セッション: ◯◯ ／ 想定読者: 文脈ゼロのAIセッション

## 0. クイックスタート(読者のAIがまずやること・やらないこと)
## 1. 経緯(3〜10行。決定の変遷を「A→B→C」で)
## 2. 確定事実(番号付き。各項目に根拠=元資料名+行番号/セル番地を必ず付ける)
## 3. 未解決論点(各論点に「現状の仮説/次に取る行動/判断者」)
## 4. ファイル地図(正本★・参考・アーカイブの区別付き)
## 5. 用語集(案件固有語・社内略語)
## 6. 次アクション(担当・期日)
```

申し送りモードは §0/2/3/6 のみで可。回答期限と回答形式(md/xlsx/JSON)を明記する。

## 手順

1. セッション内の決定事項・生成物・未決事項を洗い出す
2. **確定事実と仮説を峻別する**。根拠(行番号・セル・議事録L番号)を付けられないものは仮説側へ
3. ファイル地図はMOC・運用ルール(`docs/02`)の★規約に従う
4. 機密フィルタ: 🔒私的メモ(人物評・交渉戦術)の内容を**引継ぎ書に転記しない**。必要な場合は「交渉戦略メモvNを別途参照(配布禁止)」とポインタのみ
5. 読者テスト: 「このファイルだけ渡された新セッションが、質問なしで次アクションに着手できるか」を自問し、足りない前提を補う

## 禁止事項・安全

- 認証情報・接続設定・個人評価を本文に書かない
- 引継ぎ書から辿れない口頭前提を残さない(残る場合は〔口頭前提あり・要ユーザー補足〕と明記)
- 既存HANDOFFの上書き禁止。版を上げる

## 完了条件

- 確定事実の全項目に根拠が付いている
- 次アクションに担当と期日(または「みなし期日」)が入っている
