# 保守モード（既存エージェントの変更対応）

新規作成ではなく、**稼働中・設計中の既存エージェントへの変更依頼**を処理するときの
ワークフロー。`agent-package.md`（管理体系の正典）と `spec-template.md` /
`studio-setup-guide-template.md` / `effort-design.md` の内容と矛盾しないことを前提に、
差分対応の手順だけをここに定義する。

## トリガー

以下のような言い回しで依頼が来たら、このワークフローに入る。

- 「CPA-◯◯を更新したい」「CPA-◯◯の◯◯を直して」
- 「◯◯エージェントの挙動を直したい／トーンを変えたい」
- 「〇〇の業務も対応できるようにしたい」（既存エージェントへの追加の場合）
- 「モデルを変えたい」「エフォートを上げ下げしたい」
- 「名前を変えたい」「あのエージェント、もう使ってない」（名称変更・廃止）

新規にエージェントを作る依頼（対応する CPA-NNN がまだ存在しない）は対象外。
その場合は手順 (1) の判定でスキル本文の通常フロー（新規作成）に切り替える。

## 全体フロー

| # | ステップ | やること |
|---|---|---|
| 1 | 現状把握 | 台帳とパッケージ 5 点セットを読む |
| 2 | ヒアリングと分類 | 変更内容を聞き、影響マトリクスの行に当てはめる。理由（Why）を必ず確認する |
| 3 | 影響マトリクス確認 | 更新対象ファイルと Studio 側操作を確定する |
| 4 | ファイル更新 | 該当ファイルを直し、版を上げ、spec.md の変更履歴に記入する |
| 5 | 再設定手順書の生成 | `re-setup-CPA-NNN-v{新版}.md` をパッケージ直下に生成する |
| 6 | 品質チェック再実行 | 変更対象に応じたチェック項目だけを確認する |
| 7 | 締め | 台帳を更新し、SharePoint 再アップロード対象を提示し、検証質問を出す |

---

## (1) 現状把握

1. `agents/registry.md` を読み、対象の `CPA-NNN` の行を探す
2. 行が **ない** 場合: このワークフローを終了し、「台帳に該当エージェントが
   見つからない。新規作成として進めるか」をユーザーに確認したうえで、
   スキル本文（`SKILL.md`）の通常の新規作成フローに切り替える
3. 行が **ある** 場合: `agents/CPA-NNN-<slug>/` 配下の 5 点セット
   （`spec.md` / `instructions.md` / `skills/skill-*.md` 全部 / `setup-guide.md` /
   `tests.md`）をすべて読む。台帳の「版」と `spec.md` の変更履歴表の最新版が
   一致しているか確認し、不一致なら先にユーザーに報告する

## (2) 変更内容のヒアリングと分類

1. ユーザーの依頼を、下の「(3) 影響マトリクス」のどの行に当たるか判定する
2. 複数の行にまたがる場合は、当たる行をすべて挙げる（合算は (4)(5) で行う）
3. **理由（Why）を聞き出す**。依頼文に理由が含まれていなければ、
   「なぜこの変更が必要か（困りごと・きっかけ）」を 1 問だけ確認する。
   理由が確認できない変更は `spec.md` の変更履歴に書けないため、
   このステップを飛ばさない
4. 変更が影響マトリクスのどの行にも当てはまらない場合は、**更新対象になる
   ファイルの種類が一致する行**を候補として選ぶ（例: スキル文書を触る変更なら
   「ナレッジの手順修正」行）。候補が絞れない・複数残る場合は仮適用せず、
   「更新するファイルと Studio 側操作」の案を提示してユーザーに確認してから進める

## (3) 影響マトリクス（中核）

変更種別ごとに「更新するパッケージファイル」と「Studio 側で必要な再設定操作」を
一意に決める表。**変更が複数種別にまたがる場合は、該当する行の更新ファイルと
操作をすべて合算する**（重複するファイルは 1 回だけ更新すればよい）。

| 変更種別 | 更新するパッケージファイル | Studio 側で必要な再設定操作 |
|---|---|---|
| ナレッジの手順修正 | `skills/{該当}.md` | 該当ファイルをナレッジから削除 → 修正版を再アップロードのみ |
| 業務の追加 | `skills/{新規}.md`（新規作成）＋ `instructions.md`（Routing に 1 行追記）＋ `tests.md`（テスト質問追加） | ナレッジにファイルを追加アップロード ＋ 指示欄を全文貼り替え |
| 挙動・トーン調整 | `instructions.md` | 指示欄を全文貼り替え |
| エフォート／モデル変更 | `spec.md`（6 節「モデル・公開設定」表） | 設定 → 生成 AI でプライマリモデルを変更 |
| 名称・目的変更 | `spec.md`（1 節ヘッダ）＋ `agents/registry.md` | エージェント名を変更（`[CPA-NNN]` プレフィックスは維持） |

補足:
- 「ナレッジの手順修正」で `instructions.md` の Routing 行のタイトル文言まで
  変えた場合は「挙動・トーン調整」も同時に当たる扱いにし、指示欄の貼り替えを追加する
- 「業務の追加」で追加する業務が `deep` に分類される場合は、
  `effort-design.md` の 3 点セット（Routing のエスカレーション文・検討プロトコル・
  推奨依頼文）を新規スキル文書と `instructions.md` に組み込む
- 上記 5 行に当てはまらない変更（業務の廃止、参照文書の統合等）が発生した場合は、
  (2)-4 の基準（更新ファイルの種類が一致する行を候補にし、絞れなければユーザーに確認）
  で操作を確定し、次回以降のためにこの表へ行を追加する

## (4) ファイル更新

1. 影響マトリクスで確定したファイルを実際に書き換える
2. **版を上げる**（本書のルール）:

   | 変更の種類 | 版の上げ方 |
   |---|---|
   | ナレッジ修正・トーン調整・業務追加・モデル変更 | 第 2 位を +1（例: v1.0 → v1.1） |
   | 名称・目的変更、廃止など、エージェントの位置づけ自体が変わる変更 | 第 1 位を +1 し第 2 位を 0 に戻す（例: v1.1 → v2.0） |
   | 複数の変更を同時に反映する場合 | 該当する上げ方のうち大きい方を 1 回だけ適用する |

3. `spec.md` の「8. 変更履歴」表に 1 行追加する。**理由（Why）列は (2) で確認した
   内容をそのまま書く。空欄のまま進めない**
4. `spec.md` の 1 節ヘッダの「版」も新しい版番号に更新する

## (5) 再設定手順書の生成

`agents/CPA-NNN-<slug>/re-setup-CPA-NNN-v{新版}.md` を新規生成する
（パッケージ直下。`skills/` の中には置かない）。**フルの配備ガイドではなく、
今回の差分に絞った手順書**にする。`studio-setup-guide-template.md` と同じ粒度——
「どの画面で・どこを押して・何を貼るか」が一意に決まる書き方——を守る。

雛形:

```
# 再設定手順: [CPA-NNN] {エージェント名} — v{旧版} → v{新版}

変更日: {YYYY-MM-DD}
変更内容: {1行要約}
理由（Why）: {(2)で確認した理由}

## 対象操作

{(3) で当たった行の操作だけを、以下から該当分を残して並べる}

### A. ナレッジ差し替え・追加
1. `https://copilotstudio.microsoft.com` を開く → 対象エージェント
   `[CPA-NNN] {エージェント名}` を選択 → 「ナレッジ」タブを開く
2. {修正の場合} 一覧から `{skill-xxx.md}` を選び「削除」→
   「ナレッジを追加」→「ファイル」→ 修正済みの `{skill-xxx.md}` をアップロード
   {追加の場合} 「ナレッジを追加」→「ファイル」→ 新規の `{skill-yyy.md}` をアップロード
3. 状態が「準備完了」になるまで待つ（数分）

### B. 指示欄の貼り替え
1. 「概要」タブ → 「指示」欄の内容を全選択して削除
2. 下記の指示欄全文をそのまま貼り付ける

```
{instructions.md の更新後全文}
```

3. 文字数が 8,000 字以内であることを確認して保存する

### C. モデル変更
1. 「設定」→「生成 AI」→ プライマリモデルのドロップダウンで
   `{変更後のモデル名}` を選択 → 保存

### D. 名称変更
1. 「概要」タブ → 「名前」欄を `[CPA-NNN] {変更後の名称}` に書き換え → 保存
   （`[CPA-NNN]` の部分は変えない）

## 動作確認

| # | テスト質問 | 期待する挙動 |
|---|---|---|
| 1 | {変更箇所に関するテスト質問1} | {期待する挙動} |
| 2 | {変更箇所に関するテスト質問2} | {期待する挙動} |
```

- `{ }` はすべて実際の値で埋めてから渡す。雛形のまま渡さない
- A〜D のうち今回の変更で当たらない節は削除する（合算した場合はすべて残す）

## (6) 品質チェック再実行

フルの品質チェック（`SKILL.md` の一覧）ではなく、**変更したファイルに対応する項目だけ**
を再確認する。

| 変更したファイル | 再確認する項目 |
|---|---|
| `instructions.md` | 指示欄が 8,000 字以内か／Routing の参照タイトルと `skills/*.md` の `#`（h1）が完全一致するか／Error handling の文言が残っているか |
| `skills/skill-*.md`（既存修正） | 各 `##` セクションが単独で意味が通るか／命令口調の混入がないか |
| `skills/skill-*.md`（新規追加） | 冒頭に「この文書が扱う依頼の例」があるか／入出力例が 1 組以上あるか／`deep` なら 3 点セットが揃っているか、`light`/`standard` なら 3 点セットが入っていないか |
| `spec.md` の構成表（モデル） | 選んだモデルが `copilot-studio-track.md` のモデル対応表（light: Instant系 / standard: 既定 / deep: Thinking系）と整合しているか |
| 名称変更 | Studio 名が `[CPA-NNN] 名前` 形式を保っているか／台帳の「名称」列と一致しているか |

## (7) 締め

1. `agents/registry.md` の該当行を更新する。「版」「最終更新日」は毎回更新し、
   それ以外は下表のとおり変更種別に対応する列だけを更新する:

   | 変更種別 | 追加で更新する台帳の列 |
   |---|---|
   | ナレッジの手順修正／挙動・トーン調整 | なし（版・最終更新日のみ） |
   | 業務の追加 | 目的(1行)（対象業務が増えた場合のみ書き直す） |
   | エフォート／モデル変更 | モデル |
   | 名称・目的変更 | 名称、目的(1行) |
   | 廃止 | 状態（→ 停止） |
2. SharePoint への再アップロード対象を提示する。`agent-package.md` の規則により
   **差分ファイルだけでなく、その版のパッケージ一式を毎回置き直す**ため、
   提示するのは以下の固定リストになる:
   - `spec.md` / `instructions.md` / `skills/` 配下の全ファイル /
     `setup-guide.md` / `tests.md`（`copilot-agents/CPA-NNN_{名称}` フォルダへ上書き）
   - 生成した `re-setup-CPA-NNN-v{新版}.md` も記録として同フォルダに合わせて置く
3. **検証質問を 1 つ以上ユーザーに出す**。例:
   - 「テストパネルで {テスト質問} を投げた結果、期待どおりの文書が根拠として
     示されたか確認をお願いします」
   - 「モデル変更後、応答速度・推論の深さに体感差があるか教えてください」
