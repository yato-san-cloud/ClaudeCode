# 配備ガイド雛形（Copilot Studio 版・エージェントごとに生成して渡す）

スキルはこの雛形の `{ }` をすべて実際の値で埋めた
`agents/CPA-NNN-<slug>/setup-guide.md` を生成する。**ユーザーがこのガイドだけを見て、
画面を探し回ることなく配備を完了できる**ことが合格基準。

生成時のルール:

- `{ }` は全項目を実際の値で埋める。空欄のまま渡すことは禁止
- 「適宜」「など」「必要に応じて」という書き方は禁止。手順・設定値は具体的に書き切る
- 手順は「どの画面で・どこを押して・何を貼る/選ぶ」が一意に決まる粒度にする
- 指示文（instructions.md）の全文、ナレッジ一覧（skills/ 配下）、テスト質問
  （tests.md）は、それぞれの元ファイルの内容をそのまま埋め込む。要約や省略はしない
- STEP 0 には、Copilot Studio の UI ラベルは更新頻度が高く、本雛形の表記と
  完全一致しない場合がある旨と、その際の探し方（近い意味の項目名を探す）を明記する

---

# 配備ガイド（Copilot Studio 版）: {エージェント名}

管理番号: {CPA-NNN} ／ Studio 上の名前: `[{CPA-NNN}] {エージェント名}`

所要時間の目安: 20分（うち待ち時間 5〜10 分。ナレッジのインデックス作成待ち）

---

## STEP 0: 前提チェック（2分）

1. ブラウザで `https://copilotstudio.microsoft.com` を開く
2. サインイン後、左側に「エージェント」「フロー」の項目が並ぶホーム画面が表示されれば
   準備完了。次の STEP 1 に進む
3. 開けない場合（サインインで弾かれる、テナントの選択肢に出ない、権限エラーが出る）は、
   情シスに以下の文面で依頼する:

   > Copilot Studio（`https://copilotstudio.microsoft.com`）へのアクセス権を
   > 付与してください。用途は社内業務用エージェントの作成です。M365 Copilot
   > ライセンス内での利用のため追加費用は発生しません。
   > テナント: {テナント名} ／ 依頼者: {氏名（部署）} ／ 利用者アカウント: {アカウントのメールアドレス}

   テナント名がわからない場合は、社用メールアドレスの `@` より後ろのドメイン
   （例: `example.co.jp`）をそのまま書けば情シスには伝わる。

4. **注意**: Copilot Studio の画面ラベルは更新が速く、本ガイドに書いた文言
   （「新しいエージェント」「構成に進む」等）と完全一致しないことがある。
   一致するボタンが見当たらない場合は、同じ意味に近い名前のボタンやメニュー項目
   （例:「新しいエージェント」→「エージェントを作成」／「作成」、
   「構成に進む」→「スキップして構成する」／「スキップ」）を探して読み替える。
   **3 分探しても見つからない場合は無理に進めず**、その画面のスクリーンショットを
   撮って {困ったときの連絡先（このガイドの作成依頼元）} に確認する。

## STEP 1: エージェント作成（3分）

1. 左メニューの「**エージェント**」をクリックする
2. 「**新しいエージェント**」をクリックする
3. 会話形式でエージェントの目的を聞かれる作成画面が開くが、この対話は使わない。
   画面上部（または右上）の「**構成に進む**」を押して、直接「構成」タブに移動する
4. 「構成」タブの各欄に、下の対応表のとおり貼り付ける

| 画面の欄 | 貼り付ける内容 |
|---|---|
| 名前 | `[{CPA-NNN}] {エージェント名}` |
| 説明 | {1〜2 文の説明。spec.md の「2. 背景」または「3. 目的と成功の定義」から転記} |

5. 入力後、画面上部に「保存済み」表示があるか確認する。「**保存**」ボタンが
   表示されている画面の場合は押してから次へ進む（Studio には自動保存の画面と
   手動保存の画面が混在する。以降の STEP でも同じ確認をする）
6. **誤って別のエージェントを作ってしまった場合の戻り方**: 左メニュー「エージェント」
   の一覧に戻る → 該当エージェント行の「…」メニュー →「**削除**」→ 確認ダイアログで
   「削除」を押す → STEP 1 の 1 からやり直す

## STEP 2: 指示文の貼り付け（3分）

1. 「構成」タブの「**指示**」欄を開く
2. `agents/{CPA-NNN}-{slug}/instructions.md` を開き、全文をコピーする
3. 「指示」欄に貼り付ける（既定文言が入っている場合は全選択して置き換える）
4. 文字数の警告表示が出ていないことを確認する（8,000 文字以内であることは
   生成時に検証済みだが、貼り付け後の表示でも念のため確認する）
5. STEP 1-5 と同様に、保存済み表示（または「保存」ボタン）を確認してから次へ進む

**用語**: この指示文の中にある「## Routing」見出し配下の一覧表を、本ガイドでは
「Routing」と呼ぶ。依頼の類型と、根拠にするナレッジ文書（h1 タイトル）を
対応付ける表のこと。トラブル対処で登場する。

## STEP 3: ナレッジ登録（5分＋待ち時間）

1. 「構成」タブの「**ナレッジ**」セクションで「**追加**」をクリックする
2. ソースの選択肢から「**ファイル**」を選ぶ
3. `agents/{CPA-NNN}-{slug}/skills/` 配下の `.md` ファイルをすべてまとめて選択し、
   アップロード画面にドラッグ&ドロップする（1 ファイルずつでもよいが、まとめて
   ドロップした方が早い）
4. アップロード直後は各ファイルの状態が「処理中」または「インデックス作成中」と
   表示される。**すべてのファイルの状態が「準備完了」になるまで待つ**（数分かかる）
5. アップロードしたファイルは以下のとおり（一致しているか確認する）

| # | ファイル名 | h1 タイトル | エフォート | 状態確認 |
|---|---|---|---|---|
| 1 | {skill-xxx.md} | {スキル: 〇〇} | {light/standard/deep} | 「準備完了」を確認 |

## STEP 4: 設定トグル（3分）

1. 画面右上の「**設定**」（歯車アイコン）をクリックする
2. 左側に出るメニューから「**生成 AI**」を開く（見当たらない場合は「全般」セクション
   内に統合されていることがあるので、そちらも確認する）
3. 以下の表のとおり設定する

| 設定項目 | 場所 | 設定値 | 理由 |
|---|---|---|---|
| プライマリモデル | 設定 → 生成 AI → 「プライマリモデル」ドロップダウン | {下のエフォート対応表から選んだモデル名} | この業務のエフォートに合ったモデルを固定で使わせるため |
| AI の一般知識 | 設定 → 生成 AI（またはナレッジ設定内）の「AI の一般知識を使用する」トグル | オフ | 登録したナレッジ以外の知識で誤答することを防ぐため |
| Web 検索 | ナレッジ設定内「Web サイトを検索」のトグル | オフ | 社内手順以外を根拠に回答させないため |

### プライマリモデルのエフォート対応表

| エフォート | モデルの選び方 |
|---|---|
| `light` | Instant / 高速系 |
| `standard` | 既定（自動ルーティング） |
| `deep` | Thinking / reasoning 系 |

このエージェントの業務構成は {light/standard/deep が混在している場合はその内訳、
単一の場合はそのエフォート} のため、プライマリモデルは **{選定結果のモデル名}** を選ぶ。
{混在している場合の補足: deep 業務だけ別エージェントに分けたか、既定モデルのまま
指示文でのエスカレーションに委ねたかを記載}

4. 設定変更後、保存済み表示（または「保存」ボタン）を確認してから設定画面を閉じる

## うまく動かないとき

| 症状 | 原因 | 対処 |
|---|---|---|
| ナレッジのファイルが「準備完了」にならない | インデックス未完了 | 数分待って画面を再読み込みする。10 分待っても変わらない場合はファイルを削除し、再アップロードする |
| プライマリモデルの選択肢に deep 用モデルが出ない | テナントでそのモデルが有効化されていない、または有償プレビュー扱い | 情シス・管理者にモデルの有効化を依頼する。依頼文例:「Copilot Studio のプライマリモデルに {モデル名} を追加してください。テナント: {テナント名}」 |
| ナレッジと関係ない一般知識で答える | 「AI の一般知識」トグルがオンのままになっている、または設定変更が反映されていない | STEP 4 のトグル設定を確認する。変更直後は反映まで数分かかることがあるため、時間を置いて再テストする |
| 回答の引用リンクが開けない、グレーアウトしている | ローカルアップロードしたファイルの仕様上の制約であり、故障ではない | クリックできなくても問題ない。引用に表示される文書名（h1 タイトル）で根拠文書を判別する |
| テスト質問への回答が想定と違う文書を参照する | 指示欄の Routing のタイトルと、ナレッジ文書の h1 タイトルが不一致 | `instructions.md` の Routing 表と各 `skill-*.md` の h1 を完全一致させ、STEP 2 の指示欄を貼り直す |
| 公開後、Teams や M365 Copilot から見つからない | チャネル設定で「Teams と Microsoft 365 Copilot」が未有効化、または公開範囲の共有先にそのユーザーが含まれていない | STEP 6 のチャネル設定と公開範囲を確認する |

## 更新のしかた（運用開始後）

- **指示・手順を変えたいとき**: git のマスター（`instructions.md` または
  `skills/skill-*.md`）を直してから、STEP 3 のナレッジ画面で該当ファイルを
  削除して再アップロードする（Dataverse 上のファイルは直接編集できない）。
  再インデックスに数分かかる
- **業務を追加したいとき**: 新しい `skill-<slug>.md` を追加 → STEP 3 で
  アップロード → 「編集」画面で指示欄の Routing に 1 行追加 → STEP 5 のテスト
  質問を追記して再検証する
