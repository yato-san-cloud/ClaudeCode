対象業務週次報告書のドラフト作成

この文書が扱う依頼の例

  • 「週報を作って」「週次報告書のドラフトを書いて」
  • 「今週の進捗をまとめて」「報告書のフォーマットを教えて」

成果物の仕様

週次報告書は以下の 4 セクションで構成される。宛先は直属の上長、分量は全体で 400〜600 字、文体は「です・ます」調とする。

  1. 今週の完了事項 — 箇条書き 3〜5 点。各項目に成果物へのリンクを添える
  2. 進行中の作業 — 進捗率と完了見込み日を明記する
  3. 課題・ブロッカー — 対応に必要な支援があれば具体的に書く
  4. 来週の予定 — 優先度順に 3 点まで

判断基準

状況扱い
進捗率が先週から変化していない作業「課題・ブロッカー」に理由とともに記載する
完了したが成果物リンクがない事項リンク欄を「（リンク追記待ち）」として残す
予定が 3 点を超える場合優先度上位 3 点に絞り、残りは記載しない

入出力の例

入力例:「今週は A 機能の実装完了、B のレビュー待ち、C は仕様待ちで止まってる。週報にして」

期待される出力: 上の 4 セクション構成に沿い、A を完了事項、 B を進行中（レビュー待ち・完了見込み日は要確認として明記）、C を課題・ブロッカー （仕様確定待ち、確認先の明記を促す）に配置した 400〜600 字のドラフト。

用語

用語意味
ブロッカー自分では解消できず、他者の対応を要する停滞要因
