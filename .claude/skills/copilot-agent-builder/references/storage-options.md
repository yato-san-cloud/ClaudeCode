# ナレッジ置き場の選択肢（SharePoint が嫌いな人向けの回避策込み）

**Copilot Studio が使える場合はこのファイルは基本不要**（.md/.html を直接
アップロードでき、SharePoint を使わない。copilot-studio-track.md を参照）。
以下はエージェントビルダートラック用。要件ヒアリング時に「SharePoint への
抵抗感」を確認し、以下から選ぶ。

## ルート A: SharePoint をエクスプローラー化する（基本推奨）

SharePoint の Web UI を使うのは初回だけにして、以後はただのフォルダとして扱う。

1. 対象ライブラリを一度だけブラウザで開き、ツールバーの「**同期**」
   （または「**OneDrive へのショートカットの追加**」）を押す
2. 以後、エクスプローラー（Mac は Finder）に普通のフォルダとして現れる。
   HTML の追加・上書きはドラッグ&ドロップで完結し、自動で SharePoint に反映される
3. 「どこにあるかわからない」対策:
   - ライブラリは **1 エージェント = 1 フォルダ**、全部を `copilot-skills` 直下に集約。散らさない
   - 配備ガイドに必ずライブラリ URL を記載する（このスキルの雛形は記載欄あり）
   - サイトを「フォロー」しておくと SharePoint スタートページの一覧に常駐する

## ルート B: SharePoint を完全回避する（docx 埋め込み方式）

エージェントビルダーの**埋め込みファイル（直接アップロード、最大 20）**を使えば
SharePoint を一切触らずに済む。ただし .html は不可なので **.docx で出力**する。

- スキル文書を HTML ではなく Word（.docx）で生成する。見出し 1/2、表、番号リスト
  という構造規約はそのまま適用できる（グラウンディングはテキストのみなので品質は同等）
- エージェント作成画面の「ナレッジ」→ デバイスからアップロード、で完結
- **トレードオフ**: 上限 20 ファイル / 更新のたびにエージェント編集画面で
  再アップロードが必要（SharePoint 方式ならファイル上書きだけで反映）
- 向くケース: 個人用・スキル数が少ない・更新頻度が低い

ユーザーが docx 方式を選んだ場合、スキルは HTML の代わりに同じ構造規約の
Markdown を生成し、pandoc 等で docx 化するか、Word に貼れる形で渡す。

## ルート C: kintone をマスターにして自動同期する

kintone で管理し、SharePoint へは機械に運ばせる方式。

- サイボウズ公式の「**連携コネクタ**」（2026-05 正式リリース）が kintone ⇄
  SharePoint / OneDrive / Teams / Outlook / Excel をノーコードで同期できる。
  **月 3,000 ステップまで無料**
- 構成: kintone アプリ（レコード＋添付ファイル）をマスター → コネクタで
  SharePoint ライブラリに自動同期 → エージェントはそのライブラリをナレッジ参照
- kintone 側の更新だけで運用が回る。SharePoint は「Copilot に読ませるための
  裏方ストレージ」に格下げされ、人間は触らない
- 注意: 同期のタイムラグ＋Copilot 側の再インデックス（数分）の二段遅延がある
- **前提条件: 連携コネクタの導入には kintone 側のシステム管理（ドメイン管理者）
  権限が必要**。ドメインが本社・情シス管理で自部門に権限がない場合、このルートは
  使えない（ルート A/B に切り替える）

## （参考）Copilot Studio が使える場合

- ナレッジに **HTML を直接アップロード可能（最大 500 ファイル）**で SharePoint 不要
- kintone は Power Platform の kintone コネクタや MCP でライブ照会もできる
  （同期ではなく実行時にレコードを取りに行く）
