# Copilot Studio トラック（Studio が使える場合の既定ルート）

エージェントビルダー（HTML＋SharePoint 方式）ではなく Copilot Studio
（copilotstudio.microsoft.com）で配備する場合の差分。**Studio が使えるなら
こちらを既定にする。**

## ライセンスの前提

- M365 Copilot ライセンスがあれば、**社内利用・ライセンス保持者向けのエージェントは
  追加費用なしで Copilot Studio を使える**（2025-09 以降）
- クレジット課金（従量）が必要になるのは: 自律トリガー実行 / 社外・無ライセンス
  ユーザーへの公開 / 一部の有償プレビューモデル。個人業務の自動化なら通常は不要

## ナレッジ: Markdown を既定にする

Studio のファイルアップロードは **.md / .html を含む多形式に対応**（最大 500 ファイル、
各 512 MB、Dataverse に格納）。SharePoint は不要。

- **スキル文書は Markdown（skill-<slug>.md）で生成する**。HTML 方式より
  シンプルになる理由: スタイルの雛形が不要 / git・GitHub 上でそのまま
  差分管理・レンダリングできる / グラウンディング品質は同等（どちらもテキストと
  見出し構造しか使われない）
- 構造規約は HTML 版と同一のまま読み替える:
  - `#`（h1）は 1 ファイルに 1 つ＝スキル名。Routing はこのタイトルで参照
  - 冒頭にメタ情報表と「この文書が扱う依頼の例」
  - `##` セクションは自己完結。手順は番号リスト、判断基準は表、入出力例を 1 組以上
  - `deep` 業務には検討プロトコルと推奨依頼文（effort-design.md の 3 点セット）
- HTML を選ぶのは「文書を SharePoint 上の人間向けマニュアルとしても使い回す」
  場合のみ
- 既知の注意: ローカルアップロードしたファイルは回答の引用リンクがクリック不可に
  なることがある。文書側の h1 タイトルを一意にしておけば、どの文書が根拠かは
  引用名で判別できる

## モデル選択: エフォートを「本物の設定」にする

Studio ではプライマリモデルをドロップダウンで指定できる（設定 → 生成 AI）。
エフォート 3 段階をそのままモデル選択に対応させる:

| エフォート | モデルの選び方 |
|---|---|
| `light` | Instant / 高速系（応答速度優先） |
| `standard` | 既定（自動ルーティング）のままでよい |
| `deep` | **Thinking / reasoning 系**（GPT-5.x Thinking、テナントで有効なら Claude 等） |

- モデルはエージェント単位の設定。エフォートが混在する場合は、
  (a) `deep` 業務だけ別エージェントに分ける、または
  (b) 既定モデルのまま effort-design.md のプロンプト誘導で運用する、のどちらかを提案する
- 一部の最新モデルは有償の実験プレビュー扱いのことがある（選択肢に出ない場合は
  管理者による有効化が必要）
- **deep の 3 点セット（検討プロトコル・推奨依頼文・Routing のエスカレーション文)は
  Thinking モデルを選んでも残す**。モデルは推論の深さを、プロトコルは推論の型と
  検証可能性を担保するもので、役割が違う

## エージェントビルダーとのその他の差分

- **一般知識の遮断が本当にできる**: ナレッジ設定の「AI の一般知識を使用する」を
  オフにすると、登録ナレッジのみで回答させられる（ビルダーでは不可能だった）
- 指示文の書き方・8,000 字目安・Routing 方式・ナレッジに命令を置かない原則は
  そのまま適用する
- 発展（必要になったら別途設計する。最初のエージェントには入れない）:
  ツール接続（Power Automate / コネクタ / MCP）、定期・イベントトリガーによる
  自律実行（クレジット課金）、エージェント間連携（A2A）

## 配備ガイド生成時の差し替え（setup-guide-template.md の STEP 1〜3 を置換）

1. **STEP 1（SharePoint 不要）**: `https://copilotstudio.microsoft.com` を開く →
   左メニュー「エージェント」→「新しいエージェント」→「構成に進む」（対話形式はスキップ可）
2. **STEP 2**: 名前・説明・指示（instructions 全文）を貼り付け
3. **STEP 3**: 「ナレッジ」→「ナレッジを追加」→「ファイル」で skill-*.md を
   まとめてドラッグ&ドロップ → インデックス完了（状態が「準備完了」になる）まで待つ
4. **STEP 3.5（Studio のみ）**: 設定 → 生成 AI → プライマリモデルをエフォート表に
   従って選択 / 「AI の一般知識」を業務エージェントでは原則オフ
5. **STEP 4**: 「公開」→ チャネルで「Teams と Microsoft 365 Copilot」を有効化 →
   テスト質問で動作確認（テストパネルは公開前でも使える。まずテストパネルで
   Routing を検証してから公開するのが速い）
6. 文書更新時: ナレッジ画面で該当ファイルを削除→再アップロード
   （git のマスターを直してから上げる。Dataverse 上のファイルは編集できない）
