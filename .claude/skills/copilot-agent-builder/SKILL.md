# Copilot エージェント作成スキル（HTML スキル文書方式）

M365 Copilot のエージェントビルダーで動く「宣言型エージェント」を、
**指示欄（instructions）＋ SharePoint 上の HTML スキル文書**の 2 層構成で設計・生成するスキル。
Copilot Studio ライセンスや Cowork が使えない環境（M365 Copilot のみ）を前提とする。

## 大原則（役割分担）

Microsoft の公式ガイダンスに基づく、破ってはいけない分担:

| 置き場所 | 入れるもの | 入れてはいけないもの |
|---|---|---|
| **指示欄**（8,000字上限） | エージェントの役割・トーン・トリガー条件・どの HTML 文書をいつ参照するかのルーティング | 長大な手順の本文 |
| **HTML スキル文書**（SharePoint） | 手順の詳細・テンプレート・用語集・チェックリスト・参考例 | エージェントの挙動を変える命令文 |

理由: ナレッジは「信頼された作成者の指示」として扱われず、クロスプロンプトインジェクションの
対象になり、文書の編集権限を持つ誰でも実行時の挙動を変えられてしまう（Microsoft 公式の警告）。
したがって HTML 文書は**命令ではなく参照資料の文体**で書く（「〜せよ」ではなく「手順は以下の通り」）。

## 制約の要点（詳細は references/limits-and-facts.md）

- 指示欄: **8,000 文字**
- HTML ファイルは **SharePoint 経由でのみ**ナレッジにできる。デバイスから直接アップロードする
  埋め込みファイル（最大20）は doc/docx/pdf/ppt/pptx/txt/xls/xlsx/csv のみで **.html 不可**
- SharePoint ファイルは最大 **100**、OneDrive は 50、公開 Web サイトは 4 URL
- グラウンディングには**テキストだけ**が使われる。CSS・JS・画像は無視される
  （HTML の装飾は人間の可読性のためであり、Copilot には見出しとテキスト構造だけが効く）
- 新規アップロード後、インデックスに数分かかる

## ワークフロー

### 1. 要件ヒアリング

不足していれば以下を確認してから着手する:

- エージェントの目的と対象ユーザー（自分専用か、チーム共有か）
- 自動化したい業務の一覧（それぞれが HTML スキル文書 1 枚に対応する）
- 利用可能なナレッジ（SharePoint サイト、既存文書）
- 会社のポリシー上の制約（外部サイト参照可否、コネクタ有効化状況）

### 2. スキル文書の分割設計

- **1 業務 = 1 HTML ファイル**。Claude のスキルと同じ粒度で切る
- ファイル名は `skill-<slug>.html`（例: `skill-weekly-report.html`）
- 各文書の冒頭に「この文書が扱う質問・依頼の例」を書く（検索でヒットさせるためのキーワード）

### 3. HTML スキル文書の生成

`references/html-skill-template.html` をベースに生成する。構造の規約:

- `<h1>` は 1 つだけ＝スキル名。直下にメタ情報表（版数・更新日・所有者・対象業務）
- `<h2>` 単位でセクションを自己完結させる（チャンク分割されても意味が通るように、
  セクション内で代名詞や「上記の」への依存を避ける）
- 手順は `<ol>`、並列事項は `<ul>`、パラメータや判断基準は `<table>`
- 具体例（入力例→期待出力例）を最低 1 組入れる
- スタイルは `<style>` 1 ブロックに閉じた自己完結 HTML（外部 CSS/JS/画像なし）。
  装飾は最小限——グラウンディングでは無視されるため、投資すべきは見出し構造と本文

### 4. 指示欄（instructions）の生成

`references/instructions-template.md` をベースに、**8,000 字以内**で生成する。
Markdown で記述し、以下を含める:

- Purpose（役割 1〜2 文）/ General guidelines(トーン・言語・出力形式・してよいこと)
- **Routing**: 「依頼 X を受けたら、ナレッジ内の文書『<HTML の h1 タイトル>』の手順に従う」
  という対応表。ファイル名ではなく **h1 タイトルと冒頭キーワード**で参照する（検索精度のため)
- Error handling: 該当文書が見つからない場合は推測せずその旨を答える、という指示
- 生成後に文字数を数え、超過時は Routing 以外から削る

### 5. 配備手順の出力

ユーザーに以下のチェックリストを渡す:

1. HTML ファイルを SharePoint の所定ライブラリにアップロード（権限＝エージェント利用者と同一）
2. M365 Copilot → 右上「エージェントを作成」→ 構成タブで名前・説明・指示欄を貼り付け
3. ナレッジで該当 SharePoint ファイル（またはフォルダ）を追加
4. 数分待ってからテストプロンプトで動作確認（各スキル文書につき最低 1 問）
5. 文書更新時は SharePoint 上で上書き（エージェント側の再設定は不要、再インデックスに数分）

### 6. テスト質問の生成

各 HTML スキル文書につき、「正しくその文書が引かれるか」を確かめる質問を 2〜3 個生成して渡す。
うち 1 個は文書名を含まない言い回しにする（ルーティングの検証）。

## 品質チェック（生成物を渡す前に自己検査）

- [ ] 指示欄が 8,000 字以内か（日本語は文字数がそのままカウントされる前提で数える）
- [ ] HTML 文書に命令口調の「エージェントへの指示」が混入していないか
- [ ] 各 h2 セクションが単独で読んで意味が通るか
- [ ] Routing の参照タイトルと HTML の h1 が一致しているか
- [ ] 外部リソース（CDN・画像・スクリプト）への依存がないか
