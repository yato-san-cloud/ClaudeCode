# MOC棚卸しSkill

MOCの手動運用で起きる4種の劣化(掲載漏れ/リンク切れ/★重複/旧版注記漏れ)を検出する。**読み取り専用** — 修正はすべて「追記案」として提示し、適用は人間が行う。

## 入力

1. MOC本体(Drive上の `MOC.md`)
2. 対象フォルダ(未指定なら全番号フォルダ 00_〜99_)

## 手順

1. **MOC解析**: `[[wikiリンク]]` とバッククォートのファイルパス参照をすべて抽出し、リンク一覧を作る
2. **フォルダ走査**: Drive MCP(読み取りのみ)でフォルダ配下のファイル一覧を取得(検索は `parentId` ベースで再帰的に)
3. **突合4検査**:
   - **掲載漏れ**: フォルダに存在するがMOCに無いmd/主要成果物(xlsx/html/docx)。一時ファイル(`_tmp` `.bak` 等)は除外
   - **リンク切れ**: MOCにあるがフォルダに実体が無い(拡張子違い .md⇔.html の取り違えも検出 — 過去に実例あり)
   - **★重複**: 同一系統(ベース名が同じで版番号のみ違う)に★が2つ以上(運用ルールV-2違反)
   - **旧版注記漏れ**: vN+1が存在するのに vN の行に `（参考、最新はvX）` が無い(V-1違反)
4. **報告書生成**: 検査結果+「MOCに追記すべき行」のコピペ可能なブロックを出力

## 出力フォーマット

```markdown
# MOC監査レポート_YYMMDD
## サマリ(検出件数: 掲載漏れX/リンク切れY/★重複Z/注記漏れW)
## 1. 掲載漏れ(ファイルパス+推奨掲載セクション+追記行の案)
## 2. リンク切れ(該当行+原因推定[削除済/リネーム/拡張子違い]+修正案)
## 3. ★重複・注記漏れ(該当行+修正案)
## 4. アーカイブ候補(3版以上前・運用ルールV-4該当。※移動は人間が実行)
```

## 禁止事項・安全

- **Driveへの書き込み・リネーム・削除は一切しない**(追記案の提示まで)
- アーカイブ候補・削除候補は列挙のみ。「削除してよい」とは書かず、判断材料(最終更新日・参照元の有無)を添える
- 大量フォルダの場合は番号フォルダ単位で分割実行し、途中経過を報告する

## 完了条件

- 4検査すべての結果が報告されている(検出ゼロもゼロと明記)
- 追記案がそのままMOCにコピペできる形式になっている
