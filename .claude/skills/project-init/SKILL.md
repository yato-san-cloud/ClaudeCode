# プロジェクト立ち上げキット展開Skill

新しい物流プロジェクトの初日に、`templates/プロジェクト立ち上げキット/` の雛形一式を対話で埋めて提示する。**Driveへのフォルダ作成・ファイル書き込みは行わない**。生成物のコピー&配置は人間が行う。

## 入力(対話で聞く項目)

以下を順に確認する。ユーザーが最初のメッセージでまとめて答えていれば聞き直さない。

1. 案件名(正式名称。例: 「◯◯様2拠点化案件」)
2. 案件タグ(ファイル名接頭辞。未指定なら案件名から短縮案を提案し、確認を取る。例: 「(◯◯)」や「0716」のような会議日起点タグは使わない — タグは案件を通して固定のものを使う)
3. 顧客名(社名・敬称込みで良い)
4. 開始日(YYYY-MM-DD。未指定なら本日日付を提案し確認を取る)
5. 関係者一覧(当社側・顧客側それぞれの氏名/役割。わかる範囲でよく、後で追記可と伝える)
6. フェーズゲート名(社内の意思決定ゲート名。無い/不明な場合は空欄可とし、案件用CLAUDE.mdの当該欄に〔未設定〕と残す)

入力が足りないとき: 上記のうち埋まらない項目があっても停止しない。空欄のまま「〔未設定・後日追記〕」と明記して生成を進める(初日10分で骨格を作ることが目的であり、完全な情報が揃うまで待たない)。

## プレースホルダ置換表

`templates/プロジェクト立ち上げキット/` 配下の4ファイル(フォルダ構成雛形.md / MOC雛形.md / CLAUDE.md雛形.md / 申し送りプロトコル.md)で共通して使うプレースホルダ。

| プレースホルダ | 埋める内容 | 未回答時 |
|---|---|---|
| `{{案件名}}` | 対話で聞いた案件名 | 〔未設定〕 |
| `{{案件タグ}}` | ファイル名接頭辞 | 案件名からの短縮案(要確認と明記) |
| `{{顧客名}}` | 顧客名 | 〔未設定〕 |
| `{{開始日}}` | 開始日(YYYY-MM-DD) | 本日日付(提案である旨を明記) |
| `{{関係者一覧}}` | 当社・顧客双方の氏名/役割 | 〔未設定・後日追記〕 |
| `{{フェーズゲート名}}` | フェーズゲート名 | 〔未設定〕 |

## 手順

1. 上記6項目を対話で確認する(未回答は空欄可・明記のうえ進める)
2. `templates/プロジェクト立ち上げキット/` の4ファイルを読み込み、置換表に従ってプレースホルダを埋める(雛形ファイル自体は書き換えない。出力は新規の案件用ドラフトとして提示する)
3. 生成した4ファイルの内容をチャット上に提示する。ファイル名の提案も添える:
   - `フォルダ構成_{{案件タグ}}_v1.md`(改訂され得る文書のため命名規則N-2に従いv1を付ける)
   - `MOC.md`(★これは案件フォルダの「生きた文書」。運用ルールのLIVING_DOC扱いで版・日付を持たない)
   - `CLAUDE.md`(案件フォルダ直下用)
   - `申し送りプロトコル_{{案件タグ}}_v1.md`(同上)
4. 未設定・要確認のまま残した項目を一覧で最後にまとめ、人間に確認を促す
5. Driveへの配置手順を案内する: 「番号フォルダの作成 → 各Markdownの配置 → MOC.mdを案件フォルダ直下に → CLAUDE.mdを案件フォルダ直下に、はユーザー側で実施してください」で締める

## 出力フォーマット

```markdown
# プロジェクト立ち上げキット生成結果 — {{案件名}}

## 1. フォルダ構成雛形(置換済み)
(フォルダ構成雛形.mdの内容をそのまま提示)

## 2. MOC雛形(置換済み)
(MOC雛形.mdの内容)

## 3. 案件用CLAUDE.md(置換済み)
(CLAUDE.md雛形.mdの内容)

## 4. 申し送りプロトコル(置換済み)
(申し送りプロトコル.mdの内容)

## 5. 未設定・要確認項目
- (項目名): 〔未設定〕→ 後日ユーザーが埋めてください

## 6. Driveへの配置(ユーザー側で実施)
1. 案件フォルダ直下に番号フォルダ(00_〜)を作成
2. 上記1をもとに各フォルダの用途メモを配置(任意)
3. 上記2を `MOC.md` として案件フォルダ直下に保存
4. 上記3を `CLAUDE.md` として案件フォルダ直下に保存
5. 上記4を必要なファイル名で保存
```

## 禁止事項・安全

- **Google Driveへの接続・フォルダ作成・ファイル書き込みは行わない**。生成物の提示までがAIの担当(業務OSリポジトリ共通ルール)
- 配布・送信はしない
- 関係者一覧・機密区分欄に🔒私的メモ(人物評・交渉戦術)の具体的な中身を書き込まない。機密区分欄は運用ルールの分類名の説明に留める
- 案件タグ・フォルダ構成を勝手に確定させない。未確認の提案には必ず「要確認」を付ける
- 生成する `フォルダ構成雛形.md` 相当の内容や `MOC雛形.md` 相当の内容は、本リポジトリの雛形ファイル自体を書き換えるものではない。案件フォルダ用の**コピー**として提示する

## 完了条件

- 6項目(案件名・案件タグ・顧客名・開始日・関係者・フェーズゲート名)のすべてに値または明示的な〔未設定〕が入っている
- 4ファイルすべてのプレースホルダが置換済み、または〔未設定〕で明示されている(`{{...}}` の生残りが無い)
- Driveへの配置手順が案内されている
