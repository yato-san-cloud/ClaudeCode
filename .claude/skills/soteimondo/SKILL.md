# 想定問答Skill

議事録・残論点表を入力に、会議直前に読み込める**想定問答パック**(社内限り)をドラフトする。配布はしない・正本化は人間が行う点は他Skillと同じ。

## 入力

1. 直近〜過去の議事録(論点・ステータス・宿題。L番号があれば引用に使う)
2. 残論点表・宿題一覧(あれば。継続論点のステータス引継ぎに使う)
3. 次回会議のアジェンダ・相手側の立場が分かるメモ(あれば)
4. 任意: 一次データ(xlsx)のありか。答弁に数字を含める場合の検算導線に使う

**入力に使ってはいけないもの**: 🔒私的メモ(人物評・交渉戦術メモ)。議事録・論点表に🔒私的メモが混在している場合は、その部分を読み飛ばし、使わなかった旨をチャットで報告する。

入力が足りないとき: 残論点表が無ければ議事録から論点とステータスを再抽出して進める。相手側の立場メモが無ければ「出やすさ」は保守的(高め)に見積もり、その旨を明記する。

## 手順

1. **論点棚卸し**: 議事録・残論点表から「相手に聞かれそうな論点」を抽出し、一時ID(Q1, Q2, …)を振る。〔継続〕〔条件付き〕ステータスの論点は優先的に拾う
2. **想定質問化**: 各論点を相手視点の質問文に変換する(「なぜ〇〇なのか」「〇〇はいつまでに」等)
3. **背景・出やすさ評価**: なぜその質問が出そうか(前回発言・議事録L番号を根拠に)、出やすさを高/中/低で付ける
4. **答弁要旨作成**: 簡潔な答弁の骨子を作る。決まっていない事項は「検討中」と明記し、決まったふうに書かない
5. **強弱評価**: 各問に強=即答可(社内合意済・根拠明確)/弱=持ち帰り(未合意・根拠薄い・戦略判断が要る)を付ける。弱は無理に強へ寄せない
6. **根拠の紐付け**: 各問に議事録のL番号・資料名を付ける。根拠が無い想定問答は〔根拠不明〕と明記する
7. **数字を含む答弁の検算導線**: 答弁要旨・答弁スクリプトに具体的な数字(金額・件数・期日等)を書く場合は、その場で検算せず「suji-trace Skillで検算済み」か「〔未検算〕」かを明記する。未検算のまま強=即答可にしない
8. **逆質問票の作成**: こちらから相手に確認すべき事項を優先度(高/中/低)付きでリスト化し、回答記入欄を空欄で用意する
9. **答弁スクリプト化**: 強弱に関わらず全問ではなく、**重要論点のみ**を話し言葉の答弁スクリプトに落とす

## 出力フォーマット

`templates/想定問答テンプレ.md` に準拠。3部構成:

- **(A) 想定問答N問**: 想定質問/質問の背景・出やすさ/答弁要旨/強弱評価(強=即答可・弱=持ち帰り)/根拠(議事録L番号・資料名)
- **(B) こちらから相手への質問票**: 優先度付き・回答記入欄
- **(C) 答弁スクリプト**: 重要論点のみ、話し言葉

改訂(v2以降)する際は、新規追加した項目に**★マーク**を付ける(既存の想定問答v2の慣行を踏襲)。旧版からの変更点が一覧できるようにする。

ファイル名: `社内説明_MMDD_内容_想定問答_v1.md`(運用ルール `docs/02` のN-1・N-5・機密区分「社内限り」に準拠)

## 禁止事項・安全

- **区分は「社内限り」**。テンプレ冒頭の配布禁止注記を削除しない。顧客・先方への配布物ではない
- **🔒私的メモ(人物評・交渉戦術)は入力に使わない・出力に書かない**。議事録等に混在していた場合は使用せず、チャットで報告する
- **答弁に含める数字は検算なしに確定表現で書かない**。suji-trace Skillでの検算を推奨し、未検算の数字は答弁要旨・スクリプトの双方に〔未検算〕と明記する
- Drive上のファイルは読み取りのみ。書き込み・リネーム・削除はしない(提案に留める)
- 配布・送信・削除は実行しない。ドラフト作成までがAIの担当
- 既存の想定問答ファイルを上書きしない。常に新規ファイル(次版番号)として出力

## 完了条件

- 全想定問答に強弱評価と根拠(または〔根拠不明〕)が付いている
- 答弁・スクリプト中の数字はすべて「検算済み」か「〔未検算〕」のいずれかが明示されている
- 🔒私的メモに由来する記述が本文中に一切無い
- (B)の質問票が優先度付きで、回答記入欄が空になっている
