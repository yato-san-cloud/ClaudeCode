# LYNA自動配車クラウド ユーザーガイド 構造化ノート(9〜13章)

## 9 ドライバー向けルート表示
- **目的**: ドライバーユーザーが自身の担当ルートをスマホ等で参照するための設定手順と、ドライバー側でできる操作(ルート参照・ファイルアップロード・メーター入力)を説明する。
- **要点**:
  - 前提: ①ドライバー権限ユーザーの作成(「ユーザー」→権限設定でドライバー選択)、②「ドライバー管理」でシステム上のドライバーを作成し「ドライバーユーザー」に紐づけ、③ルートへのドライバー割り当て。
  - 割り当て方法は2通り: 計画画面でルートの「ルート：ドライバーの入替」からドライバーを選択する方法、または車両マスタで「標準ドライバー」として設定する方法。
  - ルート参照には配車計画の「確定」が必須。確定方法は2通り: 配車計画一覧の右クリックで確定 / 配車計画画面の保存時に確定。
  - ドライバーはログイン後、担当ルートの訪問順・訪問先名称・住所を参照可能。「詳細」で訪問先詳細、「注文URL」で注文データに登録されたリンクへ遷移可能。
  - ファイルアップロード: 訪問先の「ファイル」から画像等を添付可能。タップで拡大、ロングタップで詳細(ダウンロード/表示/削除)。添付は共通マスタの訪問先マスタと計画内マスタにも反映され、管理者・配車担当ユーザーも参照可能。
  - 添付ファイル制限: 1訪問先20ファイル、1ファイル最大10MB。対応形式は画像(jpg/jpeg/png/gif/heic ※heicはjpg変換されプロパティ情報は引き継がれない)、txt、pdf。ファイル名は最大255文字(環境により短縮される場合あり)。
  - ファイル削除: ドライバーユーザーは自分がアップロードしたファイルのみ削除可。削除すると共通マスタ・計画内マスタからも削除される。
  - 開始・終了メーター: ルート上部で開始メーター、末尾で終了メーターを入力。両方入力すると本日の走行距離が自動計算。片方のみ入力も可(その場合走行距離は非表示)。
- **つまずきポイント/注意**:
  - 計画を「確定」しないとドライバーにルートが表示されない(最頻出のつまずき)。
  - メーター値の制限: 正の整数、1,000,000以下、終了≧開始。
  - heic画像は作成日時等のプロパティが失われる。
  - ファイルの表示有無・アップロード/削除可否、メーター表示有無は「ドライバー設定」「ドライバールートの設定」で制御可能。
- **用語**:
  - ドライバーユーザー: ドライバー権限を持つログインユーザー。ドライバー管理上のドライバーと紐づけて使う。
  - 確定: 配車計画を確定状態にする操作。ドライバー参照の前提条件。
  - 標準ドライバー: 車両マスタに設定する既定の担当ドライバー。
  - 開始/終了メーター: 車両オドメーターの走行前後の値。差分が本日の走行距離。

## 10 配車計画の共有(シェア)
- **目的**: 複数人が離れた場所から同じ配車計画を同時参照・順次編集し、チャットで連携する仕組みを説明する。
- **要点**:
  - 共有(シェア): 複数人が同じ配車計画に同時アクセスして閲覧可能。
  - 排他制御(ロック): 同時編集は不可。誰かが編集中は他ユーザーの画面に「※〇〇さんが編集中」と表示され、編集モードに切り替えられない。編集終了すると表示が自動で消え、他ユーザーが編集可能になる。
  - チャット機能: 同じ配車計画を見ながら別担当者とチャット可能。本部作成の配車結果を現場担当者にチェックしてもらう用途など。
- **つまずきポイント/注意**: 「編集できない」場合は他ユーザーが編集中の可能性。相手の編集終了を待てば自動的に編集可能になる。
- **用語**:
  - シェア(共有): 同一計画の同時閲覧。
  - ロック(排他制御): データ整合性のため編集を一人に限定する仕組み。

## 11 お客様のセキュリティ保全
- **目的**: 不正アクセスの検知手段(前回ログイン日時・利用状況レポート)と発見時の対処を説明する。
- **要点**:
  - メインメニュー右上に前回ログイン日時が表示される。心当たりのない日時なら不正アクセスの可能性 → すぐにパスワード変更。
  - 利用状況レポート(管理者のみ): 全ユーザーの利用状況・操作履歴ログを参照可能。身に覚えのない操作があれば不正アクセスの可能性 → すぐにパスワード変更。
- **つまずきポイント/注意**: 利用状況レポートは管理者専用機能。
- **用語**:
  - 利用状況レポート: 全ユーザーの操作履歴ログを参照する管理者機能。

## 12 未配車の原因と理由
- **目的**: 配車実行後に未配車が発生した際に表示される原因表示と、その考えられる理由(対処の手がかり)を一覧で示す。
- **要点**(原因 → 内容 → 考えられる理由の全ペア):
  1. **時間指定/帰庫時刻**: 時間指定に間に合わない、または車両の終了限界時刻までに帰庫できない。積み込み側の時間指定を守ると配送先の時間指定に間に合わない場合もこれ。→ 時間指定が厳しすぎる / 車両の出発時刻が遅すぎる / 車両の終了時刻が早すぎる / デポの時間指定と顧客の時間指定の間に時間的余裕がない。
  2. **デポの時間指定**: デポの時間指定に間に合わない。→ デポの時間指定が厳しすぎる / 車両の出発時刻が遅すぎる。
  3. **荷物が大きすぎる**: 積載可能な車両が存在しないか使用不可になっている。→ 荷物が大きすぎる / 注文分割が必要(「注文分割」参照) / 車型の積載上限が小さすぎる。
  4. **距離制約**: 距離が遠すぎて車両の距離上限に引っかかる。→ 車両の最大距離が小さすぎる / 顧客やデポが遠すぎる / 住所検索の結果、誤った位置に顧客・デポが設定されている(「名寄せ先出力について」参照)。
  5. **稼働時間制約**: 配送時間が長すぎて車両の稼働時間制約に引っかかる。→ 車両の最大時間が小さすぎる / 顧客やデポが遠すぎる / 住所検索の誤位置設定。
  6. **実働時間制約**: 配送時間が長すぎて稼働時間制約に引っかかる。→ 車両の最大超勤時間が小さすぎる / 顧客やデポが遠すぎる / 住所検索の誤位置設定。
  7. **車両不足**: 車両不足で運びきれない。→ 注文に対して車両が少なすぎる / この注文を運べる車型の車両が不足。
  8. **不採算または車両不足**(「コストに関わらず全注文を出来る限り集配する」がオフの場合のみ表示): 運ばない方が利益が大きいと判断された、または運びたいが車両不足。→ 全集配設定がオフ(配車設定の変更参照) / 注文の収入または配送漏れ罰金が小さすぎる / 車型のコスト設定が高すぎる / 車両が少なすぎる / 運べる車型の車両が不足。
  9. **指定された車両/車型が無いか使用不可 + 実働時間制約**: 車両・車型指定条件に合う車両が存在しないか使用不可。かつ配送時間が長すぎる。→ 指定車両・車型が存在しない / 使用不可に設定されている / 車両の最大超勤時間が小さすぎる / 顧客やデポが遠すぎる / 住所検索の誤位置設定。
  10. **最大注文数/回転当注文数/顧客数/回転数が0 + 車両不足**: 使用可能な全車両でこれらのいずれかが0に設定されている。かつ車両不足。→ 全車両の該当項目が0 / 車両が少なすぎる / 運べる車型の車両が不足。
  11. **不明(時間関係、バースの影響等) + 不採算または車両不足**: 上記以外の主に時間関係の理由で運べない、かつ不採算または車両不足(全集配オフ時のみ表示)。→ 全集配設定がオフ / 収入・配送漏れ罰金が小さすぎる / 車型コストが高すぎる / 車両が少なすぎる / 運べる車型の車両不足。
  12. **指定された車両/車型が無いか使用不可**(単独): 車両・車型指定の条件に合う車両が存在しないか使用不可。→ 指定車両・車型が存在しない / 使用不可に設定されている。
  13. **最大注文数/回転当注文数/顧客数/回転数が0**(単独): 全使用可能車両で該当項目のいずれかが0。→ 全車両の該当項目が0に設定されている。
  14. **不明(時間関係、バースの影響等)**(単独): 上記以外の主に時間関係の理由で運ぶことができない。
- **つまずきポイント/注意**:
  - 配送先の時間指定に余裕があっても、積み込み側(デポ)の時間指定との組合せで未配になることがある。
  - 「住所検索で誤った位置に設定されている」は距離・稼働時間・実働時間系に共通する隠れた原因。名寄せ先出力で確認。
  - 「不採算または車両不足」は全集配設定がオフのときだけ現れる。
- **用語**:
  - 未配車: 配車計算の結果どの車両にも割り当てられなかった注文。
  - 全集配: 「コストに関わらず全注文を出来る限り集配する」設定。
  - 配送漏れ罰金: 未配時に課すペナルティコスト。大きいほど配車されやすい。
  - 名寄せ先出力: 住所検索精度(位置ずれ)を確認する機能。
  - 回転: 車両がデポを出て戻るまでの1周回。

## 13 違反の原因と理由
- **目的**: 配車実行後に表示される「違反」(制約を破ったルート/訪問先)の種類と、確認・修正すべき設定項目を一覧で示す。
- **要点**:
  - **13.1 ルートの違反**(違反 → 超過した車両設定):
    1. 時間 → 車両「最大時間」超過。
    2. 超勤 → 車両「最大超勤時間」超過。
    3. 実働時間 → 車両「最大実働時間」超過。
    4. 超勤実働時間 → 車両「最大超勤実働時間」超過。
    5. 距離 → 車両「最大距離」超過。
    6. 注文件数 → 車両「最大注文数」超過。
    7. 顧客件数 → 車両「最大訪問件数」超過。
    8. 回転 → 車両「最大回転数」超過。
    9. 回転注文件数 → 車両「1回転当最大注文」超過。
    10. 回転顧客件数 → 車両「1回転当たり最大訪問件数」超過。
    - 「実働時間」「超勤実働時間」「注文件数」「回転注文件数」はシミュレーションでのみ表示される違反。
  - **13.2 訪問先の違反**(違反 → 内容と確認先設定):
    1. 遅れ → 注文・所在地の納品/回収時間帯を超えたルート。注文「納品/回収時間帯」・所在地「納品/回収時間帯」を確認。
    2. 容量オーバー → 積載量に対して荷量が多い。車型「最大積載量」・注文「荷サイズ」を確認。
    3. 時間枠より早い出発 → 注文の時間指定より早く出発。注文「納品/回収時間帯」を確認。
    4. 宵積みできない荷物を宵積 → 宵積み不許可の荷物を宵積み。注文「宵積み」を確認。
    5. 先に積んだ荷物を後に積んだ荷物より先に降ろしている → 同一回転で複数デポ積み込み時、最初のデポの荷物を先に降ろす訪問順になっている。
    6. バースの容量オーバー → 設定バース数を超過。訪問先「バース」を確認。
    7. 上限積載率 → 設定した上限積載率を超過。車両「上限積載率」を確認。
    8. 混載禁止 → 混載禁止の注文・訪問先が混載。訪問先「グループ」・注文「グループ」・配車設定「混載禁止の設定」を確認。
    9. 車両グループとの混載禁止 → 混載禁止の注文・訪問先が車両に混載。車両「グループ」・訪問先「グループ」・注文「グループ」・配車設定「混載禁止の設定」を確認。
    10. 車両指定違反(所在地) → 所在地の車両指定と異なる車両が向かっている。所在地「車両指定」を確認。
    11. 車両指定違反(注文) → 注文の車両指定と異なる車両が積んでいる。注文「車両指定」を確認。
    12. 車型指定違反(所在地) → 所在地の車型指定と異なる車型が向かっている。所在地「車型指定」を確認。
    13. 車型指定違反(注文) → 注文の車型指定と異なる車型が積んでいる。注文「車型指定」を確認。
    14. 車両の開始可能時刻 → 開始可能時刻より早く出発。車両「開始可能時刻」を確認。※画面上には表示されず、データ出力時に確認可能。
    15. 車両の開始限界時刻 → 開始限界時刻より遅く出発。車両「開始限界時刻」を確認。※データ出力時に確認可能。
    16. 車両の終了限界時刻 → 終了限界時刻より遅く運行。車両「終了限界時刻」を確認。※データ出力時に確認可能。
    17. 先行する回転に対する混載禁止違反 → 次の回転に積めない種類の荷物を積んでいる。配車設定「混載禁止の設定」を確認。
    18. セット配送違反 → セットで配送したい注文がセットになっていない。注文「セット名」を確認。
    19. 同一セット同一トリップ違反 → 同一セットが同一トリップになっていない。注文「セット名」を確認。
    20. セット順違反 → セット順の指定に違反。注文「セット順」を確認。
- **つまずきポイント/注意**:
  - エリア設定違反(車両が訪問できないエリアの所在地へ向かうルート)も「混載禁止」として表示される — 混載禁止違反が出たらエリア設定も疑うこと。
  - 開始可能/開始限界/終了限界時刻の違反は画面上に表示されず、データ出力時にのみ確認できる。
  - 一部のルート違反(実働時間・超勤実働時間・注文件数・回転注文件数)はシミュレーション機能でのみ表示される。
- **用語**:
  - 違反: 車両・注文・訪問先の制約条件を破って作成されたルート/訪問の警告表示。
  - 宵積み: 前日夜のうちに荷物を積み込んでおくこと。
  - バース: 訪問先で同時に接車できる車両数の枠。
  - 回転/トリップ: 車両がデポを出て戻るまでの1運行単位。
  - セット配送: 複数注文を同じルート・順序でまとめて配送する指定(セット名・セット順)。
  - 混載: 異なるグループの荷物・訪問先を同一車両に載せること。
