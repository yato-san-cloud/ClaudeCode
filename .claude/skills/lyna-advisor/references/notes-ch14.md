## 14. オプション機能

- **要点**: 14.1 追加積載上限 / 14.2 バース / 14.3 表引き / 14.4 発着管理 / 14.5 シミュレーション / 14.6 IPアドレス制限 / 14.7 赤伝・ゼロ伝 / 14.8 最適デポ選択 / 14.9 車両日付 / 14.10 実績からの学習 / 14.11 セット配送 / 14.12 協力会社DX の12機能。
- **つまずきポイント/注意**: 特になし（目次のみ）。

## 14.1. 追加積載上限
- **目的**: 形状の異なる荷物（大小カゴ車、キャリアカーへの各種車両など）を積み合わせる際、「残りスペースにあとどれだけ積めるか」の組み合わせを定義するための機能。
- **要点**:
  - 荷サイズごとの組み合わせ上限を車型に定義する。
  - 判定ロジック: 車型の荷サイズごとの「最大積載量」と「追加積載上限」の組み合わせの**全て**の上限を超えると積載不可。どちらか1つでも上限内なら積載可能。
  - 設定パターン: (a)「最大積載量」+「追加積載上限」で全組み合わせを網羅、(b)「最大積載量」を0にして「追加積載上限」だけで全組み合わせを定義、の2通り。
  - 画面から登録する手順:
    1. 車型登録画面下方の「追加積載上限の設定」に荷サイズの組み合わせを入力。
    2. 既存車型の場合は車型変更画面で「追加積載上限を変更する」をクリック。
    3. 組み合わせを入力し「変更」をクリック。
  - Excel取り込み: 車型管理画面の「データ取り込み」で「車型」「時間表」シートと一緒に「追加積載上限」シートを取り込む。
- **つまずきポイント/注意**: 上限判定は「全てを超えた場合のみ不可」というOR的な緩い判定なので、組み合わせを網羅的に定義しないと意図しない積載が許可され得る。
- **用語**: 荷サイズ=荷物の種類・寸法区分。車型=車両タイプのマスタ。カゴ車=かご型台車。

## 14.2. バース
- **目的**: 所在地で同時に積み降ろしできる車両台数（バース数）や利用可能時間帯、禁止車型など接車の制約を表現し、荷待ちを含めた現実的な配車計画を作るための機能。
- **要点**:
  - バース数を超えた車両は先行車両の出発まで積み降ろし不可という制約を定義。
  - 制約例: (1)禁止車型あり、(2)接車可能時間帯あり、(3)車型により占有スペースが違う（大型は2台分占有など）。
  - 設定のながれ:
    1. 訪問先側: バースの時間帯ごとの同時接車可能「台数」を登録。
    2. 車型側: バースを何台分占有するかの「占有係数」を登録。
    3. 同時に積み降ろし中の車両の占有係数合計がバースの台数を超えない範囲で接車可能。
  - 訪問先管理の設定項目: 台数 / 開始時刻 / 終了時刻 / 禁止車型（訪問先変更画面の「バースの設定」→「変更」）。
  - 時間帯の追加分（例: 9-12時は+2台）は「境界の時間をまたぐように記述する」設定（設定例1）を推奨。
  - 車型管理の設定項目: 占有係数（車型変更画面→「変更」）。
- **つまずきポイント/注意**:
  - 境界時刻（9:00, 12:00など）をはっきり区切る記述だと、境界の時間に正しいバース数で配車されないことがある → 境界をまたぐ記述を推奨。
  - 遅れ許容時の「遅れ」の定義が異なる: バース未設定の所在地=指定時間終了から車両**到着**まで、バース設定済み=指定時間終了から到着し**積込みを開始する**まで。
- **用語**: バース=積み降ろし用の接車スペース。占有係数=標準車両の何台分を占有するかの係数。接車=バースに車両を着けること。

## 14.3. 表引き
- **目的**: データ取り込み時に参照(ルックアップ)したいファイルを事前登録しておく機能。管理者に加え配車担当者権限でも利用可。
- **要点**:
  1. プランニング→「表引きファイル管理」をクリック。
  2. 「追加する」をクリック。
  3. 「ファイルを選択」→ダイアログで対象ファイルを選択→「実行」。
  4. 取り込み完了後、一覧に表示される。
- **つまずきポイント/注意**: ファイルサイズ20MB超は使用不可。
- **用語**: 表引き=取り込みデータの項目を別表から参照・変換するルックアップ処理。

## 14.4. 発着管理
- **目的**: ドライバーがルート表示画面から到着・荷役終了・出発などのステータスを登録し、配車担当が計画画面でリアルタイムに運行状況を把握するための機能。
- **要点**:
  - 事前設定:
    1. 計画カテゴリー変更画面「ドライバールートの設定」で「ステータスの表示」「メモの表示」を「表示する」に。
    2. 「配車盤カードの設定」で「配車結果:メモ」を追加（「ステータス」は初期設定で追加済み。「メモ更新日時」「メモ更新者」「ステータス実績時刻」も追加可）。
  - 運用: ドライバーユーザーでログイン→自ルート画面でステータスボタン（例:荷役終了）を押下→背景色が切替（集荷=ピンク、配送=水色、集配=青、OFF=グレー）。メモ入力も可能でリアルタイム反映。
  - ステータスの編集（管理者/配車担当が計画画面から）:
    1. 配車盤カードの「ステータス」ボタンをクリック→「ステータス設定」ダイアログ。
    2. 該当ステータス（例:「出発済み」）をクリックしてON/OFF切替、「✕」で閉じる。押し忘れ・誤押下の修正が可能。
  - 実績時刻の編集: ダイアログ上部「詳細」→「ステータス詳細設定」で各ステータスの「ステータス実績時刻」を編集、チェックを外すと未押下状態に戻る。「保存」で確定、「リセット」で保存済み状態に戻せる。
  - ステータスの設定: 計画カテゴリー変更画面→「ステータスの設定」で各ステータスの表示テキスト・背景色・使用有無を変更し「登録」。さらに「計画表示設定」→「配車盤の設定」の「カードの色の設定」で「配車ステータス」をチェックするとカード色がステータス連動（初期値は「なし」）。
- **つまずきポイント/注意**: カード色をステータス連動させるには「カードの色の設定」の変更が別途必要（初期は「なし」）。ドライバーの押し忘れは管理側で修正できる。
- **用語**: 配車盤カード=計画画面上の訪問先カード。運行実績=ステータス押下時刻の記録。荷役=荷物の積み降ろし作業。

## 14.5. シミュレーション
- **目的**: 実運用前の検証向け。データ取り込み機能の代わりにExcelから計画を新規作成して配車シミュレーションを行う版。
- **要点**:
  - 実運用版との最大の違い: 「データ取り込み」がなく「エクセルからの計画新規作成」でデータを投入。共通マスタをベースに取り込みExcelをマージして計画作成。他はほぼ実運用版と同等。
  - 手順:
    1. 「エクセルからの計画新規作成」をクリック。
    2. 「ファイルを選択」で取り込みファイルを指定（テンプレートファイルとデータ作成マニュアルがダウンロード可能）。
    3. 「利用するマスタ」で共通マスタの利用有無をチェック。
    4. 「実行」をクリック。
  - 計画名・日付が既存計画と重複した場合は確認画面が表示され、「重複処理」を選択（「計画名を変更する」を選ぶと変更後の計画名を入力）→「確定」。
- **つまずきポイント/注意**: 同名・同日付の計画重複時の処理選択を忘れずに。テンプレート/マニュアルの利用を推奨。
- **用語**: 共通マスタ=訪問先・車型などの共有マスタデータ。

## 14.6. ＩＰアドレス制限
- **目的**: 許可IPアドレスを登録し、それ以外からのログインを拒否するセキュリティ機能。
- **要点**:
  - IPアドレス管理: 登録済みIPの一覧表示。
  - 登録手順:
    1. システム設定→「ＩＰアドレス登録」。
    2. IP情報を入力（「マイＩＰ」ボタンで現在の接続元IPを自動セット）。
    3. 「登録」をクリック。
  - 登録項目: ＩＰアドレス(必須、ワイルドカード※やCIDR表記の範囲指定可) / 説明。
  - 変更: 一覧から対象IPをクリック→修正→「変更」。次回ログイン時から適用。
  - 削除: チェックボックス選択→「削除」→「OK」。全選択チェックで一括削除も可（複数行選択時は確認が2回）。
- **つまずきポイント/注意**:
  - IPが1件も未登録なら全IP許可。
  - 自分が使えないIPのみを登録すると次回以降ログイン不能になるので要注意。
- **用語**: CIDR表記=「192.168.0.0/24」のようなIP範囲指定記法。マイＩＰ=現在接続中のIPを自動入力する機能。

## 14.7. 赤伝・ゼロ伝
- **目的**: 注文データの荷量がマイナス（赤伝＝返品・訂正伝票）またはゼロ（ゼロ伝）の場合の取り込み挙動を制御する機能。
- **要点**:
  - 設定場所: 配車設定画面の「赤伝処理の設定」。設定後「変更」をクリックしてからデータ取り込みを実行。
  - 赤伝（マイナス荷量）の選択肢: (1)読み込まない、(2)コードが一致する注文から差し引く（同一注文コード内で相殺）、(3)同一顧客の注文から差し引く（同一顧客コード内で相殺）。
  - ゼロ伝（荷量0）の選択肢: (1)読み込まない（該当荷物レコードを削除）、(2)そのまま読み込む。
  - 取り込み時に処理内容のメッセージが表示される（例:「注文コード001 → 同一注文内の他の荷物レコードから差し引きました」）。
- **つまずきポイント/注意**:
  - 差し引ける荷物がない（赤伝より大きい荷量の荷物がない）場合、赤伝データは無視される。
  - 赤伝は複数の荷物から分割して差し引くことはできない（警告）。
- **用語**: 赤伝=荷量マイナスの伝票（返品・訂正）。ゼロ伝=荷量0の伝票。

## 14.8. 最適デポ選択
- **目的**: 出荷元候補が複数あるとき、注文ごとに「デポ」と「代替デポ」の中から最適なデポを自動選択してルート作成する機能。
- **要点**:
  - 「代替デポ」に候補デポを設定すると有効になる。
  - 手動登録: 注文登録画面の「代替デポ」で候補を選択。
  - データ取り込み: マッチング画面で候補デポ列に「代替デポ」をマッチングさせて取り込む。
- **つまずきポイント/注意**:
  - 自動配車時に考慮される条件は必ず親デポ（項目「デポ」）の設定。ただし違反表示は実際に割り当てられたデポの条件に対して出る（警告）。
  - シミュレーション版で使う場合、項目名は「デポコード2」「デポコード3」…と記載する。
- **用語**: デポ=出荷・集荷拠点。代替デポ=親デポの代わりに選択され得る候補拠点。

## 14.9. 車両日付
- **目的**: 日付ごとの車両の使用可否を一括で取り込む機能。車両のシフト管理として利用可能。
- **要点**:
  - 取り込み形式は2種類:
    1. カレンダー形式: ○の日付=「使用」チェックON、×=OFFで取り込み。記号は任意に指定可能。
    2. 車両一覧形式: 「使用」列が1=チェックON、0=OFF。
- **つまずきポイント/注意**: 一度に取り込めるのは40日分まで（警告）。
- **用語**: 使用=当日その車両を配車対象にするフラグ。

## 14.10. 実績からの学習
- **目的**: ドライバーオプション利用者向け。発着管理の実績データから移動時間・荷積み/荷卸し時間を学習し、自動配車の精度を高める機能。補正係数で反映度合いを調整できる。
- **要点**:
  - 前提: 発着管理(14.4)の実績が蓄積されていること。
  - 学習の実行手順:
    1. 各種設定→「実績からの学習設定」。
    2. 「学習の実行」をクリック。
    3. 学習対象を選択: 「移動時間」（所在地間の移動時間）/「荷積み・荷卸し時間」（所在地の滞在時間）/「荷積み・荷卸し時間(区間)」（時間表の荷サイズ区間を設定）。
    4. 処理には時間を要し、完了で「学習が完了しました」メッセージ。
  - 学習設定項目（「変更」で保存）:
    - 移動時間: 学習設定(使用ON/OFF) / 補正係数(0～1、1=学習結果と等しく、0=反映なし)。
    - 荷積み・荷卸し時間表(区間): 区間の最大数。
    - 荷積み・荷卸し時間: 学習設定 / データ種別（「滞在時間」=到着から出発まで、「荷役時間・待ち時間」=積み降ろし開始～終了＋差分。荷役の開始終了時刻まで実績登録しているかで選択）/ 補正係数(0以上、待ち時間の考慮度、0=考慮しない)。
  - 確認: データ取り込みで計画作成→自動配車→ガントチャートモードで補正結果を確認。
  - マスタ変更時の再学習: 訪問先の緯度経度変更後は「移動時間」の学習結果を、荷サイズ区間変更後は「荷積み・荷卸し時間」の学習結果を、それぞれ「削除」→「学習の実行」で再学習する。
- **つまずきポイント/注意**:
  - 実績がない、または既に学習済みの場合は対象データなしで学習されない。
  - 「区間」学習を実行すると車型の荷積み・荷卸し時間表の区間が書き換わり、「荷積時間(分)」「荷卸時間(分)」が0になる。「荷積み・荷卸し時間」学習を使うなら0のままでよいが、使わないなら各区間の時間を手動設定する必要あり。
  - 学習後に緯度経度や区間を変更すると学習結果が不正になる → 削除して再学習必須。
- **用語**: 滞在時間=到着から出発まで。荷役時間=積み降ろしの開始から終了まで。待ち時間=滞在時間−荷役時間。補正係数=学習結果の反映度。

## 14.11. セット配送
- **目的**: 一緒に集配したい複数注文に同一「セット名」を付け、なるべく同一車両に割り当てさせる機能。
- **要点**:
  - 計画作成方法の設定: 配車設定画面「自動配車による計画作成方法の設定」で条件を設定。
    - グループ条件との関係: 「セット条件・グループ条件の両方を遵守」/「グループ条件が異なる注文は別セット扱い」/「グループ条件違反でもセット条件を遵守」。
    - 未配化: 「同じ回転で運べない場合セット全体を未配」/「同じ車両で運べない場合セット全体を未配」/「同一顧客同一車両をセット配送と同様に扱う」。
  - 注文への登録: 注文変更画面で「セット名称」「セット順」を入力、またはデータ取り込みのマッチング画面で列をマッチング。
    - セット名称: 一緒に配送したい注文への任意文言。
    - セット順: セット内の配送順。小さい数値から順に集配、0は順不指定（0以下は0扱い）。
- **つまずきポイント/注意**:
  - 一部の注文への設定を想定した機能。セット配送対象が多数だと有効に機能しない。
  - セット名を設定してもセットにならない場合は「重要度」を併用して優先配車を試す（警告）。
- **用語**: セット名称/セット順=セット定義項目。回転=1車両の1運行(ルート)単位。未配=どの車両にも割り当てない状態。グループ条件=注文をまとめる別の制約条件。

## 14.12. 協力会社DX
- **目的**: 協力会社（傭車先）への配送依頼と、日報の提出・確認をシステム上で完結させる機能群の目次章。
- **要点**: 14.12.1 はじめに / 14.12.2 ルートを割り振る / 14.12.3 日報入力・提出 / 14.12.4 日報管理 / 14.12.5 同時編集 / 14.12.6 協力会社管理者でのログイン表示。
- **つまずきポイント/注意**: 特になし（目次のみ）。
- **用語**: 協力会社DX=下請け運送会社との受発注・日報業務のデジタル化。

## 14.12.1. はじめに（協力会社DXの初期設定）
- **目的**: 協力会社・契約・協力会社管理者ユーザー・見積り提出先の初期登録を行う。
- **要点**:
  - 協力会社の登録:
    1. システム設定→「協力会社管理」→「協力会社登録」。
    2. 項目を入力: コード(必須)、業者コード(必須)、名称(必須)、住所(必須)、担当者、電話番号(必須)、メールアドレス(必須)、適格請求書発行事業者番号(T+13桁)。
  - 契約の登録:
    1. 対象協力会社をクリック→協力会社変更画面→「契約情報一覧」→「契約登録」。
    2. 項目: コード(必須)、名称(必須)、スポット対応、代金支払期日、計画カテゴリー（チェックしたカテゴリーのみ計画に反映。「全ての計画カテゴリーを対象とする」で新規カテゴリーも対象）、日報カスタム項目（日報に表示する自由入力項目）。
  - 協力会社管理者の登録: 通常のユーザー登録と同様。「権限設定」で協力会社管理者を選ぶと「協力会社」欄が表示されるので該当会社を選択。
  - 見積り提出先の登録: システム設定→「計画カテゴリー」→「協力会社連携の設定」→「提出先」を入力し「登録」。
- **つまずきポイント/注意**:
  - 計画内の協力会社・契約は参照のみ。協力会社管理から削除しても計画には反映されず残り続ける（警告）。
  - 協力会社管理者はユーザー一覧に表示されない。確認はユーザーデータ出力Excel、削除はユーザーデータ取り込みで行う（警告）。
- **用語**: 適格請求書発行事業者番号=インボイス番号(T+13桁)。スポット対応=単発・短期契約。日報カスタム項目=契約単位で日報に追加する自由項目。

## 14.12.2. ルートを割り振る
- **目的**: 配車済み計画のルートを自社または協力会社に割り振り、発注～受注～ドライバー決定までのステータスを管理する。
- **要点**:
  - 基本操作: 配車済み計画を開く→ルートのメニュー→「ルート：協力会社情報の入力」→会社情報を入力。ステータスと権限によって表示・操作可能項目が変わる。
  - 一覧表示: 協力会社/助手/契約/ステータス/特記事項/実運送会社/請負階層/実車番号/(協)ドライバー名/電話番号/助手名 を一覧に表示可能（一覧表示項目の設定）。
  - 通常契約のステータス遷移: 調整中 → 発注 → 受注（または非承諾）→ ドライバー決定。
    1. 調整中（管理者/配車担当）: 協力会社(必須、自社も選択可)、契約(必須)、助手(必須)、特記事項(2000文字まで)を入力し「発注」。
    2. 発注（協力会社管理者）: ルートが協力会社側に表示。内容確認し「受注」または「非承諾」。
    3. 受注（協力会社管理者）: 請負階層(1次請け自動、5次請けまで)、実運送会社(自動)、実車番号、(協)ドライバー名、電話番号、助手名（助手ありなら必須）を入力し「確定」（途中なら「一時保存」）→ドライバー決定。
    4. ドライバー決定: 日報入力へ進める。
  - スポット契約の見積りフロー: 調整中 → 見積り依頼中 → 見積り中 → 見積り提出 → 受注（各段階で非承諾あり）。
    1. 調整中: スポット契約選択で「見積り依頼」ボタン表示→クリック。
    2. 見積り依頼中（協力会社管理者）: 「見積り依頼 承諾/非承諾」→承諾で見積り中に。
    3. 見積り中（協力会社管理者）: 会社名・住所・電話番号（自動）、適格請求書発行事業者番号、提出先、有効期限(必須)、見積金額（「運賃」～「附帯業務料」固定+最大10項目）、支払い方法(必須)、支払手数料の負担（初期値「運送委託事業者(支払い側)が負担する」）、支払い期日（契約の代金支払期日が自動）、遅延利息の利率（初期値14.6）、備考等を入力し「提出」。
    4. 見積り提出（管理者/配車担当）: 「見積り」ボタンで内容確認→「見積り 承諾/非承諾」。承諾で受注、「発注情報」ボタンで発注内容を参照可能。
  - 自社配送の場合: 協力会社=自社、請負階層=自社（自動）、実車番号・ドライバー名・電話番号等を入力し「確定」→ドライバー決定。
- **つまずきポイント/注意**: 日報提出後は「業務情報」の入力ができなくなる（協力会社割り振り・自社配送とも）。操作前に現在のステータスを確認すること。
- **用語**: 請負階層=何次請けか(自社～5次請け)。実運送会社=実際に運ぶ会社。スポット契約=単発/短期業務の契約。傭車=外部委託車両。

## 14.12.3. 日報入力・提出
- **目的**: ドライバー決定後のルートについて日報を入力・提出し、確認→承認のワークフローで管理する。
- **要点**:
  - ステータス遷移: 日報提出 → 日報確認 → 日報承認（各段階で差し戻し/非承認あり）。
  - 日報の項目: 報告担当者(自動)、請負階層・実運送会社・実車番号・(協)ドライバー名（協力会社情報から自動反映）、開始終了時間(ルートから自動)、休憩時間、開始終了メーター(必須)、実費料金（合計自動計算）、自由記入欄(2000文字)、ファイル、契約ごとの報告内容（カスタム項目）。
  - 提出は「提出」、途中は「一時保存」。初回提出で日報番号が付与され日報管理で確認可能。
  - 日報提出（管理者/配車担当）: 「確認」（確認者を入力）または「差し戻し」。
  - 日報確認（管理者/配車担当）: 「承認」（承認者を入力）または「非承認」。
  - 日報差し戻し: 修正して再提出可能（協力会社管理者も再提出可）。
  - 日報非承認: 再提出させるには「非承認」後に再度「差し戻し」をクリックする。
  - 計画の削除制限: 計画カテゴリー変更画面→「配車計画一覧の設定」→「配車計画の削除制限」を選択して「登録」。選択肢: 「なし」/「日報提出済みの計画を含む場合に警告する」（削除するか維持するか選択ダイアログ）/「日報提出済みの計画をスキップする」（提出済みルートを含む計画は削除されない）。
  - ファイルアップロード: 「ファイルを選択」→アップロード→クリックで拡大表示、ファイル名クリックで詳細（ダウンロード/表示/削除）。
- **つまずきポイント/注意**:
  - 協力会社に発注したルートの日報が提出されると、管理者側でその日報は変更不可。
  - 添付制限: 1日報5ファイル（変更は要問い合わせ）、1ファイル10MBまで、画像(jpg/jpeg/png/gif/heic)とPDFのみ。heicはjpg変換されプロパティ情報（作成日時等）は引き継がれない。ファイル名は50文字まで・使用可能文字に制限あり。
- **用語**: 日報番号=初回提出時に付与される識別番号。開始終了メーター=走行距離計の値。

## 14.12.4. 日報管理
- **目的**: 提出済み日報を横断的に検索・確認し、ステータス変更（確認・承認・差し戻し）を行う管理画面。
- **要点**:
  - 表示手順:
    1. システム設定→「日報管理」。
    2. 初期表示は0件。「計画の日付」を設定し「この条件で検索」で一覧表示。
  - ステータス変更: 日報データをクリック→「日報登録・確認」画面→「確認」→担当者氏名入力→「OK」。
  - 一括差し戻し（差し戻し用連携ファイルが別途必要・要問い合わせ）:
    1. 「一括差し戻し」をクリック。
    2. ファイル/対象シート/列名として扱う行 を設定し「ファイル読み込み」。
    3. 処理（「差し戻し」=対象ステータスは日報提出・日報確認・日報非承認、「非承認」=対象は日報承認）、日報番号列、差し戻し理由列、担当者氏名を入力し「確認」。
    4. 差し戻し確認画面で対象を確認し「実行」。
- **つまずきポイント/注意**: 日報管理で変更したステータスは表示中の他画面へ即時反映されない。画面再表示で反映される。
- **用語**: 一括差し戻し=連携ファイルによる複数日報の一括ステータス変更。

## 14.12.5. 協力会社情報・日報の同時編集
- **目的**: 同じ協力会社情報/日報を2人が同時編集した際の競合を検知し、上書き事故を防ぐ仕組み。
- **要点**:
  - 画面を開いてからボタンをクリックするまでの間にマスタに変更があった場合を競合と判定。
  - 2人目のクリック時に競合メッセージを表示。「更新を確認」で1人目の編集内容を表示（確認するまでボタンはクリック不可）。ステータスに変更がある場合は赤字表示。
  - 「閉じる」で自分の編集画面に戻り、以降ボタンをクリックできるようになる。
- **つまずきポイント/注意**: 競合時は1人目の内容を確認しない限り保存操作ができない。
- **用語**: 競合=同一データへの同時編集の衝突。

## 14.12.6. 協力会社管理者でログインしたときの表示
- **目的**: 協力会社管理者権限でログインした場合の操作範囲の説明。
- **要点**: 操作可能なのは計画の参照、「ルート：協力会社情報の入力」「ルート：日報の登録」のみ。
- **つまずきポイント/注意**: 協力会社管理者は自社に発注されたルートが存在する計画のみ参照可能（警告）。
- **用語**: 協力会社管理者=協力会社側のログインユーザー権限。
