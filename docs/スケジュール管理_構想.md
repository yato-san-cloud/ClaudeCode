# スケジュール管理の再設計 — 「正はデータ1表、ガントは自動生成」構想

作成: 2026-07-17 / 対象: ローソン立上げ以降のスケジュール管理全般
検討材料: 過去資料 6 本（ウェルシア立上げ 189行・FFL稼働 197行×6シート・移管・支援者・レイアウト変更）

## 1. 現状分析 — 「スケジュール」は実は 3 種類ある

| 型 | 実例 | 構造 | 更新頻度 |
|---|---|---|---|
| **WBS型** | ウェルシア/FFL立上げ、レイアウト変更 | 大中小項目の階層＋正副担当＋週次セル手塗り(□■☆) | 週次（定例会） |
| **リソース型** | FFL支援者スケジュール | チーム×日付に「人」を割り当て（時間帯・車両・作業内容） | 日次〜週次 |
| **数量型** | DPL移管スケジュール | 倉庫×荷姿×頻度ごとの日別パレット数量 | 日次（移管期間中） |

### 過去資料から見えた手作業の痛点

1. **セル手塗り**: □■☆を1個ずつ塗る。日程が1週ずれると数十セルを塗り直し
2. **版の乱立**: 「0809_修」「定例会後」「(※メンテ中)」…。FFL のブックには過去版シートが 4 枚同居し、どれが正か開くまで分からない
3. **変更履歴が手書き**: FFL には「計画変更履歴」シートを人手で書いていた形跡（21行）
4. **集計不能**: 塗り絵からは「遅延は何件」「今週誰が何を」を抽出できない。目視で数える
5. **共有＝ファイル送付**: 定例会後にメール添付。相手が最新版を見ている保証がない

## 2. 方針 — schedule-as-data（gen_knowledge.py と同じ思想）

**タスク表（CSV 1枚）だけを人が触り、ガント・共有用・エージェント用は全部スクリプトが描く。**

```
tasks.csv(正本・OneDrive同期フォルダ)          ←人が編集するのはここだけ
   │  python gen_schedule.py tasks.csv
   ├→ ①_ガント.xlsx   現行様式の週次ガント(□■☆◆)。定例会・印刷用。見た目は今のまま
   ├→ ②_ガント.html   ブラウザで開くガント。担当フィルタ・今日線・遅延赤枠。Teams共有用
   ├→ ③スケジュール_最新.md  遅延/今週/マイルストーン要約 → SharePoint → エージェントの根拠
   └→ ④変更履歴.md    前回実行とのdiffを自動追記(手書きの計画変更履歴シートの代替)
```

- 日程変更 = CSV の日付を直す（1セル）→ 再実行3秒。塗り直しゼロ
- 版管理 = 正本1ファイル＋変更履歴が自動で残る。「どれが最新?」が消滅
- **プロトタイプ実装済み**: `tools/gen_schedule/`（サンプル＝FFLの大日程をローソン仮日程で再構成した18タスクで動作検証済み。遅延検知・diff・◆描画まで確認）

## 3. なぜ市販ツールでないか（検討済み・順に棄却）

| 選択肢 | 棄却理由 |
|---|---|
| Microsoft Planner（基本） | ガント・階層・依存が無い。M365 に入っているが立上げWBS には力不足 |
| Planner Premium / Project | ライセンス申請＋課金＝全体設計でいう T2/T3 ゾーン。「脳死却下」リスクの的 |
| kintone ガントプラグイン | ドメインが本社管理でプラグイン導入不可の公算大（連携コネクタと同じ壁） |
| 外部 SaaS（Asana 等） | 新規調達＋社外データ持ち出し。情シス案件化して止まる |
| **Excel を出力に格下げ（本案）** | **新規調達ゼロ。定例会文化（Excel/印刷）はそのまま。Python 資産と同じ保守モデル** |

判断の軸は全体設計 v0 §7 と同じ——「申請しない範囲で実績を作る」。本案は既存 PC の Python と OneDrive だけで完結する。

## 4. 運用フロー（週次・1回5分）

1. 定例会・現場報告を受けて `tasks.csv` を直す（状態変更・日程変更・行追加）
2. `gen_schedule.py` 実行（定時ジョブ化も可: 定時ジョブ設定手順.md に1行）
3. 出力先は OneDrive 同期済み SharePoint フォルダ → ①xlsx を定例会へ、②html を Teams タブに、③md はエージェントが自動参照
4. 変更履歴は④に自動追記済み——「先週から何が変わったか」を定例会の冒頭で読み上げられる

## 5. エージェント統合（CPA-006 スケジュール番・T1 で成立）

ナレッジ: `スケジュール_最新.md`（動的）＋ 標準WBSテンプレ（静的・下記）＋ 用語集（共有）

| できること | 使い方 |
|---|---|
| 照会 | 「今週の静東のタスクは?」「遅れてるのは?」→ モバイルから即答（部下・上司も使える） |
| 定例会メモ→変更指示の下書き | 議事メモを貼る→「S-06 完了 / S-09 1週間後ろ倒し」の CSV 修正リストを出す→人が反映 |
| 新規スケジュールの分解ドラフト | 「◯◯立上げ、12月稼働、規模…」→ 標準WBSテンプレを土台に tasks.csv ドラフト生成 |

**標準WBSテンプレ**: ウェルシア(2017)と FFL(2021)の 2 案件から共通工程を抽出した「立上げの型」
（0.大日程 → 1.作業設計 → 2.準備 → 3.教育・移管 の 4 フェーズ、正副担当の部署パターン込み）。
これがあると次の立上げの初期計画が「ゼロから考える」から「型を当てて差分を埋める」に変わる。
