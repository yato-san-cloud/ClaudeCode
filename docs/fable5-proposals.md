# Fable 5 でやるべきことの提案

> 作成日: 2026-07-09
> 対象モデル: `claude-fable-5`（Claude 5 ファミリー）

## 1. Fable 5 とは何か

Fable 5 は Claude 5 ファミリーのモデルの 1 つで、Opus 4.8 / Haiku 4.5 と並ぶ最新世代にあたります。「Fable（寓話）」という名前が示す通り、**物語・創作・世界観構築・長文の一貫性**に強みを持つモデルと位置づけられます。

そのため、コード生成や厳密な推論を主眼とする Opus 系とは異なり、**「人が読んで面白い・自然・没入できる」テキストを大量かつ一貫して生み出すタスク**で最大の価値を発揮します。以下では、その特性を活かした「やるべきこと」を優先度つきで提案します。

---

## 2. 提案タスク一覧（優先度順）

### 優先度: 高

#### 2.1 インタラクティブ・ストーリーエンジンの試作
- **内容**: 分岐する物語（ゲームブック/ノベルゲーム）を Fable 5 で駆動する最小構成のエンジンを作る。
- **なぜ Fable 5 か**: 長い物語の一貫性（キャラクター設定・伏線・世界観）を保ちながら分岐を生成する能力が核心。
- **成果物**: プロンプト設計 + 状態管理（キャラ・所持品・フラグ）の JSON スキーマ + サンプル 1 章。
- **評価指標**: 5 分岐先でも設定矛盾が起きない一貫性、読者の没入度。

#### 2.2 キャラクター・ペルソナ駆動の対話ボット
- **内容**: 明確な性格・口調・背景を持つキャラクターとの対話システム。
- **なぜ Fable 5 か**: ペルソナの声（voice）を崩さずに長い会話を続ける能力が期待できる。
- **成果物**: ペルソナ定義テンプレート + ガードレール（キャラ崩壊・脱線防止）+ 評価用会話ログ。

#### 2.3 モデル特性のベンチマーク整備
- **内容**: Fable 5 vs Opus 4.8 vs Haiku 4.5 を「創作」「一貫性」「指示追従」「コスト/レイテンシ」で比較する評価セット。
- **なぜ最初にやるか**: 以降の全提案で「どのタスクにどのモデルを割り当てるか」の判断材料になる。
- **成果物**: 評価プロンプト集 + 採点ルーブリック + 比較レポート。

### 優先度: 中

#### 2.4 長文コンテンツの下書き→推敲パイプライン
- **内容**: Fable 5 で初稿を大量生成し、別モデル（Opus 系）で事実確認・構成チェックを行う二段構え。
- **なぜ Fable 5 か**: 「量とドラフト品質」を Fable、「厳密さ」を Opus に分担させる役割分担が合理的。
- **成果物**: パイプライン設計図 + 各段のプロンプト + 品質ゲート定義。

#### 2.5 世界観・設定資料（World Bible）の自動生成と整合管理
- **内容**: 地名・年表・勢力・用語集などの設定資料を生成し、相互矛盾を検出・修正する。
- **成果物**: 設定データのスキーマ + 整合性チェックのルール + サンプル世界観。

#### 2.6 教育・研修用のシナリオ生成
- **内容**: ロールプレイ研修、語学学習の会話シナリオ、ケーススタディなどを生成。
- **なぜ Fable 5 か**: 現実味のある登場人物と状況を作る力が学習効果に直結する。

### 優先度: 低（探索的）

#### 2.7 マルチキャラクターの群像シミュレーション
- 複数のペルソナ・エージェントを同時に動かし、相互作用する物語/議論を生成。

#### 2.8 トーン&スタイル変換ツール
- 同一内容を「フォーマル / カジュアル / 童話調 / 技術文書」などに変換するユーティリティ。

## 3. 共通で先に整えるべき土台

どの提案を選ぶ場合でも、以下を先に用意すると立ち上がりが速くなります。

1. **プロンプト/評価のリポジトリ構造** … `prompts/`, `evals/`, `schemas/` などの雛形。
2. **モデル呼び出しの薄いラッパー** … `claude-fable-5` を含むモデル切替を 1 箇所で管理。
3. **一貫性チェックの仕組み** … 設定矛盾・キャラ崩壊を検出する軽量な検証（LLM-as-judge など）。
4. **コスト/レイテンシの計測** … 創作は長文になりがちなので、トークン消費の可視化を最初から。

---

## 4. 推奨する進め方

1. まず **2.3 ベンチマーク整備**で Fable 5 の得手・不得手を数値で把握する。
2. その結果をもとに **2.1 または 2.2** のどちらかを PoC として実装する。
3. PoC で得た知見を **共通土台（第 3 章）**に還元し、以降のタスクを高速化する。
