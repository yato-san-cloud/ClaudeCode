# 業務マップ(STEP 1)— 八峠さんの業務構造分析

- 作成: 2026-07-16
- 根拠: Google Drive「ローソン提案」プロジェクトフォルダの実ファイル群(MOC.md、議事録、審議回答、収支エンジン、調査シート等)からの逆算
- 位置づけ: 業務OS(横断基盤)整備の土台。案件固有の内容は例示であり、構造は次案件でも再利用可能

## 1. 業務の全体像

物流拠点プロジェクト(現在: ローソン袋井サテライト2拠点化)の**企画・提案・要件定義・社内審議・顧客/IT部門交渉を一人で統括**する仕事。
実態は「**会議・調査で得た情報を、正確な数字と根拠付きで、相手別の文書に変換し続ける**」仕事であり、文書変換パイプラインの品質と速度が業務全体の速度を決めている。

```
[入力]                      [処理]                        [出力]
会議(Web/対面)の文字起こし → 論点抽出・決定/宿題分類     → 議事録(md→docx正本)
Excel一次データ(収支/実績)  → 数字トレース・検算・根拠整理 → 審議回答md+数字1枚HTML
WMSソース/SQL調査結果       → 裏取り・タスク分解          → 論点対応表・要件定義書
現場の疑問・確認事項        → 調査設計                    → 調査シートHTML(篁さん向け)
過去セッションの成果物      → 文脈の再構築                → 引継ぎ書(HANDOFF)
```

## 3. 人間がやるべき判断 vs AIに任せられる作業

### 人間(八峠さん)にしかできない判断
- 営業判断(議事録から何を削るか、表現をどうマイルドにするか)
- 交渉のカードを切る順番、相手の人物評に基づく戦術
- 正本の確定(md→docx昇格の判断)、顧客送付のGOサイン
- ファイル・フォルダの削除実行
- 数字の最終責任(検算結果の採否)

### AIに任せられる(型化して委譲すべき)作業
- 文字起こし→議事録ドラフト(論点抽出・分類・L番号引用)
- 数字の出典セル特定・検算・ブリッジ表作成
- 版チェーン(v1→v2→v3)の差分整理と「最新はどれか」の管理
- MOCへのリンク追記案・リンク切れ検出
- 調査依頼書・引継ぎ書の構造化(型に流し込む)
- 命名規則への適合チェック

### 分界線の原則
**「AIはドラフトと検算まで、人間は削る・送る・消すの3つ」**。この分界を各Skillに明記する。

## 4. 特定した最大のボトルネック(優先順)

1. **版管理・数字整合の維持**(本人申告+ファイル群の証跡が一致)
   - 症状: v0〜v3+Rev9〜11+（参考、最新はvX）注記が人力。様式-08に「地雷5件」が実在した(手打ち/外部リンク切れ等)
   - 5年収支エンジンで計算側は解決済み。**残るのは「文書側の整合」と「どれが正本か」の管理**
2. **議事録パイプライン**(本人申告+高頻度)
   - 症状: 文字起こし→md→docx→加筆→v3 の工程が毎回手組み。ただし0629議事録で**完成形フォーマットは確立済み**→即Skill化可能
3. **セッション間の文脈引継ぎ**(証跡: HANDOFF文書を都度手書き、申し送りmd多数)
4. **MOC・フォルダの手動運用**(証跡: リンク切れ修正履歴、棚卸しを単発実施)
