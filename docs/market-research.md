## 2. 機能パターン対応表（市販 vs 本ツール群）

| 市販の機能パターン | 本ツール群での扱い |
|---|---|
| ステップ構造化・画像への丸/矢印/文字 | ✅ 実装済み（index.html。モザイク・スポットライトは未対応） |
| テンプレートからの半自動作成 | ✅ **今回実装**（planner.html：作業タイプ別テンプレート→構成・フロー・撮影指示を生成） |
| AIによる自動生成 | ⭕ 部分対応：planner.htmlが「AI用プロンプト」を生成し、Copilot/社内LLMに貼ると指示書が返り、そのままツールに取り込める（オフライン原則を守りつつAIを外付け） |
| 承認ワークフロー・改訂履歴 | ⭕ 簡易版実装済み（承認前チェック7項目・品質スコア・版数・状態管理）。多段承認は台帳（Kintone/Teams）側で |
| 閲覧レポート・理解度テスト | ❌ 未対応（台帳KPI＋点検記録コピーで一部代替） |
| 動画マニュアル・自動字幕 | ❌ 対象外（設計判断：オフライン単一ファイルと両立しない） |
| 多言語翻訳 | ❌ 未対応（Phase 4候補） |
| スキルマップ | ❌ 未対応（教育・引継ぎメモが個票レベルの代替） |

## 3. 本ツール群の立ち位置

- **費用ゼロ・アカウント不要・オフライン**：市販の月額3,000〜300,000円に対し、導入判断なしで今日から始められる
- **様式固定**：承認欄つきA4様式・点検記録・現場モードを1ファイルに内蔵
- **自動化はRPA（キーエンスRK）と分業**：市販のクラウド管理機能の代わりに、既存資産のRK＋Kintone/Teamsで台帳・リマインド・KPIを回す（docs/rk-interface-spec.md）
- **AIは外付け**：ツール自体はAI非搭載のまま、プロンプト生成→指示書取り込みの契約でAIの恩恵だけ取り込む

## 4. 市販ツールへ乗り換え（併用）を検討すべき条件

次のいずれかに達したら、無理に内製を伸ばさず市販導入を検討する：

1. **動画が主役になったとき**（微妙な手つき・音・速度が本質の技能伝承）→ tebiki系
2. **多言語の現場**（外国人材が主力で翻訳が常時必要）→ Teachme Biz / tebiki の自動翻訳
3. **閲覧・習熟の証跡が監査要件になったとき**（誰がいつ見たか、理解度テスト）
4. **運用中マニュアルが数百本規模**になり、検索・権限・フォルダ管理が台帳では回らないとき

その場合も、本ツールで蓄積したデータは全てJSON（`__manualdata`）で機械可読なので、移行コストは小さい。

## 5. 今回の実装への反映（planner.html）

市販調査から採用した3パターン：

1. **テンプレート起点の半自動作成**（Teachme のテンプレート機能に相当）→ 作業タイプ8種の雛形から構成・業務フロー・撮影指示を即生成
2. **「撮ってから作る」フロー**（tebiki の現場撮影ファースト思想）→ 撮影指示書（【撮影】ブロック）を先に渡し、写真が揃った時点でマニュアルの骨格が完成している状態を作る
3. **AI生成の外付け化**（Teachme のAI生成に相当）→ AI用プロンプトのワンタップコピー。返答は凍結契約（rk-interface-spec §7）でツールに還流
