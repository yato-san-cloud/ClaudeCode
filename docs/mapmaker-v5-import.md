# MapMaker カスタム版 v5.1β → whsim 取込 仕様・想定表

whsim 側の**取込**が MapMaker カスタム版（v4.4〜v5.1β）の出力をどう読むかの一覧。
実サンプルが手元に無い出力（3D/KPI JSON）については**想定したキー名**を全部ここに
書き出してある。**MapMaker 作者はこの表の「想定キー」と実際の出力を突き合わせて、
違うところだけ指摘すればよい**（コードを読む必要はない）。

- 書き出し側（whsim → MapMaker）は `docs/mapmaker-v5-export.md`（別担当）。
- 実装: `src/whsim/{mapmaker_kpi.py, locmaster.py, cad.py, rmpm.py}`、
  API は `src/whsim/web/routes/imports.py`、CLI は `src/whsim/cli.py`。
- 取込の流儀は `docs/ARCHITECTURE.md` §1 の不変条件どおり **寛容・never-blocks**:
  読めない行は落として件数を報告し、例外で止めない。

---

## 0. 段数の数え方（v4.9 統一規約 — whsim もこれに合わせる）

MapMaker v4.9 で「段数」の意味が全機能で統一された。whsim の容量計算はこれと
食い違ってはいけないので、取込コードの各所に同じ規約をコメントで明記している。

| 用語 | 定義 | whsim 側 |
|---|---|---|
| 段数 | **パレット段数（ロケ段数）**。什器マスタに値があればそのまま（天井高で勝手に切り下げない）。0 のときだけ天井有効高から自動算出 | `ShelfArea` → `Location.level` の段数 |
| ネス基数（逆ネス） | **基数 = 段数 − 1**（段数 = 基数 + 1） | KPI JSON が基数しか持たないときだけ `段数 = 基数 + 1` で復元 |
| 有効ロケ数 | **間口数 × 段数**（未使用指定を除く） | `len(model.locations)` |
| 収納力計算 (Ctrl+K) | 寸法からパレット数を推定する**別の数え方**（中量棚・軽量棚は棚板面積扱いでパレットに計上されない） | 取込では使わない。混同しないこと |

## 1. 3D/KPI用データ書き出し（JSON） → `whsim.mapmaker_kpi`

- API: `POST /api/projects/{name}/import-mapmaker-kpi`（`?probe=true` で**書き込まずに**キーの答え合わせだけ）
- CLI: `whsim import-kpi <project> <file.json>` / `whsim import-kpi ... --probe` / `whsim probe-kpi <file.json>`
- 単位 **mm**、原点 **左上**、**x右+ / y下+**（rmpm と同じ座標系）。取込時に mm→m、最小角を原点へ平行移動。
- `meta.unit` があればそれに従い、無ければ図面の広がり（>2000 なら mm）で判定。

### 1-1. トップレベルの入れ物（想定）

| 意味 | 想定キー（いずれか1つ当たれば可） |
|---|---|
| 棚の配列 | `shelves` / `shelf` / `racks` / `rack` / `fixtures` / `objects` / `items` / `locations` / `棚` / `什器` / `data` |
| 壁の配列 | `walls` / `wall` / `壁` |
| 検品場の配列 | `stations` / `station` / `検品場` / `検品台` / `ステーション` / `inspection` |
| 階段の配列 | `stairs` / `stair` / `階段` |
| コンベアの配列 | `conveyors` / `conveyor` / `コンベア` / `コンベヤ` / `belts` |
| 計算前提 | `meta` / `header` / `params` / `settings` / `計算前提` / `前提` / `倉庫パラメータ` |
| フロア | `floors` / `floor` / `フロア` |

- トップが**素の配列**のときは棚一覧とみなす。
- フロアが複数ある場合は**先頭フロアのみ**（whsim は現状単一フロア）取り込み、警告を出す。

### 1-2. 棚1件のフィールド（想定）

| 意味（説明書の表現） | 想定キー | whsim での使い道 |
|---|---|---|
| ロケ番号 | `loc` / `locNo` / `locationNo` / `location` / `locationCode` / `ロケ` / `ロケ番号` / `ロケーション` / `フルロケ` / `棚名` / `棚番号` / `shelfName` / `shelfId` / `rackName` / `name` / `code` | 棚名＝在庫・出荷履歴との**join キー**。無いと突合できない（警告） |
| 座標 X | `x` / `xmm` / `x_mm` / `left` / `posX` / `座標X` / `x1` | 棚矩形の**左上**（mm） |
| 座標 Y | `y` / `ymm` / `y_mm` / `top` / `posY` / `座標Y` / `y1` | 同上 |
| 中心座標 | `cx`/`cy` / `centerX`/`centerY` / `中心X`/`中心Y` | 左上が無いときだけ footprint の半分を引いて左上に直す |
| footprint 幅 | `w` / `width` / `wmm` / `幅` / `間口幅` / `sizeX` / `dx` / `footprintW` | 棚の幅（mm） |
| footprint 奥行 | `d` / `depth` / `奥行` / `奥行き` / `sizeY` / `dy` / `footprintD` | 棚の奥行（mm） |
| footprint（まとめ） | `footprint` / `フットプリント` / `設置面積` / `占有面積` | `{w,d}` / `[w,d]` の形も受ける |
| 概算全高 | `height` / `totalHeight` / `overallHeight` / `全高` / `概算全高` / `外寸高さ` / `topZ` | 3D の押し出し高さ（現状は記録のみ） |
| 段数 | `levels` / `level` / `tiers` / `stages` / `段数` / `段` / `パレット段数` / `ロケ段数` | **段数=パレット段数**（§0）。`Location.level` の上限 |
| ネス基数 | `nesBase` / `nestainerBase` / `ネス基数` / `基数` | 段数が無いときだけ `+1` して段数に |
| 間口数 | `faces` / `face` / `bays` / `bay` / `openings` / `間口` / `間口数` / `slots` | 段×間口で展開 |
| 有効ロケ数 | `usable` / `usableLocations` / `有効ロケ` / `有効ロケ数` / `effectiveSlots` | 間口数が無いとき `有効ロケ数 ÷ 段数` で間口数を逆算 |
| 什器種別（自動判定） | `gear` / `type` / `fixtureType` / `kind` / `category` / `rackType` / `什器種別` / `種別` / `設備種別` | whsim の `racktypes` id へ（§4 の対応表） |
| 什器名 | `gearName` / `fixtureName` / `equipmentName` / `什器名` / `設備名` / `什器` | 種別が空のときの手掛かり |
| パレット収納力 | `pallets` / `palletCapacity` / `palletCount` / `capacity` / `パレット収納力` / `収納力` / `収納パレット数` | 有効ロケへ**按分**（合計が図面の数字と一致する） |
| 棚板面積 | `boardArea` / `shelfArea` / `棚板面積` / `保管棚板面積` / `area` / `面積` / `m2` | 中量棚等の面積（記録のみ） |
| ゾーン（棚グループ） | `zone` / `group` / `groupName` / `ゾーン` / `棚グループ` / `グループ` | `Location.zone` へ |

**要確認（曖昧なので想定を置いた点）**

1. `h` の意味は**文脈で切り替えている**: 同じレコードに `d`/`depth`/`奥行` が無ければ
   `h` は footprint の奥行（rmpm 流の `w,h` 矩形）、あれば全高。
2. 座標は**棚矩形の左上**と仮定（rmpm の `tl` と同じ）。中心なら `cx/cy` で書いてもらえれば自動で直る。
3. 「面積」は m²、座標・寸法は mm と仮定。

### 1-3. 壁 / 検品場 / 階段 / コンベア

| 対象 | 読むもの | whsim での扱い |
|---|---|---|
| 壁 | `x,y,w,d`（矩形）＋ `height`/`高さ`/`壁高` | 長辺の中心線＋厚みの `Wall` |
| 検品場 | `x,y,w,d` または `cx,cy` ＋ 名前 | `resources.stations[]`（中心座標） |
| 階段 | — | **見送り**（件数を警告で報告。whsim は単一フロア） |
| コンベア | `points`/`nodes`/`vertices`/`path`/`ポイント`（`[[x,y],…]` / `[{x,y},…]` / `[x1,y1,x2,y2,…]`）＋ `speed`/`速度` | `resources.conveyors[]`。速度が無ければ 0.5 m/s |

### 1-4. 計算前提（meta）

`unit`/`単位`, `ceiling`/`天井有効高`, `palletW`/`パレット幅`, `palletD`, `palletH`/`荷姿高`,
`version`, `profile`/`出力プロファイル` を拾って `stats.meta` に残す（数字が独り歩きしないように）。

### 1-5. probe（答え合わせ機能）

```
whsim probe-kpi 出力.json
# または  POST /api/projects/{name}/import-mapmaker-kpi?probe=true
```

返るもの:

- `matched`: 意味 → **実際に当たったキー名**（例 `{"name": "loc", "levels": "段数"}`）
- `unknown`: **別名表のどこにも載っていないキー**の一覧（`key` / 出現回数 / サンプル値）。
  ある棚が `loc` と書いていても検品場の `name` は「未知」にならない（別名表全体で判定するため）
- `keys_seen`: 出てきた全キーの出現回数

`unknown` に載ったキーが「意味のあるデータ」なら、その意味を教えてもらえれば
`FIELD_ALIASES` に1行足すだけで拾えるようになる。色・資産情報など whsim が
意図的に使わないキーは `_IGNORED` に入れてあるので `unknown` には出ない。

## 2. ロケーションマスタ Excel出力（CSV） → `whsim.locmaster`

MapMaker の出力列（v4.10 で末尾に「ゾーン」列が追加。**既存列の位置は不変**）:

```
エリア,列,棚,段,間口,フルロケ,X,Y,什器種別,什器名,面積[,ゾーン]
```

| 列 | 想定列名（別名） | whsim での使い道 |
|---|---|---|
| エリア | `エリア` / `area` | フルロケが無いときの住所組み立て |
| 列 | `列` / `通路` / `aisle` / `col` | 同上 |
| 棚 | `棚` / `連` / `bay` | 同上 |
| 段 | `段` / `level` / `tier` | 異なり数＝**段数**（§0） |
| 間口 | `間口` / `face` / `slot` | 異なり数＝間口数 |
| フルロケ | `フルロケ` / `ロケーション` / `ロケ` / `location` / `loc` | 棚キー（先頭3節に正規化・2桁ゼロ詰め） |
| X / Y | `X` / `x_mm` / `xmm`（Y も同様） | **mm**。直接配置経路の座標 |
| 什器種別 | `什器種別` / `什器` / `設備種別` / `rackType` | `racktypes` id（§4） |
| 什器名 | `什器名` / `設備名` / `gearName` | 参考値 |
| 面積 | `面積` / `footprint_m2` / `area_m2` / `m2` | **m²**。直接配置で幅を出すのに使う |
| ゾーン | `ゾーン` / `zone` / `棚グループ` / `グループ` | `Location.zone`（WMS のゾーン別ピッキング／搬送区分） |

**列名の衝突対策**: 「面積」と「ゾーン」は部分一致で「エリア(area)」に食われるため、
この2列を**先に**確定してから残りを解決している（`_pick(..., used=…)`）。

### 2-1. 2つの配置経路

| 経路 | 使うとき | 座標の出どころ |
|---|---|---|
| `place=drawing`（既定） | 図面（rmpm/CAD/KPI）を先に取り込んである | **図面の棚**。マスタの X/Y は使わない（3D の棚は図面から生えるので、数 cm ずれるだけで在庫が棚の脇に浮く） |
| `place=direct` | **CSV しか無い** | マスタの **X/Y（mm）**。`locmaster.build_layout()` |

`place=direct` の想定（**要確認**）:

- **X/Y は棚の中心**と仮定（`coord="center"`。左上なら `coord="topleft"`）。
  マスタの1行は「スロット」を指し、スロットの代表点は普通その中央、という理由。
- 奥行は什器プリセットの値、幅は `面積 ÷ 奥行`（面積が無ければ `間口数 × 間口幅`）。
- 向きは分からないので **+x 方向に伸びる（間口は下向き）** として置く。設計タブで回せる。

## 3. CAD(DXF)エクスポート → `whsim.cad`

MapMaker はレイヤで仕分けて出す。whsim のレイヤ解釈（部分一致・大小文字問わず）:

| レイヤ名に含まれる語 | whsim での扱い | 備考 |
|---|---|---|
| `CONVEYOR` / `コンベア` / `コンベヤ` | **`resources.conveyors[]`**（ポリライン＝ベルト中心線） | **壁にはしない**。v4.10 がベルト足元に自動生成する「壁」と同じ物体なので、両方に入れると同じ場所に障害物が2つできる（説明書の「二重計上しません」と同じ考え） |
| `SHELF` / `棚` | **保管ゾーンの棚（`zone.shelves`）** | 壁にはしない。棚は経路の障害物として `zone.shelves` から直読される。**棚名は付かない**（DXF では棚名は別の TEXT なので、名前が要るなら rmpm / ロケマスタ経路が正） |
| それ以外（`WALL` 等） | `layout.walls[]`（従来どおり） | 未知のレイヤも壁になる＝顧客の任意の図面がそのまま使える |
| `RECEIVING`/`入荷`, `SHIPPING`/`出荷`, `PACKING`/`梱包`, `PICKING`, `STORAGE`/`保管` | 閉じたポリラインならゾーン矩形 | 従来どおり |

- 速度は DXF に載らないので **0.5 m/s** を既定で入れる（設計タブで変更可）。
- 単位は `$INSUNITS`（無ければ広がりから mm/m を推定）。

## 5. rmpm（ネイティブ保存形式）

### 5-1. v4.4+ の末尾埋め込み＝**正常系**として静かに扱う

v4.4 以降、什器マスタ・割当・グループ・資産情報（v4.9 以降はコンベアも）は
**rmpm ファイルの末尾に追記**される。旧 MapMaker がそれを読み飛ばして開けるための
設計であり、壊れているわけではない。

- 以前: javaobj が `Warning!!!!: Stream still has N bytes left` をエラーログに出していた（破損に見える）。
- 現在: そのログを抑止し、**自分で残りバイト数を測って**警告文を出す:
  「MapMaker カスタム版の拡張データ N bytes をスキップしました（v4.4+ が rmpm 末尾に
  埋め込む什器マスタ・割当・資産情報等。図面本体の読込には影響しません）。」
- `stats.custom_trailer_bytes` に N が入る。
- 本当に壊れたストリームは従来どおり友好的な `ValueError` で落とす。

### 5-2. 「コンベア足元の自動生成壁」は rmpm からは識別**できない**（調査結果）

`reference/mapmaker/decompiled/.../model/map/objects/WallObject.java` を確認した結果、
壁が持つフィールドは次で全部:

```
WallObject              : height_mm (double)
AbstractRectangleObject : tl, br (Coord)
AbstractObject          : id (Integer), editLock (boolean)
```

**名前フィールドが無い**（`toString()` は定数 `"壁"` を返すだけ。`StairsObject` の
`name` にも `FreeShelfObject` の `shelf.name` にも相当するものが無い）。したがって
v4.10 がコンベア足元に自動生成した壁を、**手で描いた壁と区別する手段が rmpm 上に
存在しない**。説明書が言う「生成物は元アプリの壁クラスそのもの（旧 MapMaker でも
普通に開ける）」という設計要件そのものが、印を付けられない理由になっている
（印を付ければ旧版で開けなくなる）。

唯一の追加情報は `height_mm`（プロパティ P で指定するベルト高）だが、手描きの壁にも
入る値なので判定には使えない。残る手は v4.4+ の末尾埋め込み（コンベアの実体データは
そこにある）を解くことだが、形式は非公開でサンプルも無い。

→ **DXF の CONVEYOR レイヤ経路を正とする**（§3）。rmpm 側では:

- 壁はそのまま壁として取り込む（`conveyor_footprint` の印は**付けない** = 嘘をつかない）。
- `height_mm` を `walls[].height_m` として素通しし、
- 高さ 1.2 m 以下の壁があれば件数と一緒に「コンベアかもしれないので DXF の
  CONVEYOR レイヤを取り込んでください」と**助言だけ**する（断定しない）。

**MapMaker 側で1つだけ足せるなら**: 自動生成した壁に何らかの識別（例えば
`WallObject` のサブクラス、または末尾埋め込みに「この壁 id はコンベア由来」という
対応表）を持たせてもらえれば、rmpm 単体でコンベアを復元できるようになる。

### 5-3. **名前規約の解釈**（オブジェクト名に書かれた意味を読む）

rmpm には **z 座標が無く**、置ける種別も `WallObject` / `FreeShelfObject` /
`StationObject` の3つしか無い。2段駆動コンベアの上段/下段も、床に描いただけの
停止線も、人の立ち位置も、荷物の置き場も、**形式の上では同じ矩形**になる。だから
現場は **オブジェクト名に意味を書き込む**運用をしている。名前を無視すると実データは
こう壊れる —— コンベアも立ち位置マーカーも全部「作業台」になり、**表示のための線が
経路を塞ぐ壁**になり、上下段は同じ平面座標なので片方が消える。

そこで `whsim.rmpm` は名前を読む（`_NAME_RULES` の1つの表。判定は **NFKC 畳み込み＋
部分一致**で、**先に載っている行が勝つ**）。**規約語を1つも含まない図面の結果は
従来と1バイトも変わらない**（当たらなければ従来どおり type で分類する＝never blocks）。

| 名前に含まれる語 | 解釈 | 出力 |
|---|---|---|
| `停止線` / `停止位置` / `仕切り` / `区画線` / `表示線` | 表示・区画であって障壁ではない | **壁にしない**。`non_barriers[]`（`{id,name,kind,points,thickness}`）＝経路を塞がない |
| `立ち位置` / `作業者` / `作業員` / `検品者` / `梱包者` / `ピッカー` | 人の立ち位置マーカー（通例 500mm 角。寸法は条件にしない） | **什器にしない**。`markers[]`（`{id,name,x,y,role}`、role=`picker`/`inspector`/`packer`/`worker`） |
| `コンベア` / `コンベヤ` / `ベルト` / `本線` / `引き込み` / `還流` / `フリーコンベア` / `無動力` | 搬送設備 | **作業台にしない**。`conveyors[]`（矩形の**長辺の中心線**＝2点ポリライン、`speed_mps` 既定 0.5、`role`=`main`/`spur`/`return`/`gravity`/`belt`） |
| `段=下段` / `段=上段`、`床上NNNNmm` / `HNNNN` / `FL+NNNN` | 2段駆動コンベアのデッキ高さ | `conveyors[].elevation_m`。既定 下段 0.35 / 上段 0.95、**名前に書かれた高さが勝つ**（常に mm 表記として読む）。**同一XYの2本は両方残す**（高さだけが両者を分ける） |
| `東向き` / `西向き` / `北向き` / `南向き`、`北→南` 等 | 進行方向 | ポリラインの向き（`北 = -y`＝取込は Y を反転しない）。**長辺と直交する指定は無視**して警告 |
| `北半` / `南半`（`東半`/`西半`） | 本線を跨ぐ1本を作図都合で半分ずつ描いたもの | 同じ接頭辞の対を**1本に結合**（残りの名前が同じものだけ＝段が違えば結合しない）。件数を警告に1行 |
| `梱包台` / `検品台` / `作業台` / `投入口` | 作業台 | `stations[]`。名前で作業台と判った時だけ **実寸 `w`/`d`（mm→m）と `role`** を付ける（長辺の向き＝作業者の立ち位置）。無印の `StationObject` は従来どおり `{id,x,y}` のまま＝1台20mの検品場を「作業台1台」と言わない |
| `入荷エリア` / `出荷エリア` / `梱包エリア` / `ピッキングエリア` / `積み付け` / `置き場` / `エリア` | 意味領域 | `zones[]`（`type` は文脈から。決められなければ `staging`） |

- 返り値は従来の `{bounds, zones, walls, stations, warnings, stats}` を**壊さず**、
  `conveyors` / `markers` / `non_barriers` を**加算**する（知らない呼び出し側は無視するだけ）。
  `stats` にも件数（`conveyors`/`markers`/`non_barriers`/`merged_conveyors`）が増える。
- 判定は**種別に依らない**（名前が先、type は fallback）。壁クラスに名前が無い版
  （§5-2）では停止線に名前を書けないので、その図面は従来どおり全部壁になる。
- 規約に当たらない名前は一切影響しない（棚名 `100-01-09` 等はそのまま棚）。
- 回帰テスト: `tests/test_rmpm_naming.py`（規約7項目＋**規約語ゼロの図面が従来と完全一致**）。
