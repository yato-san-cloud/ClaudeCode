# 不具合連絡票の転記自動化 構想（ネオ・ウィング）

作成: 2026-07-17 / 検討材料: 現物写真 2 枚（不具合連絡票・手書き）

## 1. 現状と問題

- 現場（ネオウイング/ネオロジ）で紙の「不具合連絡票」をバインダー運用
- 様式: 日付 / 発生場所(2択☑) / 区分(入荷・出荷に丸) / 場所(T-sort・HT検収・9マルチに丸) /
  氏名(手書き) / 作業名(6択に丸) / 事象(チェックボックス12種+発見・破損) /
  詳細(伝票番号 T+6桁 等の手書き) / 注文番号 / ロケーション / JAN(手書き13桁) / 品目名 / 数量 / 責任(2択に丸)
- 紙→データの転記が手作業のため**転記漏れの疑い**。漏れると件数集計も傾向分析も欠損する

## 2. 対策は 3 層に分ける（抽出精度だけでは漏れは直らない）

| 層 | 対策 | 手段 |
|---|---|---|
| ①漏れの**検知** | 票に**連番**を振る（ナンバリングスタンプで十分）。番号の欠番=漏れ、が機械判定になる | 運用改善・コストゼロ |
| ②紙→データの**抽出** | 写真/スキャンPDFを Copilot エージェント（T1）が構造化。**CPA-004 として実装済み** | エージェントビルダー |
| ③kintoneへの**書込** | T1 は書き込み不可。**kintone REST API + ローカル Python** が書込役（gen_knowledge.py の逆方向） | 既存資産の延長 |

## 3. フェーズ計画

### Phase 1（今すぐ・半自動）: 撮影→CPA-004→人が貼る

```
現場: スマホ撮影 or 複合機スキャン
 → M365 Copilot チャットで CPA-004 に画像/PDF を添付「転記して」
 → 1票=1レコードの kintone 貼り付け形式で出力(読めない字は【要確認】)
 → 人が kintone 不具合アプリに貼る（検品＝【要確認】の解消のみ）
```

- 活動記録整形（CPA-002）と同じ「出力を人が貼る」型。現場リーダーに共有すればその場で使える
- 出力の最後に**「票 n 枚 → n セット」を必ず明記**（写した枚数と出力数の一致確認＝その場の漏れ検知）

### Phase 2（kintone 不具合アプリ稼働後・自動書込）: CSV→API 転記

```
CPA-004 の出力を CSV 形式に → ローカル defects_upload.py が kintone REST API で一括登録
 → 登録前に機械検証: JAN チェックデジット / 伝票番号 T+6桁 / 選択肢が enum 内 / 票No重複
 → 検証NG行だけ人に差し戻し
```

- JAN は EAN-13 チェックデジットで**転記ミスを数学的に検出できる**(手書き数字の読み誤り対策の本命)。
  LLM に検算させず、スクリプト側で検証する役割分担
- スクリプトは kintone API トークンがあれば書ける（gen_knowledge.py --kintone と同じ認証）。
  情シス申請・追加ライセンス不要

### Phase 3（定常運用・漏れ検知の自動化）: 週次突合

- 週次ジョブ: kintone の票No を連番チェック → **欠番一覧＝転記漏れ疑い**を出力（朝会/週報に添付）
- 発生日ベースで「先週の起票 n 件・登録 n 件」の件数照合も併記
- 副産物: kintone に全量入れば「T-sort出荷の過剰ピックが今月 x 件」等の傾向分析が
  証拠工場のネタになる（現行の紙バインダーでは不可能だった集計）

### （参考）完全無人化の条件

SharePoint 着信→フロー→AI 抽出→kintone 書込の無人ラインは T2（エージェントフロー）＋
kintone コネクタの成立が前提（判定テスト T3b）。通っても AI Builder は従量課金のため、
**Phase 2 の「撮る→エージェント→1コマンド」で十分軽い**ならそこで止めるのが費用対効果として妥当。

## 4. kintone「不具合アプリ」フィールド定義案

| フィールド | 型 | 値 |
|---|---|---|
| 票No | 数値(重複禁止) | 連番スタンプの番号 |
| 発生日 | 日付 | |
| 発生場所 | ラジオ | ネオウイング / ネオロジ |
| 区分 | ラジオ | 入荷 / 出荷 |
| 場所 | ラジオ | T-sort / HT検収 / 9マルチ |
| 作業者 | 文字列 | |
| 作業名 | ドロップダウン | 入荷検収 / 格納 / ピック / 検品 / T-sort入荷 / T-sort出荷 |
| 事象 | チェックボックス | 過剰入庫 / 過少入庫 / 入庫漏れ / 格納漏れ / 過剰ピック / 過少ピック / 誤ピック / 棚移動ミス / 特典JAN貼りミス / 作業完了エラー / 破損 |
| 発見/破損 | チェックボックス | 発見 / 破損 |
| 詳細 | 文字列(複数行) | 伝票番号含む |
| 伝票番号 | 文字列 | T+6桁（詳細から抽出） |
| 注文番号 / ロケーション | 文字列 | |
| JAN | 文字列 | 13桁・チェックデジット検証済 |
| 品目名 / 数量 | 文字列 / 数値 | |
| 責任 | ラジオ | ロジスティード中部 / NW様 |
| 原票画像 | 添付 | 撮影画像を添付(監査証跡) |
