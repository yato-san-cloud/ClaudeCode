# whsim — UI デザイン依頼（Claude Design 用プロンプト）

> このドキュメントをそのまま Claude Design に貼ってください。最後の「依頼」セクションが指示本体です。

---

## 1. 一言で

**「素人でもプロ並みの倉庫モデルが組めるハーネス」**。
非エンジニアの営業が、顧客のゆるい要件をヒアリングしながら倉庫を設計し、ワンクリックで
裏の重厚な離散事象シミュレーション（SimPy・モンテカルロ）が走り、提案書に貼れる結果
（2D/3Dアニメ・KPI・コスト・現行↔提案比較）が出る Web アプリ。**入力は簡単・計算は本格的**。

## 2. ターゲットユーザーと文脈

- **主役**：3PL / 物流の**営業・提案担当（非エンジニア）**。顧客先で、その場でライブに触る。
- **副**：物流コンサル、倉庫設計者、経営層（提案を受ける側）。
- 文脈：商談・提案。専門用語に詳しくない人が、迷わず・恥をかかず・数分で“それっぽく正しい”結果に到達できること。

## 3. デザイン原則

1. **Notion風**：白基調・余白広め・髪の毛のように細い境界線・控えめな影・温かいニアブラック文字・落ち着いた一貫性。装飾過多にしない。
2. **直感優先**：専門用語を表に出さない。各画面で「次に何をすればいいか」が1つ明確。空状態が親切。
3. **裏は重厚、表は静か**：モンテカルロ・待ち行列・ボトルネック等の難しさは隠し、「安定度 92%」「対応可能」など**結論と信頼度だけ**を見せる。
4. **常に動く／止めない**：データが欠けても仮値で必ず結果が出る。エラーで行き止まりにしない。
5. **正直さ＝信頼**：どこまで実データでどこからが仮定か（プロベナンス「実データ 25%」）を常時表示。

## 4. 情報設計（画面構成）

- **トップバー**：ロゴ「whsim 倉庫シミュレータ」／右に「実データ N%（取り込み: … ／ テンプレ仮値: …）」のプロベナンス・チップ。
- **左サイドバー（操作の縦動線）**：
  1. プロジェクト（テンプレ選択して作成 / 既存を開く）
  2. 顧客データ取り込み（ZIP ドラッグ&ドロップ ／ CAD図面(DXF)取込）
  3. キー項目（営業がヒアリングで埋める5項目：ピッカー人数・出荷オーダー/時・ピッキング方式・稼働時間・歩行速度）
  4. 「▶ シミュレーション実行」大ボタン＋ステータス
- **メイン（タブ）**：設計 / 2Dアニメーション / 3D / 提案PNG / 比較 / エクスポート（＋右端に「3D表現」プリセット：ナチュラル/夕/夜/モノ）
- **下部**：再生バー（再生/一時停止・シーク・速度・凡例）／KPIバー（判定バナー＋KPIカード群）

## 5. 主要フローと状態（各画面で空/実行中/結果/エラーを設計）

- **設計（デザイン）モード**：構造的・パラメトリックな編集キャンバス。サブツール＝
  - レイアウト（ゾーンをドラッグで移動/リサイズ、ラックは「通路×間隔」で自動生成、梱包台配置）
  - 設備（AGV/コンベア/自動倉庫/ロボットアーム/クレーン/フォークリフトをクリック配置）
  - 躯体（外壁ポリライン＋ドック扉/通用口/シャッターを作図）
  - フロー（工程ストリップ：入荷→格納→ピッキング→梱包→出荷、各工程の方式＝人手/AGV/コンベア/自動倉庫をインライン切替＋ピッキング方式）
  - 動線（任意経路を引いて距離・所要時間を一覧表示）
- **検証**：実行すると裏で**10回のモンテカルロ**。結果は2D（作業員/AGV/フォークリフトが動く）・3D（影付き・機器3Dモデル）・提案PNG。
- **比較**：現行 / ピーク日 / AGV導入 を横並び。デルタ色分け（緑=改善/赤=悪化）。¥/件・必要人員・投資回収。
- **エクスポート**：KPI CSV・動線一覧CSV・編集可能な提案書（PPTX/PDF）。

## 6. デザインシステム（Notion風トークン）

- **タイポ**：ラテン= **Inter**（400/500/600/700）、日本語= **Noto Sans JP**。本文14px/行間1.55、見出しは控えめなウェイト。数字は等幅（tabular-nums）。
- **カラー**
  - 文字：`#37352F`（温かいニアブラック）／副 `#5F5B53`／淡 `#8A8780`
  - 面：白 `#FFFFFF`、淡い面 `#F7F6F3`（サイドバー）
  - 境界線：`rgba(55,53,47,0.10)`（極細）
  - アクセント：Notionブルー `#2383E2`（hover `#1A6DC4`／淡 `#E9F2FB`）
  - 状態：成功 `#0F7B6C`（淡 `#DDF4EF`）／注意・危険 `#E03E3E`（淡 `#FBE4E4`）
  - 影：ごく弱い（`0 1px 2px rgba(15,15,15,.05)` 〜 `0 8px 24px rgba(15,15,15,.10)`）
  - 角丸：6–10px
- **コンポーネント**：カード、セグメントタブ、フォーム入力/セレクト（明確なフォーカスリング）、プライマリ/セカンダリ/ゴーストボタン、ドロップゾーン、ピル（プロベナンス）、KPIカード、判定バナー（成功=緑/危険=赤のコールアウト）、比較テーブル（デルタ色分け）、再生トランスポート、トースト/インライン通知。
- **モーション**：穏やかなトランジション（.14–.22s）。`prefers-reduced-motion` を尊重。
- **ダークモード**：あると尚良（`prefers-color-scheme`、Notionダーク寄り）。

## 7. 各画面のデザイン要点

- **判定バナー**：画面の主役。緑「対応可能 — ピッキング工程の稼働率45%で需要をさばけます（10回中10回が安定処理）」、赤「要注意 — 梱包がボトルネック…」。一目で結論。
- **KPIカード**：スループット（例 `120 件/時 (112–125)` ←p5–p95帯）、出荷完了、ボトルネック、ピッカー/梱包/AGV稼働率、処理時間中央値/最悪、**安定度（モンテカルロ）**、1件あたり歩行、**1件あたりコスト・月間コスト**。大きな等幅数字でスキャナブルに。
- **設計キャンバス**：図面は明快な平面図トーン（ゾーン淡色、ラックはABC色の小点、機器はラベル付きマーカー、壁は太線、扉は色分け）。右に選択中要素のインライン編集パネル。
- **2D/3D 再生**：状態色の凡例（待機/移動/ピック/運搬/梱包）。3Dは提案グレード（影・床テクスチャ・機器モデル）。
- **プロベナンス**：常時バーで「実データ 25% ／ 取り込み: 商品マスタ・出荷 ／ テンプレ仮値: …」。安心と次アクション（残りをヒアリング）を促す。

## 8. コンテンツ / トーン

- **全文日本語**。丁寧だが簡潔。**シミュレーション専門用語を出さない**（「離散事象」「稼働率σ」等は内部表現、画面は「安定度」「混み具合」等の平易語に）。
- 数字には単位（件/時、名、台、分、m、¥、%）。通貨は ¥ + 桁区切り。

## 9. アクセシビリティ / レスポンシブ

- キーボード操作・可視フォーカスリング・十分なコントラスト（WCAG AA）。
- 主対象はノートPC（商談）。最低 1280px 幅で最適、~1024pxでも崩れない。サイドバー折りたたみがあると良い。

## 10. 既存実装との対応（重要・現実的に作って）

これは絵だけでなく**実在のアプリ**です。以下にマップしてください（クラス/IDは流用前提）：
- レイアウト：`header / .brand / .provenance / .sidebar / .main / .card / .tabs/.tab(.active) / .stage / .panel(.active) / .transport / .kpibar / .verdict(.ok/.bad) / .kpi(.k/.v)` など。
- メインのビューは `#design / #view2d(canvas) / #view3d(three.js) / #viewpng / #compare / #export`。
- 構成・トーンは現行スクショ（添付の Notion 風刷新版）を出発点に、さらに洗練。

## 11. 成果物（お願いしたいアウトプット）

1. **デザインシステム**（カラー/タイポ/スペーシング/コンポーネント、トークン値つき）。
2. **主要画面のハイファイデザイン**：①設計（各サブツール）②2Dアニメーション＋KPIバー＋判定 ③3D ④比較 ⑤エクスポート/提案書 ⑥空状態・実行中・エラー。
3. **主要コンポーネント**：判定バナー、KPIカード、比較テーブル、プロベナンス・チップ、再生トランスポート、ドロップゾーン、フロー工程ストリップ。
4. 可能なら **CSSトークン or Tailwind/CSS変数**で受け渡せる形（実装に直接落とすため）。

## ▼ 依頼（これがプロンプト本体）

> あなたはトップクラスのプロダクトデザイナーです。上記の `whsim`（物流倉庫シミュレータ）の Web UI を、**Notion風のスマートで直感的な**デザインに仕上げてください。コンセプトは「**素人でもプロ並みの倉庫モデルが組めるハーネス＝入力は簡単・計算は本格的**」。主対象は非エンジニアの**物流営業**で、商談中にその場で触ります。
>
> 要件：(1) Notion由来の落ち着いた美学（白基調・広い余白・極細境界線・控えめな影・Interフォント＋日本語はNoto Sans JP・温かいニアブラック文字・Notionブルーのアクセント）、(2) 専門用語を出さず**結論と信頼度だけ**見せる（判定バナー＋KPIカード＋「安定度」）、(3) 全文日本語・丁寧簡潔、(4) アクセシブル（フォーカスリング・AAコントラスト・キーボード）、(5) 上記の画面構成（左サイドバー操作動線＋メインのタブ：設計/2D/3D/提案PNG/比較/エクスポート）とコンポーネントを網羅。
>
> 成果物：デザインシステム（トークン値）、主要画面のハイファイ、主要コンポーネント、空/実行中/エラー状態、そして実装に渡せる **CSS変数（またはTailwind）トークン**。既存のクラス/ID（`header/.sidebar/.card/.tabs/.tab/.panel/.kpibar/.verdict/.kpi` 等）に素直にマップできる構成にしてください。
