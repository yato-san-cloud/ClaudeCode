# 過去マニュアル評価メモ：「Lumenデバイス出荷・保管業務 作業マニュアル」（pptx・7枚・4:3）

評価日：2026-09-08 ／ 目的：既存マニュアルの型と癖を言語化し、「マニュアル作成スキル」設計の材料にする。
評価方法：スライドXMLの構造・文言・埋め込み写真21枚を直接読解（この環境ではLibreOfficeがファイルを開けず、
画像レンダリングは未実施）。原本pptxは機密（開示範囲指定あり）のためリポジトリには含めない。

## 2. 残すべき型（スタイルガイド候補）

1. **工程ナビ**：現在地が常に見える左レール
2. **帳票解説ページ**：帳票写真に番号を振り「どこを見るか」を最初に教える
3. **ステップグリッド**：番号＋短い見出し＋1〜2行＋写真＋機器画面（HT）の一貫レイアウト
4. **開示範囲の明記**：顧客名入りマニュアルの機密ラベル

## 3. 直すべき癖（リント項目候補）

| 癖 | 実例 | 対策（スキル側） |
|---|---|---|
| 写真負債 | 「商品の写真を添付」×5、「⇒「○○」」未記入 | プレースホルダ検出→未完了レポート、写真負債率をKPI化 |
| 写真品質 | 5〜18KBの縮小画像、ラベル・台車写真が90°回転、画面写真にモアレ | 解像度・向きの機械チェック、原本差し替え |
| 完了条件・NG例なし | 「一致しているか確認する」で終わり、不一致時の行動なし | 完了の見た目・困ったとき（planner/index.htmlのedu欄）を必須化 |
| 版管理情報なし | 表紙に版数・日付・作成者・見直し日がない | 表紙メタデータ必須＋見直し日超過警告 |
| 構造の重複 | 工程ナビ8個の図形が4ページに個別コピー | 正本JSONから描画（1か所修正で全頁反映） |
| 読者混在 | 顧客説明資料と作業者手順書が同一文書 | 同じ正本から読者別密度で出力（pptx顧客版／HTML現場版） |
| 誤記 | 「。。」、「⇒「○○」」 | 文言リント |

## 4. 設計への示唆（壁打ち結論）

- 「上手なpptxを書くスキル」ではなく **①言語化ルール（スタイルガイド＋良い例/悪い例）②構造化データ正本（`__manualdata` JSON）③指定書式レンダラー（4:3ハウス様式pptx／現場HTML／PDF）** の3層に分解する
- 判定できる項目はスクリプト（リント）に押し込み、AIには判断が要る部分だけ残す（ルール肥大＝遵守低下）
- 未決の論点：主読者（顧客 or 作業者）、指定書式は4:3 pptx固定か、過去マニュアルの量と評価情報、写真原本の有無、顧客別バリアント管理
