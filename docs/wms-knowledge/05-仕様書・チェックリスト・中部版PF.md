## 1. パッケージ仕様書から分かるシステム全体像

製品名は「ONEsLOGI Cloud / WMS」。パッケージ仕様書は機能単位のExcel（`パッケージ仕様書_<英語機能ID>_<日本語機能名>.xlsx`）で、サブシステム別フォルダに整理されている。

### 1.1 サブシステム構成（フォルダ構成＝機能体系）
- 00_共通資料（共通仕様、標準チェックリスト、記載基準書、メッセージ・区分値・採番一覧、画面遷移図［Web/HT/SD］）
- 01_入荷管理 / 02_出荷管理 / 03_在庫管理 / 04_棚卸管理
- 05_マスタ管理（01_マスタ、02_システム）
- 06_共通機能 / 07_日次処理 / 08_ＥＣ管理
- 09_ＨＴ機能（ハンディターミナル。配下は 共通機能・入荷・出荷・在庫・棚卸・システムのサブ構成）
- 10_ETL関連 / 11_運用管理 / 12_ＳＤ機能（スマートデバイス）

### 1.2 主な機能インベントリ（代表例）
- **入荷管理（16機能）**: 入荷予定入力／入荷予定一括取込（画面＋バッチ）／入荷予定リスト発行／入荷実績入力（予定あり・予定なし）／入荷未完了一覧／入荷履歴／商品別・伝票別入荷一覧／入荷ステータス別進捗／入庫ラベル発行／汎用ラベル発行／入荷実績抽出バッチ
- **出荷管理（44機能）**: 出荷指示入力／出荷指示一括取込（画面＋バッチ）／出庫指示バッチ・後処理バッチ／自動出庫指示登録バッチ／ピッキングリスト発行・パターンピッキングリスト発行／ピッキング提案（明細含む）／出荷検品（通常・数量入力・箱登録・単行・パターン）／梱包明細（一覧・修正・履歴・個口追加）／送り状データ出力／貨物追跡番号一括取込／積込リスト発行／出荷確定一覧／出荷実績訂正／出荷履歴／出荷期限管理一覧／配送コース別出荷一覧／AMS連携（移動指示抽出・移動取消抽出・割付データ取込バッチ）
- **在庫管理（23機能）**: 在庫問合せ（通常・参照）／トータル在庫問合せ／在庫受払問合せ／在庫調整／在庫移動（指示・一括移動・明細一覧・履歴・訂正）／補充指示一覧／セット組・セット解除（指示＋指示書発行）／シリアルNo.管理（一覧・メンテナンス）／搬送ラベル発行／在庫抽出バッチ
- ほかに棚卸管理、EC管理、日次処理、ETL、運用管理、SD機能がある。

### 1.3 仕様書の記載形式（仕様概要シート）
各機能はユースケース形式で記述: 利用者(Who)・利用タイミング(When)・利用場所(Where)＋「利用目的(Why)／利用方法(How)／処理内容(What)／処理前提・補足／使用ボタン等」の繰り返し。例:
- **入荷予定入力（ReceivePlanInput）**: 荷主・仕入先等から電話/FAX等で受付した入荷予定を登録・変更・削除。登録時マスタに不備があると入荷ステータス「エラー有」で登録し、伝票別入荷一覧で再チェック。変更・取消は「未入荷」ステータスのみ対象、取消は物理削除。処理区分/在庫区分/預託、予定倉庫・ロケーション、ロット・期限日、入庫ラベルNo.、顧客発注No.等を事前指定可能。行追加/行削除で行数変更。
- **出荷指示入力（ShippingPlanInput）**: 出荷指示の登録・変更・削除。マスタ不備は「エラー有」で登録し出庫指示一覧で再チェック。変更は「未出荷」のみ、取消は出庫指示一覧のキャンセル参照。緊急フラグ（1:緊急）、納品予定日・作業日・出荷日、配送コース、ワンタイム届先（納品先名称・郵便番号・住所・電話を直接入力）を指定可能。

### 1.4 共通仕様（パッケージ仕様書_共通仕様.xlsx）の要点＝システム共通の制約・UI規約
- **画面共通UI**: カレンダーボタン（日付選択）、プルダウン、アシストボタン（コード検索→検索モーダル）、入力後のコード名称表示、トグルボタン（絞り込み・展開/閉じる）、プレビュー表示、Excel出力/取込機能。使用不可ボタンは非活性化。
- **検索モーダルの共通体系**: センタ、荷主、倉庫、ゾーン、棚（ロケーション）、運送業者、仕入先、商品、取引先、ロケーション等のマスタ検索モーダルを全画面で共通利用。From/To指定は「荷主CD(From)/(To)」等の対で持つ。
- **マスタの参照体系**: 共通運送業者マスタ、荷主別マスタ、初期処理区分/EDI/取込棚区分/荷材（荷材グループ・デフォルト荷材）/棚変（商品荷姿マスタ：補充点・最大格納数・最大棚卸数量等）/在庫管理単位（荷姿グループ）/カレンダ・タイムゾーン/権限（権限グループ）/メニューグループ/区分値（区分値グループ：センタ別・センタ区分グループ別に階層検索、名称は区分値マスタから取得）など。区分値はシステム共通→センタ別→センタ区分グループ別の優先で解決。
- **入力チェックの共通規約**: 必須チェック、桁数（フル桁+1は入力不可またはエラー）、文字種制限、From≦Toチェック（片側のみ入力も許容）、数値の右詰め・カンマ編集（4桁以上）、日付はYYYY/MM/DD（"/"なし入力可）、時刻はHH:MM(24時間制、":"なし入力可)、負数・小数点の可否チェック。
- **メッセージ体系**: エラー/警告発生時はメッセージ表示＋該当項目にフォーカス。共通エラーID（entryAlreadyUpdatedError＝排他制御、netUploadError、fileUploadCheckError、overSafetySizeToReportError など）が定義され、メッセージ・区分値・採番一覧.xlsx に一覧化。処理完了時は「登録を完了しました」等のセクション情報を表示。
- **帳票/ラベル**: 出力帳票に完了・失敗メッセージ規約あり。
- **画面遷移**: 画面遷移図.xlsx（Web）、画面遷移図(HT).xlsx、画面遷移図(SD).xlsx で全体遷移を管理。

### 1.5 運用上の含意
- 予定→実績→履歴という流れが入荷・出荷とも基本（予定/指示の一括取込はファイル取込＋バッチ）。
- ステータス駆動（未入荷/未出荷のみ訂正可、エラー有は一覧画面で解消）。進捗はステータス別進捗画面で監視。
- HT（ハンディ）とSD（スマートデバイス）に同系統の現場機能があり、Web画面と併用する構成。

## 2. 標準チェックリスト（フォルダ「05_標準チェックリスト」）

導入・改修時の品質確認用テストチェックリスト4種。運用開始前の受入確認観点としても使える。

### 2.1 画面系単体テスト用（113項目、2014/7更新）
画面ID・サブシステム名・機能名単位に確認。主な観点:
- **フォーム/画面全体**: タイトルバー名称（遷移元ボタン名と一致・誤字なし）、ボタン/ボックスのレイアウト・大きさ統一、項目名称の画面間（HT含む）統一、初期フォーカス位置、デフォルト値、画面遷移（親画面への戻り・子画面遷移）、標準ディスプレイサイズで切れないこと。
- **テキストボックス/グリッド**: 桁数統一、Enter/Tab（Shift+で逆）フォーカス移動、フォーカス順（左上→右下）、活性/非活性の切替タイミング、エラー時のメッセージ表示とフォーカス。
- **入力値チェック**: フル桁入力可・フル桁+1不可、指定外桁数/文字種エラー、必須チェック、入力不可項目、ソート可否、特殊文字（*, %,「」等）・スペースのみ・途中スペースの処理、数値の右詰め・カンマ編集・小数点/マイナス/境界値(MAX/MIN)・四捨五入、日付書式YYYY/MM/DDと存在チェック（4/31等）・From>Toエラー、時刻書式HH:MM:SS・24時間制、IMEオフ固定。
- **コマンドボタン/ファンクションキー**: ボタン名に合った処理、Enterキー押下同等動作、Fキー割当の有無どおりの動作。
- **コンボボックス**: 選択肢の内容（コードのみ/コード＆名称、削除フラグ=0のみ）とソート。
- **スクロールバー、メッセージダイアログ**: 処理（登録・更新・削除）前の確認メッセージ、完了後の正常/異常メッセージ、印刷完了メッセージ、応答後シーケンス、文言の適切さ（エンドユーザに明解か）、アイコン/タイトル適正。
- **エラー処理**: 同種項目のエラーチェック統一、エラー順序（左上→右下、必須→内容→マスタ存在の順）。
- **登録・更新・検索・Excel**: 再表示時の内容一致、最大桁でのABENDなし、エラー時入力値保持、全検索条件での検索、From/To（FROMのみ・TOのみ・両方）、Excel出力の項目過不足・左詰/右詰、Excel一括取込が画面登録と同等処理か、ユーザ権限に沿った制御、右クリックメニュー、単位（cs、g、cm3等、単位換算表示）。

### 2.2 帳票系単体テスト用（29項目、2014/7更新）
- タイトル（画面の出力ボタン名称と統一・誤字なし）、帳票IDの出力、項目サイズ・位置、最大文字列の欠け、出力対象範囲（出力期間・店舗名・倉庫名）、日付YYYY/MM/DD・時刻HH:MM書式。
- 明細: タイトル部、対象データの出力、ソート順、合計（縦計・横計）・総合計。
- 改ページ: Max/Max−1/Max＋1データ量での頁割れ、ページブレイク条件（複数出荷日等）、合計行のみ次ページの場合の改ページ。
- Max桁の桁落ち（明細・合計欄）、カンマ編集、マイナス表示、ページ数、実際に印刷して罫線途切れ確認、項目名称の帳票間統一、帳票出力完了/失敗メッセージ。

### 2.3 組合せテスト用
- 前提条件: 全テストケースで「小数有り商品」と「小数無し商品」の両方をテストする。
- 業務パターン別のシナリオマトリクス形式。例:「業務パターン（入荷）（入庫ラベルNo管理有）」＝入荷予定入力→入荷予定一覧→入荷予定リスト発行→入荷実績入力→入庫ラベル発行→入荷照会…と機能を横断した流れで、荷主・数量小数、権限グループマスタ設定込みの計画/実績/エラー系（マスタ不備でエラー有登録→解消、ロット・期限入力、HT入荷等）を確認する構成。進捗管理シート（バーンダウン、消化件数・摘出バグ数集計）付き。

### 2.4 総合テスト用【サンプル】
サンプルの総合テスト計画/チェックリスト（.xls）。プレビュー1ページ目はほぼ白紙で、業務総合シナリオの雛形として提供されているもの。

## 3. 中部版PF説明資料（中部版PFとは）の要点

- **定義**: 物流ソ（日立物流ソフトウェア）が保有する「春日部ECPF」をベースにした標準PF（仮称）に、中部独自の7機能を追加したものが「中部版PF」。系譜: 2019年 世田谷食品独自機能追加 → 2021年 春日部ECPF稼働 → 標準PF → 中部版PF。
- **中部独自7機能**:
  1. マルチピック（HT/タブレット）
  2. FBA（Fulfillment by Amazon）納品代行
  3. 箱Noバーコード発行
  4. 出力帳票バーコードスキャン
  5. 業者/方面別積込検品
  6. 送り状先出し機能【パターンピック・検品】
  7. 返品機能
- **ライセンス・制約（注意点）**:
  - ライセンス費用: 1,200,000（中部版PF）。
  - 標準PF本体に追加された最新機能は中部版PFへは反映されない（機能分岐）。
  - 中部版ではなく標準PFを使いたい場合は別途ライセンス費用が発生し、その時点の最新Verのみ使用可能。
  - 中部版への機能追加は年間3M円以内であれば可能。
