## 共通データモデル「ロジスティクスDWH」(全ユニット共通・この名前以外を発明しない)

### ファクトテーブル
- `F_出荷明細`: [出荷ID], [日付], [顧客ID], [商品ID], [拠点ID], [数量], [重量kg], [運賃], [受注日], [出荷予定日], [実出荷日], [納品予定日], [実納品日], [誤出荷フラグ](0/1)
  - 粒度: 出荷明細1行(1出荷×1SKU)。[日付]=実出荷日ベースで日付テーブルと接続。
- `F_在庫`: [日付], [商品ID], [拠点ID], [在庫数], [在庫金額]  ※日次スナップショット(足してはいけない!)
- `F_配車`: [便ID], [日付], [拠点ID], [車両ID], [積載重量kg], [走行km], [配送コスト], [個口数]

### ディメンションテーブル
- `D_商品`: [商品ID], [商品名], [カテゴリ], [温度帯](常温/冷蔵/冷凍), [単価], [原価]
- `D_顧客`: [顧客ID], [顧客名], [業態](量販店/EC/卸/外食), [地域]
- `D_拠点`: [拠点ID], [倉庫名], [エリア]
- `D_車両`: [車両ID], [車格](2t/4t/10t), [最大積載量kg]
- `日付`: [Date], [年], [月], [年月], [年月キー], [曜日], [営業日フラグ]  ※「日付テーブルとしてマーク」済み

### DAX表記規約(type/fill問題の正解はこの規約に厳密に従う)
- メジャー参照: `[出荷件数]`(表名なし) / 列参照: `F_出荷明細[数量]`(表名あり)
- 日付テーブルの列は `'日付'[Date]` のようにクォート付き。他テーブルはクォートなし。
- 演算子の前後に半角スペース1つ。カンマの後に半角スペース1つ。

### 標準メジャー辞書(既出メジャーとして参照可。定義もこれが正)
```
[出荷件数]       = COUNTROWS(F_出荷明細)
[出荷数量]       = SUM(F_出荷明細[数量])
[運賃合計]       = SUM(F_出荷明細[運賃])
[売上金額]       = SUMX(F_出荷明細, F_出荷明細[数量] * RELATED(D_商品[単価]))
[出荷原価]       = SUMX(F_出荷明細, F_出荷明細[数量] * RELATED(D_商品[原価]))
[出荷顧客数]     = DISTINCTCOUNT(F_出荷明細[顧客ID])
[納品件数]       = COUNTROWS(FILTER(F_出荷明細, NOT ISBLANK(F_出荷明細[実納品日])))
[期限内納品件数] = COUNTROWS(FILTER(F_出荷明細, F_出荷明細[実納品日] <= F_出荷明細[納品予定日]))
[OTD]           = DIVIDE([期限内納品件数], [納品件数])
[誤出荷件数]     = CALCULATE([出荷件数], F_出荷明細[誤出荷フラグ] = 1)
[誤出荷率ppm]    = DIVIDE([誤出荷件数], [出荷件数]) * 1000000
[平均リードタイム] = AVERAGEX(F_出荷明細, DATEDIFF(F_出荷明細[受注日], F_出荷明細[実納品日], DAY))
[月末在庫数]     = CALCULATE(SUM(F_在庫[在庫数]), LASTDATE('日付'[Date]))
[在庫金額合計]   = CALCULATE(SUM(F_在庫[在庫金額]), LASTDATE('日付'[Date]))
[積載率]         = DIVIDE(SUM(F_配車[積載重量kg]), SUMX(F_配車, RELATED(D_車両[最大積載量kg])))
```

## 物流KPIチートシート(教材内の定義はこれに統一)
- OTD(納期遵守率) = 期限内納品件数 ÷ 納品件数(目標例 98%)
- 誤出荷率 = 誤出荷件数 ÷ 出荷件数 × 1,000,000(ppm表記、目標例 50ppm以下)
- 在庫回転率 = 出荷原価 ÷ 平均在庫金額(年換算)/ 在庫日数 = 365 ÷ 回転率
- 積載率 = 積載重量 ÷ 最大積載量(車両容積ベースの議論にも触れてよい)
- リードタイム = 受注日→実納品日の日数
- 物流波動 = 曜日・月内・季節の物量変動。移動平均でならして見る。

## ユニット構成(10ユニット・各4〜5レッスン)
各レッスンの演習: 4〜6問(mc/fill/typeミックス。SCHEMA.mdの規則に従う)。
「type例」は出題例。そのまま使ってよいし、同水準の別問題でもよい。

### Unit 01 🚚 物流データアナリスト事始め(color: #e8641b)— 4レッスン
1. **物流データの地図** — WMS/TMS/OMS/基幹システムから出るデータの種類。トランザクション(出荷明細・入荷・在庫移動)とマスタの違い。「粒度」という概念(出荷明細1行=何を表すか)。
2. **物流KPI大全** — OTD・誤出荷率ppm・在庫回転率・積載率・リードタイムの定義と「なぜその指標か」。fillでKPI定義式(算数レベル)を組ませる。
3. **ロジスティクスDWHのスタースキーマ** — 共通データモデルの全体像をここで導入。ファクト×3とディメンション、1対多の向き。「スライサーはディメンションから」。
4. **分析の型と問いの立て方** — トレンド/構成/比較/異常検知の4類型。悪い問い(「在庫を見たい」)を良い問い(「どのSKUの在庫日数が伸びているか」)に直す。ダッシュボードは「意思決定から逆算」。

### Unit 02 🧹 M基礎 × 出荷CSVクレンジング(color: #d99a06)— 5レッスン
1. **let式とCSV取込** — Csv.Document→ヘッダー昇格→型変更という定番3点セットをMコードで読む。let/in、ステップ=変数。
2. **型変換の地雷原** — 「テキストを数値に変換できません」。全角数字・単位付き数値(`"1,200個"`)・null。Number.From、Text.Select。type例: `Number.From(Text.Select([数量テキスト], {"0".."9"}))`
3. **SKUコードの正規化** — Text.Trim/Clean/Upper/PadStart。「ゼロ落ちしたSKU」(Excelで00123→123)をText.PadStartで復元。type例: `Text.PadStart(Text.From([商品ID]), 8, "0")`
4. **each再入門と行フィルター** — each=関数の糖衣構文。テスト出荷・キャンセル行の除外。Table.SelectRowsのeachの中身を書く。
5. **日付とリードタイム** — Date.From、Duration.Days で受注→納品のLT列を作る。type例: `Duration.Days([実納品日] - [受注日])`

### Unit 03 🏭 M応用 × 拠点データ統合(color: #a16a3c)— 5レッスン
1. **フォルダー結合** — 拠点別CSV(東京・大阪・福岡…)の一括取込。Folder.Files、サンプルファイル変換関数の仕組み、Source.Name列から拠点名を抽出。
2. **マージ戦術** — Table.NestedJoinとJoinKind。LeftAntiで「商品マスタ未登録SKUの検出」(データ品質チェックの定番)。キーの型・空白を揃えてから結合。
3. **Table.Groupで便別集計** — 便ID単位の個口数・重量集計。Groupのeachに渡る「部分テーブル」の理解。
4. **エラー処理と品質ゲート** — try...otherwise、error での意図的な更新停止(「マスタ未登録が1件でもあれば更新を失敗させる」)。
5. **フォールディングと100万行** — クエリフォールディングの原理、ネイティブクエリ表示、切ってしまう操作。不要列は早く削る。Table.Bufferの使い所と副作用。

### Unit 04 📏 DAX基礎 × KPIメジャー第一歩(color: #2f8f46)— 5レッスン
1. **メジャー vs 計算列** — 物流KPIは原則メジャー。評価タイミングとメモリの違い。計算列が正当な場面(スライサー用の区分列)。
2. **基本集計メジャー** — [出荷件数][出荷数量][運賃合計][出荷顧客数]を実際に書く(標準メジャー辞書どおり)。type例: `出荷顧客数 = DISTINCTCOUNT(F_出荷明細[顧客ID])`
3. **DIVIDEと誤出荷率ppm** — 0除算の安全策。ppm換算。type例: `誤出荷率ppm = DIVIDE([誤出荷件数], [出荷件数]) * 1000000`
4. **SUMXで明細金額** — SUMは列しか取れない→行ごとの「数量×単価」はSUMX+RELATED。[売上金額]を書く。
5. **メジャー整理術** — 命名規則(ベース名+修飾子)、メジャーテーブル、表示フォルダー、DIVIDE/フォーマット文字列の作法。

### Unit 05 🔍 コンテキスト × 拠点・顧客分析(color: #1f8a80)— 5レッスン
1. **フィルターコンテキスト** — 拠点×年月マトリックスの各セルで[出荷件数]が変わる仕組み。スライサー(温度帯)の効き方。
2. **行コンテキスト** — 計算列でLT区分(翌日/翌々日/3日以上)を作る。SWITCH(TRUE(), ...)パターン。行コンテキストはフィルターしない。
3. **CALCULATE入門** — `CALCULATE([出荷数量], D_商品[温度帯] = "冷凍")`。同一列フィルターの上書き挙動。
4. **ALLと全社構成比** — `DIVIDE([出荷数量], CALCULATE([出荷数量], ALL(D_拠点)))` で拠点構成比。
5. **ALLSELECTEDと選択内シェア** — スライサーで選んだ地域内でのシェア。ALLとの違いを実感させる。

### Unit 06 ⏰ CALCULATE道場 × 納期遵守率(color: #2f6fd0)— 5レッスン
1. **OTDメジャーを組み立てる** — FILTER+COUNTROWSで[期限内納品件数]→[OTD]。ブールフィルターとFILTERの使い分け。type例: 標準辞書の[OTD]系。
2. **KEEPFILTERSと上書き** — 「量販店のOTD」をスライサーと共存させる。掛け合わせvs上書き。
3. **コンテキスト遷移とワースト顧客** — SUMX/AVERAGEX(VALUES(D_顧客[顧客名]), [OTD])。メジャー参照=暗黙CALCULATE。重複行の罠。
4. **USERELATIONSHIP** — [日付]は実出荷日ベース。納品日ベースの件数を非アクティブリレーションで。type例: `納品日基準件数 = CALCULATE([出荷件数], USERELATIONSHIP(F_出荷明細[実納品日], '日付'[Date]))`
5. **VARでOTD前月差** — VARの1回評価、スナップショットの罠(VARにALLが効かない)、RETURN差し替えデバッグ。

### Unit 07 📈 タイムインテリジェンス × 物量トレンド(color: #5561d6)— 5レッスン
1. **日付テーブル構築** — M版(List.Dates)とDAX版(CALENDARAUTO)、営業日フラグ、マークする。自動日付/時刻オフ。
2. **累計(YTD/QTD/MTD)** — TOTALYTD で累計出荷数量。会計年度(4月始まり: "3/31")対応。type例: `出荷数量YTD = TOTALYTD([出荷数量], '日付'[Date], "3/31")`
3. **前年同月比** — SAMEPERIODLASTYEAR / DATEADD。前年比%メジャーをVARで。
4. **移動平均で波動をならす** — DATESINPERIOD で7日移動平均。物流波動(曜日波動)の実務文脈。type例: `出荷数量7日平均 = AVERAGEX(DATESINPERIOD('日付'[Date], MAX('日付'[Date]), -7, DAY), [出荷数量])`
5. **営業日あたり物量** — 営業日フラグで割る。休日を含む単純平均との違い。CALCULATEで営業日数メジャー。

### Unit 08 📦 在庫分析 × 半加法メジャー(color: #8a4fd3)— 5レッスン
1. **スナップショットを足すな** — F_在庫は日次残高。SUMで月合計すると意味不明な数に(実例の数字で見せる)。半加法(semi-additive)の概念。
2. **LASTDATEと月末在庫** — [月末在庫数]を書く。LASTNONBLANKとの違い(データが月末までない月)。type例: 標準辞書の[月末在庫数]。
3. **在庫回転率と在庫日数** — 平均在庫金額(AVERAGEX over 年月)→回転率→在庫日数365/回転。遅い在庫=キャッシュの滞留という実務観点。
4. **滞留在庫の検出** — 最終出荷日からの経過日数。`DATEDIFF(CALCULATE(MAX(F_出荷明細[実出荷日])), TODAY(), DAY)`系。90日超滞留SKUリスト。
5. **欠品と充足率** — 在庫ゼロ日数のカウント、欠品率。COUNTROWS(FILTER(...在庫数=0...))パターン。

### Unit 09 🏆 上級 × ABC分析とランキング(color: #c23a8c)— 5レッスン
1. **RANKXで顧客ランキング** — `RANKX(ALL(D_顧客[顧客名]), [出荷数量])`。ALLが要る理由(コンテキスト復元)。同率のDENSE/SKIP。
2. **TOPNと上位10顧客** — 上位10顧客の売上、「その他」の作り方(全体−上位)。
3. **パレートとABC分析** — 累積構成比メジャー(自分以上の売上の顧客/SKUを合計÷全体)。A=80%/B=95%閾値。物流での使い道(ロケーション最適化、棚割り)。
4. **動的グルーピング** — SWITCHでABC区分をメジャー化 vs 計算列化のトレードオフ(スライサーに使うなら列)。
5. **TREATASで物量計画vs実績** — リレーションのない計画テーブル(月×拠点粒度)と実績の突合。type例: `計画対比 = DIVIDE([出荷数量], CALCULATE(SUM(計画[計画数量]), TREATAS(VALUES('日付'[年月]), 計画[年月])))` ※このレッスンのみ `計画` テーブル([年月], [拠点ID], [計画数量])を追加登場させてよい。
6.(任意)まとめクイズレッスンにしてもよい(5レッスン目に統合可)。

### Unit 10 🎓 総合演習 × 経営ダッシュボード(color: #8c6d1f)— 5レッスン
1. **配車分析と積載率** — F_配車×D_車両。[積載率]メジャー(SUMX+RELATED)。積載率が低い=便数過多のコスト問題。
2. **配送コスト分析** — コスト/個口、コスト/kg、コスト/km。DIVIDEの応用。拠点間比較で「どの倉庫が高いか」ではなく「なぜ高いか(距離?積載率?)」に分解する思考。
3. **パフォーマンス総点検** — パフォーマンスアナライザー→DAX Studio。カーディナリティ削減、計算列→メジャー化、双方向フィルター排除。モデル軽量化チェックリスト。
4. **KPIツリーとダッシュボード設計** — 経営KPI(物流コスト率)→中間KPI(積載率・在庫回転)→現場KPI(誤出荷・OTD)のツリー。1画面の情報設計、Zの視線、スライサー配置。
5. **卒業試験** — 全ユニット横断の難問ミックス(type2問以上を含む6問)。合格したら「物流データアナリスト認定」の演出はシェル側の結果画面に任せる(コンテンツは問題を出すだけ)。
