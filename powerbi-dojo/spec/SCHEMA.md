# コンテンツスキーマ仕様 (src/units/unitXX.js)

各ユニットファイルは**次の形式のみ**を含む(他のロジック・関数定義は禁止):

```js
window.DOJO_UNITS = window.DOJO_UNITS || [];
window.DOJO_UNITS.push({
  id: "unit01",          // ファイル名と一致(unit01〜unit10)
  no: 1,                 // ユニット番号(数値)
  icon: "🚚",
  name: "物流データアナリスト事始め",
  color: "#e8641b",      // CURRICULUM.md指定のテーマ色
  desc: "1行の説明",
  lessons: [ /* 4〜6件 */ ]
});
```

## lesson オブジェクト
```js
{
  title: "レッスン名",
  doc: `HTML文字列`,        // 解説。<p> <pre> <code> <b> <p class="tip"> を使用可
  exercises: [ /* 4〜6問 */ ]
}
```
- doc には**必ず1つ以上の `<pre>` コード例**と、できれば `<p class="tip">💡 実務メモ: ...</p>` を含める。
- doc内の `<pre>` の中では `<` を `&lt;` にエスケープすること(`<=` `<>` に注意)。
- 現場の1シーン→概念→コード例→実務メモ、の流れを推奨。長さの目安は本文3〜5段落。

## 演習タイプ(3種)

### mc — 4択
```js
{ type: "mc", q: "設問文", code: "表示用コード(任意)", lang: "m"|"dax"(codeがある場合),
  c: ["選択肢1","選択肢2","選択肢3","選択肢4"], a: 1, e: "解説" }
```

### fill — トークンバンク式穴埋め(Duolingo風)
```js
{ type: "fill", q: "設問文", lang: "dax",
  code: "OTD = DIVIDE(【0】, 【1】)",
  bank: ["[期限内納品件数]", "[納品件数]", "[出荷件数]", "SUM(F_出荷明細[数量])"],
  answers: [0, 1],   // スロットnの正解 = bank[answers[n]]
  e: "解説" }
```
- `【n】` は0から**連番**。answers.length === スロット数。
- bank は answers で使う数 + **2個以上のダミー**(もっともらしい誤答)。bank内の重複禁止。
- 同一トークンを2スロットで使う場合でもbankには1回だけ入れ、answersから同じindexを2回参照してよい。

### type — エディター記述式
```js
{ type: "type", q: "何を書くべきか完全に特定できる設問文",
  lang: "dax",
  scaffold: "誤出荷率ppm = ",     // 任意。エディタの初期値(定型部分)
  answer: "誤出荷率ppm = DIVIDE([誤出荷件数], [出荷件数]) * 1000000",  // scaffold含む完全な最終コード
  accept: ["誤出荷率ppm = DIVIDE([誤出荷件数], [出荷件数]) * 1e6"],   // 任意。妥当な別解
  hint: "ヒント文(答えそのものは書かない)",
  e: "解説" }
```
- answer はエディタの**全文**(scaffoldを含む)。1〜3行に収まる規模にする。
- 列名・メジャー名・関数はCURRICULUM.mdの共通データモデル/標準メジャー辞書/表記規約に**厳密に一致**させる。
- 判定は正規化比較(全半角・大文字小文字・空白の差は吸収される)なので、意味の違う別解のみacceptに入れる。
- scaffoldでメジャー名など定型部分を与え、学習者が打つのは「本質部分」になるよう設計する。

## 問題ミックスの規則(validate.jsが機械チェックする)
- 各レッスン: 演習4〜6問、**fillを1問以上**。
- ユニット2以降(no >= 2): 各レッスンに**typeを1問以上**。
- ユニット10の最終レッスン(卒業試験): typeを**2問以上**、計6問。

## 共通ルール
- 解説 `e` は必ず2〜3文: ①なぜそれが正解か ②物流実務でどう効くか。20文字以上。
- 設問 `q` は曖昧さゼロ(答えが一意に定まる)。qやe内でインラインコードは `<code>` で囲んでよい。
- mc の誤答選択肢は「ありがちな勘違い」を反映させる(でたらめな選択肢にしない)。
- 文字列内に `</script` を絶対に含めない(`<\/pre>`等は問題ない。scriptタグのみ禁止)。
- code / q / bank / answer / scaffold は生テキスト(HTMLエスケープ不要。表示側で処理する)。**docだけがHTML**。
- 難易度はレッスン内で易→難に並べる。最後の1問は少し背伸びさせる。

## 完了条件
`node spec/validate.js src/units/unitXX.js` がエラーゼロで通ること。
