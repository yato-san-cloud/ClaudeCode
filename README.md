# 広告詐欺ゲーム

YouTube などで流れてくる「面白そうなのに、実際にダウンロードすると影も形もない」
あのゲーム広告 — その**広告の方**を、全部ちゃんと遊べるようにしたブラウザゲームです。

`index.html` をブラウザで開くだけで遊べます。外部リソースなし、ビルド不要、`file://` でも動きます。

## 流れ

1. **広告** — 下手なプレイヤーが盛大に失敗するデモが流れ、「99%の人が失敗します」と煽られる。
   そのあと自分で操作できる。スキップボタンは 5 秒後に出るが 2 回逃げる。
2. **ストア** — ★4.9、1億DL、パズルのスクリーンショット。
   小さい注意書きに「本アプリの主要コンテンツは『マージ王国：ドラゴンサーガ ぷにぷに』です」。
3. **インストール** — 87% で急に減速し、99% で止まる。
4. **実物** — パズルは影も形もない。タマゴを合体させるだけ。
   初回ポップアップ 4 連発、3手ごとに全画面広告、エネルギー切れ、
   パズルモードは「レベル150で解放」。
5. **返金** — 設定から返金をリクエストすると承認され、
6. **広告ギャラリー** — 「広告では見たのに、入れたら無かった」ゲームが全部遊べる。

行き詰まらないよう、実物のゲームから先へ進む出口は 3 つ用意してあります
（設定 → 返金 / 広告 4 本目のあとの問いかけ / パズルタブを何度も叩く）。

## これは実際にあった話

2020年9月、英国の広告基準協議会 (ASA) が Playrix の「Homescapes」「Gardenscapes」の広告を
誤解を招くとして禁止しました。広告に出てくるピン抜きパズルは、4000以上あるレベルのうち
**約10レベル**にしか存在せず、そこへ到達したプレイヤーは Playrix 自身の申告で**約0.03%**。
「※実際のゲーム画面とは異なります」という注記も、誤認を打ち消すものとしては認められませんでした。
モバイルゲームの誤認広告に対する初の禁止処分とされ、以降「広告はゲームの中心的な体験を
反映していなければならない」という基準として引用され続けています。

日本では「広告ゲー」「ピン抜きパズル」などと呼ばれます。

## 開発

```
node build.mjs            # src/ + template.html → index.html を生成
node tools/verify.mjs     # ピン抜きの全ステージをヘッドレスで物理検証
node qa/one.mjs <id>      # 広告ゲームを 1 本だけ単体でビルドして検証（並列作業向け）
npm i && node qa/check.mjs    # 全広告ゲームを実ブラウザで自動クリアさせて検証
npm i && node tools/smoke.mjs # 本編を通しプレイし、各画面を撮影
```

`index.html` は生成物です。編集は `src/` と `template.html` に対して行い、`node build.mjs` で焼き直してください。

### 広告ゲームを追加する

`src/ads/<id>.js` を 1 ファイル置くだけで、ビルドが自動で拾います。契約は `src/mini.js`
の冒頭コメントに全部書いてあります。要点は 3 つ:

- **トップレベルの宣言は `export const <大文字ID> = { meta, create(api) }` ただ 1 つ。**
  ビルド時に全モジュールが 1 スコープへ展開されるため、それ以外を置くと名前が衝突します。
- **`game.solve()` を必ず実装する。** 「正解手順で自動クリアする」フックで、
  `qa/one.mjs` と `qa/check.mjs` がこれを呼んで実ブラウザ上でクリア可能性を検証します。
  クリアできないステージを置いてしまう事故は、これで機械的に防げます。
- `src/app.js` の `MINI_GAMES` へ登録する（忘れるとビルドが止まります）。

ステージの正解が自明でないゲーム（経路探索・順序パズルなど）は、
**ソルバをゲーム内に持たせて `solve()` から呼ぶ**のが確実です。
`src/ads/dig.js`（幅優先探索）と `src/ads/tower.js`（ビットマスク総当り）がその例で、
「解けないステージを置く」ことが構造的にできなくなります。

### ピン抜きパズルのステージを触るときの注意

物理シミュレーションが絡むので、目視だけだと理不尽なステージができます。
必ず `tools/verify.mjs` を通してください。検証は「解法どおりで勝てる」「罠の手順では負ける」
「目標より 1 割以上の余裕がある」の 3 点を見ます。

過去に踏んだ落とし穴と対策が `src/levels.js` の冒頭にまとまっています。要点だけ:

- **棚の上面 y と、その段の窓の下端 y を一致させる。**
  ずれると溶岩が最後の一層を流し切れず、抜いた瞬間に残り火が直撃する。
- **部屋は上下左右を閉じる。** 床のピンは側壁と同じ幅にする。
  ピンが側壁より狭いと、角から斜めに中身が漏れる。
- **床のピンの下端は、下の棚の上面より上で止める。**
  棚の上面に居座ると溶岩だまりを左右に分断し、片側が窓に届かなくなる。
- **宝の縦坑の真下に天井・棚を置かない。**
  粉体は 45 度で安定するので、いったん積もると二度と取り出せない。
- **溶岩と宝を同じ部屋に同居させない。**
  ピンは 1 枚の矩形なので、抜けた跡が両者をつなぐ通路になり、宝が全部溶ける。
- **宝のゲートは最後に抜く手順にする。**
  棚が残っているうちに落とすと、棚の上で砂山が横に広がって回収できない位置に積もる。

## ファイル構成

```
src/sand.js      落砂シミュレーション（決定論的乱数なのでヘッドレス検証できる）
src/levels.js    ピン抜きの全ステージ定義 + 解法 + 罠
src/puzzle.js    ピン抜き画面の描画と操作
src/gfx.js       ミニゲーム共通の描画ヘルパ
src/mini.js      広告ゲームの契約と共通ホスト
src/ads/*.js     広告ゲーム本体（1 ジャンル 1 ファイル）
src/fake.js      「実物」のマージゲーム、ポップアップ、全画面広告
src/app.js       画面遷移とシナリオ
src/sfx.js       WebAudio の効果音
template.html    画面の骨組み
build.mjs        単一 HTML への束ね + 登録漏れの検査
tools/verify.mjs ピン抜きステージのヘッドレス検証
tools/strip.mjs  ES モジュールを素のスクリプトに落とす処理（ビルドと検証で共用）
qa/one.mjs       広告ゲーム 1 本の単体検証
qa/check.mjs     全広告ゲームの通し検証
qa/shot.mjs      任意の画面のスクリーンショット取得
tools/smoke.mjs  本編の通しプレイ + スクリーンショット
```
