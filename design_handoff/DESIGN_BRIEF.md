# DESIGN BRIEF — 3PL 倉庫 物量分析ツール UI リニューアル

> 添付 `screenshots/` が現状の実機画面。本書は文脈・制約・画面別の課題と改善方向・
> 依頼成果物をまとめたもの。Claude Design はこれ1冊で着手できる想定。

---

## 1. プロダクト概要

- **何**: WMS（倉庫管理システム）が吐く CSV / Excel を取り込み、物量推移・ABC・
  ピーク・在庫回転・予測などを可視化する **3PL 倉庫向け分析ダッシュボード**。
- **誰**: 3PL の **現場リーダー / 倉庫オペレーション管理者 / 営業**。
  データ分析の専門家ではない。「数字を見て、明日の人員と発注を決める」人。
- **どこで**: PC が主、現場・客先ではスマホでもチラ見する。日本語 UI。
- **コア価値**: 生データを開かなくても「**自動で見つけた注目ポイント**（インサイト）」と
  KPI が一覧で出て、**次のアクション**（人員配置・発注見直し）まで示唆される。
  → キーエンス的な「指摘 → 提案」のトーンが既に入っている（サマリー上部のカード）。

## 2. 技術制約（重要・必読）

このアプリは **Streamlit**（Python）製。デザインは“何でも自由”ではなく、
**できること / できないこと**が決まっている。リデザインはこの枠内で。

**できる（テーマで効く）**
- `.streamlit/config.toml` の `[theme]`: primaryColor / backgroundColor /
  secondaryBackgroundColor / textColor / font（sans-serif / serif / monospace、
  またはカスタムフォント）, baseRadius, borderColor など全体トークン。
- `st.markdown(..., unsafe_allow_html=True)` による **カスタム HTML/CSS カード**
  （現状のインサイトカードがこれ。色・角丸・余白は自由に作り込める）。
- **Plotly** チャートの配色・テンプレート・フォント・凡例・余白（`layout` 全般）。
- 絵文字アイコン → **统一アイコンセット**（SVG を HTML 埋め込み）への置換。
- レイアウト: `st.columns`, `st.container`, `st.tabs`, `st.metric` の組み合わせ。

**できない / 苦手**
- ピクセル完全な自由レイアウト（CSS グリッドで全部組む、は非現実的）。
- ネイティブ部品（`st.metric`, タブ, スライダー, dataframe）の **DOM 構造の作り替え**。
  → 色・フォント・余白は CSS で寄せられるが、構造は Streamlit 既定に従う。
- 複雑なホバー/モーダル/アニメーションのインタラクション。
- **だから依頼は**「テーマトークン＋カスタムCSSカード＋Plotlyテンプレートで実現できる
  範囲のビジュアル刷新」を主軸に。構造改変が要る提案は“将来カスタムコンポーネント化”
  として別枠で。

## 3. 現状のデザイン課題（横断）

スクショから読み取れる、今のままの問題点：

1. **「素の Streamlit」感**: 既定フォント・既定の青・既定の余白そのまま。
   ブランド/プロダクトとしての個性がなく、無料テンプレ感。
2. **情報密度のムラ**: サマリーは密、他タブは上スカスカ＋下に長い縦スクロール。
   余白とセクション境界の設計が弱く、視線の導線がない。
3. **チャート配色がバラバラ**: タブごとに Plotly 既定色（青/緑/赤…）が混在。
   ヒートマップ・散布・棒・ドーナツでパレットが不統一。**意味と色の対応**がない
   （A/B/C ランク、入庫/出庫、増/減 などに一貫した色が割り当てられていない）。
4. **KPI（st.metric）が平板**: 22 個の数字が均一に並び、**重要度の階層**がない。
   何を最初に見るべきか分からない。
5. **インサイトカードは良いが未整理**: 色分け（赤/黄/青）の意図は良い。が、
   タイポ・アイコン・余白が粗く、severity の視覚的強弱が弱い。
6. **アイコンが絵文字**: 📦🏷️⏰🔄 …親しみはあるが OS 依存でブランド感に欠ける。
7. **モバイルが破綻気味**: タイトル・タブが左で**見切れ／横はみ出し**
   （`m1_summary_mobile.png`）。タブが多くて横スクロール、カードの余白も窮屈。
8. **テーブルが素っ気ない**: 既定 dataframe。重要行のハイライトや単位・桁区切りの
   見せ方に改善余地。

## 4. デザインゴール / 方向性

- **信頼できる業務ツール感**（“ちゃんとした SaaS”）。派手さより**可読性と判断の速さ**。
- **「指摘 → 提案」の主役化**: インサイトと「次の一手」を画面の主役に。
- **意味のある色**: ランク・増減・入出庫・重要度に**一貫したセマンティックカラー**。
- **PC で密度、スマホで素直**に。レスポンシブ破綻の解消。
- トーン候補（Claude Design に2案ほど提案してほしい）:
  - **A: クリーン・ロジスティクス**（白基調＋ディープブルー＋アンバー差し色、
    角丸小さめ、データインク重視）。
  - **B: ダーク・オペレーションコックピット**（濃紺背景＋高コントラスト数値、
    現場の大画面/暗所向け）。

## 5. 画面別インベントリ（課題と改善方向）

各画面：**目的 / 現状の主な要素 / 課題 / 改善方向**。

### 00 ランディング＋サイドバー (`00_landing_sidebar.png`)
- 目的: データ投入（サンプル or アップロード）、エンジン切替（pandas / DuckDB）、期間絞り込み。
- 課題: サイドバーが説明テキスト多めで手順が埋もれる。①②の段組みはあるが弱い。
- 改善: **3ステップのオンボーディング**（①データ ②期間 ③見る）を視覚的に。
  エンジン切替は上級者向けなので折りたたみ/補足化。CTA「サンプルで試す」を主ボタン化。

### 01 サマリー (`01_summary.png`) ★最重要・最初に着手
- 目的: 1 画面で経営/現場判断。インサイト → KPI → ミニチャート。
- 現状: 自動インサイトカード（赤/黄/青）→ KPI 22 種（ボリューム/効率/在庫/ピーク）
  → 日次推移・曜日別の小チャート。
- 課題: カードと KPI が等価に並び主従不明。KPI の塊が単調。
- 改善: **上段＝インサイト（大きく、severity で強弱）**、中段＝**ヒーロー KPI 4〜6個**
  （残りは折りたたみ/小）、下段＝スパークライン。カードに「推奨アクション」を一段強調。

### 02 物量推移 (`02_trend.png`)
- 目的: 入出荷の推移と異常日（z-score）検知。
- 改善: 入庫/出庫に固定色、異常日マーカーを目立つアクセント1色に統一。
  期間平均・移動平均の補助線、ゼロ基線とグリッドの整理。

### 03 ABC 分析 (`03_abc.png`)
- 目的: SKU/取引先のパレート（累積寄与）とランク件数。
- 改善: **A=濃 / B=中 / C=淡** の3段セマンティックを全タブ共通化。
  パレートの累積線と棒のコントラスト、80%ラインの注記。

### 04 ピーク分析 (`04_peak.png`)
- 目的: 曜日・時間帯の繁閑、取引先×曜日の偏り → 人員シフト検討。
- 現状: 曜日棒/時間帯棒/曜日×時間ヒート/取引先×曜日ヒート。
- 課題: 棒2本は別色（青・緑）でパレット不統一。ヒートの凡例位置・連続スケールが各々。
- 改善: **単一の連続スケール**（淡→濃）でヒートを統一、棒も同系。ピークセルに注記。

### 05 在庫回転 (`05_inventory.png`)
- 目的: SKU 別回転率/供給日数/デッドストック判定。
- 改善: デッドストック/過剰在庫を**警告色**で明示、回転良/不良の双方向色分け、
  閾値ラインの可視化。テーブルは重要行ハイライト＋単位明記。

### 06 予測 (`06_forecast.png`)
- 目的: 曜日季節性＋トレンドの簡易予測（95%バンド）。
- 改善: 実績/予測の線種・色を明確に分離、信頼バンドを淡い面で。
  「予測はあくまで簡易」である旨の控えめな注記デザイン。

### 07 SKUポートフォリオ (`07_portfolio.png`)
- 目的: 回転率×在庫の4象限散布＋ライフサイクル分布（ドーナツ＋表）。
- 現状: バブル散布（カテゴリ別色）＋ドーナツ＋上位表。
- 課題: 散布の凡例カテゴリ色とドーナツ色が無関係。象限の意味（優良/過剰/死蔵…）が
  色や背景で示されていない。
- 改善: **4象限を薄い背景帯で区切り**、各象限に意味ラベル。カテゴリ色を散布⇄ドーナツで一致。

### 08 期間対比 (`08_compare.png`)
- 目的: 2期間の SKU/取引先別 寄与度（ウォーターフォール）。
- 現状: 期間A/B合計＋変化%、増減ウォーターフォール（緑増/赤減）。
- 改善: 増=緑/減=赤を**全タブ共通の増減色**に固定。合計→変化の流れを矢印やコネクタで。
  上位寄与SKUに直接ラベル。

### モバイル (`m1_summary_mobile.png`, `m2_peak_mobile.png`)
- 課題: タイトル・タブが**左で見切れ／横はみ出し**、タブ多数で横スクロール、余白窮屈。
- 改善: モバイルでは**タブをセレクトボックス or 2段**に、タイトル短縮、
  カードを縦1列・余白確保、チャートは縦積みで横幅100%・高さ最適化。

## 6. デザインシステムとして欲しいもの

- **カラートークン**: 背景/サーフェス/テキスト各階調、プライマリ、
  **セマンティック**（success=増/良, danger=減/警告, warning=注意, info）、
  **ランク3段（A/B/C）**、**フローの入庫/出庫**、ヒートマップ連続スケール1本。
- **タイポ**: 日本語可読フォント指定、見出し/本文/数値（KPI は tabular-nums）スケール。
- **スペーシング & 角丸**: セクション/カード/余白の基準値、`baseRadius`。
- **コンポーネント・スタイル**: インサイトカード（severity 3種）、KPI カード
  （ヒーロー/標準/ミニ）、テーブル行ハイライト、タブ、サイドバー手順。
- **アイコン**: 絵文字 → 統一 SVG セット（タブ8種＋severity＋KPI）。
- **Plotly テンプレート**: 上記トークンを反映した `layout` テンプレ1つ（全チャート適用）。
- **成果物の形式**: 可能なら **`.streamlit/config.toml` のテーマ値** と
  **カスタム CSS スニペット**、**Plotly テンプレート(JSON/py)** に落として渡してほしい
  （＝そのまま実装に移せる）。
