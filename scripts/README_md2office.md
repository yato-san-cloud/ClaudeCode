# md2office.py — md→docx/html 統一変換スクリプト(候補13)

`docs/01_自動化候補一覧.md` 候補13の実装。文書ごとに個別のmd変換スクリプトを作らず、
1本のCLI+文書タイプ指定で `md(AIドラフト) → docx/html` の変換を行う(docs/02 M-1の
「md生成 → 人間修正 → docx正本 → 配布」ライフサイクルのうち、md生成直後の変換工程)。

## 使い方

```bash
python3 scripts/md2office.py 入力.md --type gijiroku|yoken|kaito [--out docx,html] [--outdir DIR]
```

例:

```bash
# 議事録ドラフトをhtmlだけ確認したい
python3 scripts/md2office.py templates/議事録テンプレ.md --type gijiroku --out html

# 要件定義をdocx+html両方、別フォルダに出力
python3 scripts/md2office.py 0710_要件定義_v1.md --type yoken --out docx,html --outdir 出力/

# 審議回答(横向き表が多い)をdocxのみ
python3 scripts/md2office.py 審議回答_v2.md --type kaito --out docx
```

引数:

| 引数 | 必須 | 説明 |
|---|---|---|
| `入力.md` | ○ | 変換元のMarkdownファイル(位置引数) |
| `--type` | ○ | `gijiroku` / `yoken` / `kaito` のいずれか |
| `--out` | - | 出力形式(カンマ区切り)。既定 `docx,html` |
| `--outdir` | - | 出力先ディレクトリ。省略時は入力ファイルと同じ場所 |

出力ファイル名は入力名を引き継ぐ(`入力.md` → `入力.docx` / `入力.html`)。

## タイプ別プリセット

| type | 用途 | 見た目の違い |
|---|---|---|
| `gijiroku` | 議事録(`.claude/skills/gijiroku`の出力md想定) | 冒頭の「項目/内容」キーバリュー表を罫線・見出し省略スタイルで表示し、`配布先`行を強調(背景色)。決定事項・宿題など通常の見出し付き表はそのまま罫線表になる |
| `yoken` | 要件定義 | `##`(h2)以下の見出しに章番号を自動採番(例: `1.` `1.1.` `1.1.1.`)。h1(タイトル)は採番しない |
| `kaito` | 審議回答・数字1枚もの等 | A4横向き(landscape)。表が横に広い資料向け |

すべてのタイプで共通: A4サイズの印刷用インラインCSS、游ゴシック指定(docx)、
太字・インラインコード・箇条書き・番号リスト・引用・水平線に対応。

## 対応するMarkdown記法

- 見出し `#`〜`####`(5階層目以降は非対応)
- 表(`| ... |` + 区切り行 `|---|---|`)
- 箇条書き(`-` `*`)/ 番号リスト(`1.` `2.` …)
- 引用(`>`。複数行はまとめて1つの引用ブロックに結合)
- 太字 `**text**` / インラインコード `` `code` ``
- 水平線(`---` `***` `___`)

非対応(必要になれば拡張): 見出し内のネストしたインライン、リストのネスト、画像、リンク、
コードブロック(\`\`\`)、テーブルセル内の改行・インライン太字以外の装飾。

## 依存関係

- html出力: 標準ライブラリのみで完結(追加インストール不要)
- docx出力: [python-docx](https://python-docx.readthedocs.io/) が必要
  - 未導入の場合は `pip install python-docx` を案内した上でhtmlのみ出力してエラー終了しない
  - 検証環境では `pip install python-docx` が成功することを確認済み(プロキシ経由でPyPIに到達可能だった)。
    到達できない環境では手動導入するか、`--out html` で運用する

## 正本保護・安全原則

- 入力の `.md` は一切変更しない(読み取り専用)
- 既存の出力ファイル(同名の`.docx`/`.html`)がある場合は**上書きしない**。
  既存ファイルを `入力_2.docx` のように退避してから新しい出力を書く
  (手動修正済みのdocx正本を誤って潰さないため。空き番号がなければ `_3` `_4` …と探す)
- 変換完了時に必ず `⚠️ 正本昇格前に目視確認(docs/02 M-1)` を表示する。
  docxに手動修正を入れた後は、mdの冒頭に `⚠️ 正本は同名.docx(手動修正済)` を人間が追記すること(M-2、本スクリプトは追記しない)
- Google Driveへの接続・書き込み、配布・送信・削除は一切行わない(ローカルファイル生成のみ)
- レポートツール方針: 入力なし/不正な`--type`など想定内のエラーでも、分かるメッセージを出した上で
  **終了コードは常に0**(`scripts/name_lint.py`と同じ方針。CIやパイプラインで誤って処理を止めないため)

## 制限事項

- Word/LibreOffice上での見え方(改ページ、フォント実際の描画)は環境依存。**docx生成後は必ず目視確認すること**
- python-docxが利用できない環境ではdocx出力は生成されない(html出力のみで代替)
- 表の列数が行によって異なる場合(不揃いなMarkdown表)、多い方に合わせて欠落セルは無視される
- ネストしたリスト・画像・リンク・コードブロックは非対応(プレーンテキストとして残る場合がある)
- `numbers.json`(候補16)との連携や、数字の自動検算は行わない。数字の正本はxlsx(M-5)のまま
