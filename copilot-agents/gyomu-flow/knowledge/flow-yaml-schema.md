# flow.yaml スキーマ（業務フロー図の中間表現）

業務フロー図の唯一の正となるデータ形式が flow.yaml です。図・処理一覧・チェック結果はすべてこの flow.yaml から派生します。図を直接描かず、まずこの形式でレーン・列・ノード・接続を宣言します。

このドキュメントは flow.yaml に書けるキーの全一覧です。ここに載っていないキーは使えません。

## flow.yaml の全体構造

flow.yaml は次の5ブロックだけで構成されます。

```yaml
meta:     # タイトル・版数・グリッド寸法
lanes:    # Y軸。担当者・組織・システム
columns:  # X軸。工程ステップ（左から右が時間の流れ）
nodes:    # 箱。lane と col で決まるセルに配置する
edges:    # 矢印
```

lanes と columns を先に決め、nodes をそのセルに置きます。これがこの形式のすべてで、自動レイアウトに位置を奪われないための設計です。

最小構成の例です。

```yaml
meta:
  title: 受注から出荷までの流れ
lanes:
  - {id: cs,     label: 受注担当}
  - {id: wh,     label: 倉庫}
  - {id: screen, label: 管理画面, kind: system}
columns:
  - {id: c1, label: 受注}
  - {id: c2, label: 出荷指示}
nodes:
  - {id: n010, lane: cs,     col: c1, type: process, label: 受注登録, ref: T03}
  - {id: n011, lane: screen, col: c1, type: screen,  label: WMS\n受注画面}
  - {id: n020, lane: wh,     col: c2, type: process, label: ピッキング}
edges:
  - {from: n010, to: n011}
  - {from: n010, to: n020}
```

## meta ブロック（flow.yaml のタイトルと寸法）

meta には図全体の設定を書きます。

| キー | 既定値 | 説明 |
|---|---|---|
| `title` | 業務フロー | 図の上に出るタイトル |
| `version` | "0.1" | 版数。図中には出ないがファイルに埋まる |
| `grid` | 下表 | 寸法の上書き |
| `legend` | なし | 凡例。強調色を使ったら必ず書く |

meta.grid で調整できる寸法は次のとおりです。

| キー | 既定値 | 用途 |
|---|---|---|
| `lane_h` | 88 | レーン1本の高さ。箱を大きくしたいとき上げる |
| `col_w` | 150 | 列1本の幅。ラベルが長いとき上げる |
| `lane_hdr_w` | 100 | 左端のレーン名カラムの幅 |
| `title_h` | 26 | 上部の青帯の高さ |
| `node_w` | 112 | 標準ノードの幅 |
| `node_h` | 46 | 標準ノードの高さ |
| `show_columns` | false | 上部の青帯に列名を出すか |
| `font_size` | 11 | ノードラベルの文字サイズ。情報密度が高い図では10まで下げる |
| `x0` | 40 | 図全体の原点X |
| `y0` | 60 | 図全体の原点Y |

情報密度が高い詳細設計向けの図では、ラベルが4〜6行になることがあります。その場合は `lane_h: 150` / `node_h: 92` / `font_size: 10` / `node_w: 178` あたりから始めます。

meta.legend の書き方です。強調色を使った図では、色の意味を図の中に置いておかないと単独で配られたときに読めなくなります。

```yaml
meta:
  legend:
    - {emphasis: warn, label: この方式にのみ存在する活動}
```

## lanes ブロック（誰が登場するか）

lanes は書いた順に上から並びます。人のレーンを上、システム系のレーンを下に置くと読みやすくなります。

```yaml
lanes:
  - {id: ec,     label: EC担当}
  - {id: screen, label: 管理画面, kind: system}
```

| キー | 必須 | 説明 |
|---|---|---|
| `id` | 必須 | ノードから参照する識別子。英数字を推奨 |
| `label` | 任意 | 図に出る名前。省略すると id がそのまま出る |
| `kind` | 任意 | `actor`（既定）または `system`。処理一覧の区分列に出る |

短縮記法として文字列だけを書くと id と label が同じになります。例: `lanes: [MD, 物流]`

レーンは7本が実用上の上限です。超えると1枚に収まらず読み手が追えなくなります。分割の切り口は「業務フロー図」と「システム関連図」に分けるか、工程を前半後半で切ることです。

人のレーンとシステムのレーンを1枚に混ぜてかまいません。BPMN の教科書からは外れますが、詳細設計では「業務がどの画面を通ってどのDBに落ちるか」が1枚で見えることの価値が上回ります。システム系には `kind: system` を付けて区別だけしておきます。

## columns ブロック（時間をどう刻むか）

columns は書いた順に左から並びます。列は工程ステップであり、時間の刻みです。処理の個数ではありません。

```yaml
columns:
  - {id: c1, label: 商品情報提供}
  - {id: c2, label: MD登録, width: 190}
```

| キー | 必須 | 説明 |
|---|---|---|
| `id` | 必須 | ノードから参照する識別子 |
| `label` | 任意 | 工程名。`show_columns: true` のとき図に出る。処理一覧には常に出る |
| `width` | 任意 | この列だけ幅を変える |

列の切り方の原則です。

- 同時に起きることは同じ列に置きます。担当が違うだけの一連の流れは同じ列に並びます。
- 1つの列に同じレーンのノードが2つ来たら、それは2工程です。列を足すのが基本で、slot で無理に詰めるのは横幅をどうしても使いたくないときだけです。
- 列は12本が上限の目安です。超えたら横長すぎるので工程を分割します。

## nodes ブロック（箱）

```yaml
nodes:
  - id: n020
    lane: md
    col: c2
    type: process
    label: 新商品情報\n登録
    system: MDシステム
    ref: T12
    note: 商品コード採番はここ
```

| キー | 必須 | 説明 |
|---|---|---|
| `id` | 必須 | 一意。`n010, n020, ...` と10刻みにすると後から挿入しやすい |
| `lane` | 必須 | 配置するレーンの id（attach を使う場合は不要） |
| `col` | 必須 | 配置する列の id（attach を使う場合は不要） |
| `type` | 任意 | ノード種別。既定は `process` |
| `label` | 任意 | 図に出る文字。`\n` で改行する |
| `slot` | 任意 | 同じセルに複数置くときの横位置（0起点） |
| `system` | 任意 | 処理を行うシステム名。図には出ず、処理一覧に出る |
| `ref` | 任意 | 要件定義書のID。カンマ区切りで複数可。要件トレースの要 |
| `note` | 任意 | 備考。図には出ず、処理一覧に出る |
| `attach` | 任意 | 添付ノート用。`{to: n010, at: br}` の形式 |
| `emphasis` | 任意 | 強調色のキー。色コードは直接書けない |
| `w` / `h` | 任意 | 個別のサイズ上書き |

システム名はラベルに書かず system に逃がします。図が混むうえ、処理一覧に構造化された形で出たほうが後工程で使えるからです。ref と note も同じ理由で図には出しません。

## nodes の type 一覧（ノード種別と図形）

| type | 図形 | 使いどころ |
|---|---|---|
| `process` | 角丸なし矩形 | 業務処理。既定値 |
| `screen` | 角丸矩形 | システム画面・操作 |
| `db` | シリンダー | データベース・テーブル |
| `external` | 楕円 | 外部起点、社外からの入力 |
| `terminal` | 角丸50%のスタジアム形 | 開始・終了 |
| `decision` | ひし形 | 分岐判断 |
| `data` | 青いノート | 帳票・データ・成果物 |
| `manual` | 手入力記号 | 手作業・紙 |
| `batch` | 縦線付き矩形 | バッチ処理・自動処理 |

`decision`（ひし形）は要注意で、矩形と同じサイズだと文字がひし形からはみ出します。テキストブロックの倍近い寸法（例: 2行の日本語に対して w 236 / h 104）を明示的に指定してください。

## nodes の emphasis 一覧（強調色）

| キー | 色 | 用途 |
|---|---|---|
| `warn` | 黄 | この方式にのみ存在する、注意して読む箇所 |
| `info` | 青 | 補足・参考 |
| `ok` | 緑 | 合意済・確定 |
| `alert` | 赤 | 未協議・リスク |
| `muted` | 灰 | 対象外・現行どおり |

生の色コードを flow.yaml に書けないのは意図的な制約です。1枚の中で色が増えると、読み手は色の意味を推測しはじめます。意味のある5色に閉じておくと、凡例がそのまま図の読み方の説明になります。

強調を使ったら meta.legend に凡例を書きます。

```yaml
meta:
  legend:
    - {emphasis: warn, label: この方式にのみ存在する活動}
nodes:
  - {id: n040, lane: fk, col: c4, emphasis: warn, label: 補充：リザーブ→取り場}
```

方式比較や As-Is / To-Be の2枚組を作るときは、レーンと列の定義を両方の flow.yaml で揃えます。骨格が同一だと、差分がノードの有無としてそのまま見えます。片方にしかない活動に `emphasis: warn` を付ければ、比較の主張が図の中で完結します。

## nodes の attach（添付ノート）

帳票やデータを表す青いノートは、ノードに貼りつく形で配置します。線を引かず相対配置されるので、lane と col は書きません。

```yaml
- {id: a010, type: data, label: 商品情報, attach: {to: n010, at: br}}
```

at に指定できる位置は `br`（右下）`bl`（左下）`tr`（右上）`tl`（左上）`r` `l` `t` `b` です。既定は br にして、隣の箱と重なるときだけ bl などに逃がします。位置を細かく調整したくなったら、そのセルが混みすぎている合図です。

添付ノートは「その処理で何が生まれるか」を示すためのもので、処理そのものではありません。矢印を1本増やすより情報密度が上がります。

## edges ブロック（矢印）

```yaml
edges:
  - {from: n010, to: n020}
  - {from: n020, to: n021, kind: data, label: 商品マスタ}
```

| キー | 必須 | 説明 |
|---|---|---|
| `from` | 必須 | 始点のノードID |
| `to` | 必須 | 終点のノードID |
| `id` | 任意 | 省略すると `e001` から自動採番される |
| `kind` | 任意 | `flow`（既定・実線）/ `data`（破線）/ `trigger`（点線） |
| `label` | 任意 | 線に添える文字。データ名や分岐条件 |
| `exit` / `entry` | 任意 | 接続位置の手動指定。`"1,0.5"` 形式 |

線の経路は作図ツールの直交ルーティングに任せます。exit と entry は自動で決まった向きが気に入らないときだけ書きます。

右から左に戻る線（逆流）が多い図は、たいてい列の切り方が間違っています。ループがあるなら decision ノードを置いて明示します。

## よくある書き間違い

**改行が反映されない**
YAML の平文スカラーでは `\n` はバックスラッシュと n のままです。この形式では救済して実際の改行に変換するので `label: 新商品情報\n登録` と書いてかまいませんが、明示したいときは `label: "新商品情報\n登録"` とダブルクォートで囲みます。

**同じセルに2つ置いてしまう**
`slot: 0` と `slot: 1` を振って横に並べるか、列を1本足します。列を足すほうがたいてい正しい判断です（工程が2段階あるということなので）。

**添付ノートに lane を書いてしまう**
attach があるノードは相対配置なので lane と col は無視されます。混乱のもとなので書きません。

**IDを連番で詰めてしまう**
`n1, n2, n3` にすると工程を1つ挟むたびに全部振り直しになります。`n010, n020` のように10刻みにしておくと差し込みが効きます。

**色コードを書いてしまう**
`#FFCC00` のような色指定はできません。emphasis の5つのキーだけを使います。
