# 倉庫・物流の解法アプローチ 判定ガイド

このドキュメントは、3PL・倉庫・物流オペレーションの課題を4つの解法アプローチに仕分けするための判定基準をまとめたものです。エージェントは分類名・典型例・ツール名を答える際、このドキュメントを参照してください。

---

## コア判定：部品に分解して足し算で済むか

すべての判定の起点は「問題を部品に分解して足し算で済むか」です。

| 状況 | 分類 |
|---|---|
| 足し算で済む | Excel領域（算数・待ち行列） |
| 済まない、確率性なし | 数理最適化領域 |
| 済まない、確率性あり、評価だけ | シミュレーション領域 |
| 済まない、確率性あり、最適化したい | シミュレーション最適化領域 |

---

## 判定フロー（Q1→Q2→Q3の順を守る）

```
Q1. 閉形式で書けるか？
├─ Yes → Excel領域（足し算・掛け算・M/M/1など）
└─ No  → Q2へ

Q2. ばらつき（確率性）が結果を左右するか？
├─ No  → 数理最適化領域
└─ Yes → Q3へ

Q3. 最適化したいか、評価だけか？
├─ 評価だけ → シミュレーション領域
└─ 最適化も → シミュレーション最適化領域
```

判定に迷う場合の既定値は安全側に倒します。Q1が判断できない場合は「書けない」として扱い、Q2が判断できない場合は「左右する」として扱います。

---

## 用語の注意：閉形式とは何か

「閉形式で書けない」とは、**答えに至る数式が書けない**という意味です。答えが無限にあるという意味ではなく、答え自体は一意です。

閉形式は線形と同義ではありません。非線形でも閉形式で解ける問題は多く、M/M/1の待ち行列公式はその代表例です。「非線形だからシミュレーション」という判断は誤りです。

---

## 分類1：Excel領域（静的な能力値）

何個/h、何人、何㎡、何時間、といった**静的な問い**に答える領域です。

倉庫領域での典型例:

- オムニソーター単体の処理能力（投入速度と排出速度のmin）
- 必要間口数、必要人員、必要㎡の算出
- 待ち行列（M/M/1、M/M/c）による静的な詰まり近似
- ピッキング歩行距離の平均的見積もり

ツール: Excel（算数・待ち行列の公式）

上位の分類へ移行する条件: 波動（ばらつき）で結論が変わる、前後工程の相互作用が効く、と分かった時点でシミュレーション領域に移行します。

---

## 分類2：数理最適化領域（最適な配置・順序・割当）

「最適な〜は？」に答える、**決定的な**問題の領域です。確率性は無視できる前提です。

倉庫領域での典型例:

- ダイヤ作成（VSP / VRPTW）
- ロケーション割当（ABC分析に基づく配置）
- シフト最適化
- 静的条件下でのバッチ編成
- ラック配置最適化

ツール: OR-Tools / PuLP / Gurobi / scipy.optimize.linprog / Excelソルバー

定式化で必ず整理する3点:

1. 目的関数（何を最大化・最小化するか）
2. 決定変数（何を決めるか）
3. 制約（何を守るか）

上位の分類へ移行する条件: 確率性が無視できない場合はシミュレーション最適化領域に格上げします。決定的最適化のままだとロバスト性を欠いた解になります。

---

## 分類3：シミュレーション領域（ばらつき下での評価）

「詰まるか？ 待ち時間はどれくらいか？ 波動に耐えるか？」に答える領域です。最適化はせず、**評価に専念**します。

倉庫領域での典型例:

- オムニソーターが波動で詰まるかの検証
- ピッキング動線の評価
- 前後工程を繋いだボトルネック検証
- バース競合・待機時間評価
- ダイヤのストレステスト

ツール: SimPy（離散事象シミュレーション）/ 自作シミュレータ / モンテカルロ

実装は3層構造（別ドキュメント「実装パターン」を参照）で組むのが定石です。

---

## 分類4：シミュレーション最適化領域（最適設計 × 複雑な評価）

最適化したい、**かつ**評価にシミュレーションが必要な領域です。

倉庫領域での典型例:

- ダイヤのロバスト性検証と改善
- レイアウト代替案の比較評価
- バッチサイズ × 投入タイミングの組合せ探索
- 波動対応シフト設計

ツール: 最適化 × シミュレーションの組み合わせ / scikit-optimize / Optuna

探索戦略の選択とUI構成は別ドキュメント「実装パターン」を参照してください。

---

## キーワードから分類を引く早見表

ユーザーの言葉から当たりをつけるための表です。最終判定は必ずQ1→Q2→Q3のフローで確定させてください。

| ユーザーの言葉 | 当たりをつける分類 |
|---|---|
| 能力値、何個/h、必要人員、必要間口、必要㎡ | Excel領域 |
| 平均待ち時間をざっくり、M/M/1 | Excel領域 |
| 最適な配置、割当、順序、ダイヤ作成、シフト最適化 | 数理最適化領域 |
| ロケーション、ABC分析、ラック配置 | 数理最適化領域 |
| 詰まるか、滞留するか、波動に耐えるか、ストレステスト | シミュレーション領域 |
| ボトルネック検証、バース待ち、動線評価 | シミュレーション領域 |
| ロバスト性、代替案比較、組合せ探索、波動対応シフト | シミュレーション最適化領域 |

## 判定に必要なヒアリング項目

情報が足りない場合、以下から最大3つを1回にまとめて質問します。1問ずつ小出しにしないでください。

1. 知りたいのは「静的な能力値」「最適な配置・順序・割当」「ばらつき下での挙動」のどれか
2. ばらつき（波動・変動）は無視できるか、できないか
3. 規模感（拠点数 / SKU数 / 行数 / 便数 / 人数 / 対象時間帯）
4. 守るべき制約（時間枠、能力上限、人員、レイアウト、車両）
5. 評価したい指標（処理能力、待ち時間、滞留、稼働率、コスト）

すでに会話で分かっている項目は聞き返しません。判定に足りる情報が揃った時点で、追加質問をせず即座に分類します。

## 利用者の立場（営業・プランナー視点の補助線）

このエージェントの利用者は営業や現場プランナーであり、手法を完全に理解する必要はありません。重要なのは次の3点です。

1. 問題タイプを嗅ぎ分けることで、AIに構造化して投げられるようになる
2. 現場課題と手法を繋げる立場そのものが希少で、価値がある
3. 意思決定者が自分で触れるUIまで作ると、訴求力が跳ね上がる

3PL・物流業界ではこの視点を持つ営業・プランナーが少なく、「手法オタク」ではなく**現場の課題を手法に翻訳する通訳**として立ち回ることが最大の武器になります。手法の中身を解説しすぎず、判定と方向付けに集中してください。
