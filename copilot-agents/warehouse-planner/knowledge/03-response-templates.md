# 応答の型とClaude Code依頼文テンプレート

このドキュメントは、判定結果をどう言語化して返すか、そして実装をClaude Codeに引き継ぐための依頼文の雛形をまとめたものです。

---

## 応答の型：ケース1 能力値の試算を聞かれた時

```
これはExcel領域ですね。〜の式で出ます。
[具体的な式と変数]
ただし [条件] が変わると [別手法] に移行します。
```

数値そのものを断定せず、式と必要な変数を示して「この値を入れて計算してください」という形で返します。

---

## 応答の型：ケース2 「詰まるか評価したい」と聞かれた時

```
これはシミュレーション領域です。
3層構造で組むのが定石です。
1. Pythonでシミュレーション本体（SimPyなど）
2. パラメータを振って結果テーブル化
3. HTML/Streamlitで意思決定者が触れるUIに
まず [最初の一手] から始めるのが良さそうです。
```

---

## 応答の型：ケース3 「最適な〜を決めたい」と聞かれた時

```
これは数理最適化領域です。
・目的関数: [何を最大化・最小化するか]
・決定変数: [何を決めるか]
・制約: [何を守るか]
[ツール] で解けます。
ただし [確率性] が無視できない場合はシミュレーション最適化に格上げします。
```

---

## 応答の型：ケース4 問題が曖昧な時

```
判定のためにいくつか確認させてください。
・知りたいのは静的な能力値でしょうか、最適な配置でしょうか、ばらつき下での挙動でしょうか
・ばらつき（波動・変動）は無視できますか、できませんか
・規模感（拠点数・SKU数・行数・便数・人数・対象時間帯）はどのくらいですか
```

質問は最大3つまで、1回にまとめて聞きます。1問ずつ小出しにしないでください。回答が揃った時点で分類を確定させます。

---

## Claude Code依頼文テンプレート（共通の雛形）

このエージェントはコードを実行できません。出口は必ず「推奨手法 + 実装方針 + Claude Codeへの依頼文テンプレート」です。会話から埋められる項目は埋め、未確定の項目は空欄にせず「（要確認）」と明記して残します。

```
warehouse-planner スキルを使ってください。

■ 問題タイプ: （Excel領域 / 数理最適化領域 / シミュレーション領域 / シミュレーション最適化領域）
■ 目的: （何を決めたいか、何を評価したいか。1〜2文）
■ 対象: （拠点・設備・工程）
■ 規模感: （拠点数 / SKU数 / 行数 / 便数 / 人数 / 対象時間帯）
■ 入力データ: （項目名と粒度）
■ 制約: （時間枠、能力上限、人員、レイアウト、車両）
■ 評価指標: （処理能力、待ち時間、滞留、稼働率、コスト）
■ ばらつきの扱い: （無視する / 分布を仮定する / 実績データから生成する）
■ 出力形式: （結果テーブルまで / HTML・StreamlitのUIまで）
■ 推奨ツール: （OR-Tools、PuLP、SimPy、Optuna など）

まず実装方針を提示してください。合意できたらコードを書いてください。
```

## 依頼文テンプレート：分類別の追記行

共通の雛形の末尾に、分類に応じて次の1行を足します。

| 分類 | 追記する行 |
|---|---|
| Excel領域 | 「まず式の形と変数一覧を提示し、そのうえでExcelに貼れる計算表を作ってください。」 |
| 数理最適化領域 | 「目的関数・決定変数・制約を数式で明示してから、OR-Tools（またはPuLP）で実装してください。小規模データで解を確認してから全件に広げてください。」 |
| シミュレーション領域 | 「3層構造で組んでください。1. Pythonでシミュレーション本体、2. パラメータを振った結果をテーブル化、3. HTML/Streamlitでスライダー操作のUI。重い計算はオフライン、表示はオンラインでお願いします。」 |
| シミュレーション最適化領域 | 「評価用シミュレータを先に作り、振るパラメータを3つ以内に絞って全探索してください。次元が増える場合はラテン超方格またはOptunaに切り替えてください。最終的に3層構造でUIまで作ります。」 |

## 過去プロジェクトの分類（ユーザーが言及した時の位置づけ）

ユーザーが以下の固有名詞に言及した場合、この対応で分類の当たりをつけます。

| プロジェクト | 分類 |
|---|---|
| PickSim（単ピック vs 合計ピック比較） | シミュレーション / シミュレーション最適化 |
| オムニソーター詰まり評価 | シミュレーション（3層構造推奨） |
| DDC便ダイヤ作成 | 数理最適化（割当）+ シミュレーション（ロバスト性検証） |
| Neo Wing 残業分析 | 静的分析 + シミュレーション（シフト設計時） |
| 倉庫レイアウト評価（DPL新富士など） | シミュレーション最適化 |

この表にないプロジェクト名が出た場合は、推測で分類せず、通常の判定フロー（Q1→Q2→Q3）で仕分けしてください。
