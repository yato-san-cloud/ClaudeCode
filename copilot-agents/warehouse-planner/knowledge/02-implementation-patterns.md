# 倉庫・物流の実装パターンとアンチパターン

このドキュメントは、判定した問題タイプをどう実装に落とすかの定石をまとめたものです。エージェントは実装戦略を提案する際、このドキュメントを参照してください。

---

## 実装パターン：3層構造（シミュレーション系の標準形）

シミュレーション領域・シミュレーション最適化領域を扱う時は、まずこの構成を提案します。

```
[重い計算層]  Python（シミュレーション本体）
     ↓ 事前計算（グリッドサーチ / ラテン超方格 / ベイズ最適化）
[結果テーブル層]  JSON / CSV / Parquet / DuckDB
     ↓ 読み込み
[可視化・操作層]  HTML / Streamlit（スライダーUI）
```

原則は「**重い計算はオフライン、軽い表示はオンライン**」です。

意思決定者が自分でパラメータを動かして納得できるUIまで作ることが重要です。客先デモ・社内説明での訴求力が桁違いに変わります。逆に、その場で重い計算を走らせるUIは、数秒から数分の待ちが発生してデモが成立しません。

## 探索戦略の選択（パラメータ次元数で決める）

| パラメータの次元数 | 探索戦略 |
|---|---|
| 3次元以下 | グリッドサーチ全探索 |
| 5〜10次元 | ラテン超方格サンプリング + 補間 |
| さらに多い、または1評価が重い | ベイズ最適化（Optuna、scikit-optimize） |

ケース数が数万を超える見込みになったら、全探索をやめて上の段の戦略に切り替えます。ケース数の見積もりは提案時に必ず一度行ってください。

---

## 近似の対象：手法によって「何を諦めているか」が違う

「最適化もシミュレーションも結局は近似では」という問いには、この表で整理します。

| 手法 | 何を近似するか | 評価軸 |
|---|---|---|
| 数理最適化 | 最適解 x* | 最適解からの距離（gap） |
| シミュレーション | 期待値 E[X] | 標準誤差（1/√N で縮小） |
| シミュレーション最適化 | ノイズ入りの最適解 | 上記の両方 |

「何を諦めて、何を近似しているか」を意識すると手法選択の精度が上がります。シミュレーションの精度を上げたいなら試行回数N、最適化の精度を上げたいなら定式化と求解時間、という対応関係になります。

## ツール早見表

| 分類 | 定石ツール |
|---|---|
| Excel領域 | Excel（算数・待ち行列の公式） |
| 数理最適化領域 | OR-Tools / PuLP / Gurobi / scipy.optimize.linprog / Excelソルバー |
| シミュレーション領域 | SimPy（離散事象シミュレーション）/ 自作シミュレータ / モンテカルロ |
| シミュレーション最適化領域 | 最適化 × シミュレーションの組み合わせ / scikit-optimize / Optuna |
| 結果テーブル層 | JSON / CSV / Parquet / DuckDB |
| 可視化・操作層 | HTML / Streamlit |

この表にない手法名・ツール名を創作して提案しないでください。

## アンチパターン（提案してはいけないもの）

- **なんでもシミュレーション**：Excelで解ける問題にSimPyを持ち出すのは過剰投資です。
- **なんでも最適化ソルバー**：確率性が効く問題を決定的最適化だけで扱うと、ロバスト性を欠いた解になります。
- **事前計算なしのリアルタイム重計算UI**：客先デモで数秒から数分待たされ、説明が止まります。
- **パラメータ爆発の無視**：グリッドサーチで数万ケース以上を全探索しようとしないでください。
- **モデル精緻化しすぎ**：意思決定に効かない精度を追求しても、結論は変わりません。
- **手法の理論解説**：利用者が求めているのは判定と方向付けです。理論は聞かれた時だけ簡潔に。

## 提案時に必ず添える「次の一手」

分類だけ伝えて終わらせず、最初の一歩を必ず具体的に示します。目安は次の通りです。

| 分類 | 最初の一手 |
|---|---|
| Excel領域 | 式の形と必要な変数を列挙し、既存実績値で1ケース試算する |
| 数理最適化領域 | 目的関数・決定変数・制約の3点を文章で固定し、小規模データで解く |
| シミュレーション領域 | 対象工程を1本に絞ってSimPyで最小モデルを作り、実績と突き合わせる |
| シミュレーション最適化領域 | 評価用シミュレータを先に作り、振るパラメータを3つ以内に絞って全探索する |

いずれの場合も、範囲を絞った最小モデルから始め、実績データと突き合わせてから拡張するのが安全です。
